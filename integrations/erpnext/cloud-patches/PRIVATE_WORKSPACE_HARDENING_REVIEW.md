## Contract and decisions

The root operator imports only stdlib. Root-private config must provide `helper_image` as exact local `sha256:<64>` or repository `@sha256:<64>`, `helper_network` exactly `erpnext-private-proof`, required `helper_hostname` as one canonical lowercase DNS FQDN, readonly DSN, `host_tool_shared_secret`, optional root-controlled `host_ca_file`, Worker host UID, HMAC key path and socket path. The OCI call uses `--pull=never`, a fixed native Python module, UID/GID65532, read-only filesystem, no mounts, cap-drop/NNP, PID/memory/CPU limits and one named network. Credentials and optional CA PEM travel only on bounded stdin. CA verification uses the existing FreshERPAuthority injected-client seam with `ssl.create_default_context(cadata=...)`; TLS stays enabled.

New native image module is `zebra_agent_worker.erp_private_workspace_proof`, copied by Dockerfile.worker. Stdin is JSON with exactly `readonly_dsn,shared_secret,ca_pem,session_id,workspace_id,nonce` (maximum16384bytes). Stdout is one bounded JSON object with exactly `identity,state,expires_at,session_id,workspace_id,nonce`; expires_at is the fresh Host verdict's Unix timestamp. Failure returns a bounded stderr code and nonzero exit, without credentials or traceback. The helper uses the native canonical binding reader, active Task/segment/projection/source proof, native PostgresHostConnectorRegistry and existing FreshERPAuthority. It checks live binding expiry/ceilings and performs an independent pinned HTTPS authority probe. No business tool runs.

The operator checks fresh expiry after acquiring the allocation lock, before mount, after mount, before identity publication and before returning a verified receipt. The helper subprocess has a7second cap within the request budget and reserves1second of the current remaining budget before launch; cleanup uses at most the lesser of1second and the global remaining budget. An exhausted deadline starts no cleanup subprocess and latches refusal. Explicit container removal must succeed. Failure latches all later proof requests off, and startup refuses prefixed stale containers. Root must review/clean these containers before restarting.

A serial main-thread SIGALRM enforces one absolute20second request budget through cleanup and the final response write, shared by lock acquisition and all child commands. Socket input/output uses at most5seconds and never extends the global deadline; a late response is silently closed. Worker uses an absolute30second response budget. Like ordinary subprocess/Linux deadlines, kernel uninterruptible I/O or a wedged Docker daemon is not a hard realtime guarantee. Cleanup failure produces refusal and an operator gate. An inherited/unknown image is never reformatted.

Each leaf reserves256MiB. The32leaf/8GiB limit counts manifest reservations plus orphan `*.ext4` files using the maximum of256MiB, apparent size and allocated blocks per leaf. Sparse/unallocated reservation debt is included in the2GiB free-space floor. Noncanonical names, nonregular files, symlinks and multiple hard links refuse allocation. Unknown bytes are retained.

The journal reaches `ready` only after mount and Worker ownership/mode0700. `reserved` or `formatted` after interruption always requires operator review; there is no retry-format path. Lost ACK after durable ready can replay through a new nonce and returns the same mount. Unique manifest temp files avoid crash-left fixed manifest.tmp deadlock and never delete that unknown stale file. Restore checks the persisted ext4 UUID and backing image, mounts only an empty trusted mountpoint, and refuses existing ownership/mode drift. Existing incomplete journals are deliberately not migrated.

Root verifies actual blkid UUID, exact mount, loop backing, ownership/mode and persisted f_fsid on every successful receipt and restart. A root-owned0755 sibling `.identities` directory holds root-owned0644 per-UUID immutable JSON; Worker cannot replace it. Worker verifies these trusted ancestors and metadata, compares persisted UUID and f_fsid against the authenticated receipt, and independently checks the local ext4 mount's kernel f_fsid/capacity/device. This check runs in the native Worker container, not a runsc command sandbox whose virtualized device identity differs. verify_revision now requires session identity and the same private guard whenever private mode is active; no current native caller was found, and local-profile behavior remains compatible.

## Helper hostname wiring repair — source review only

The independent native helper is a new Docker process; it does not inherit the Worker Compose environment. Its existing native HTTP transport reads `ZEBRA_HOST_TOOL_SSRF_ALLOW_HOSTNAMES` and otherwise rejects private address resolution. The root-private operator config must now provide `helper_hostname` (production example `erpnext.zebra.local`; isolated QA example `authority-qa-fc59cd41.local`). Only that trusted config supplies the one explicit Docker `--env ZEBRA_HOST_TOOL_SSRF_ALLOW_HOSTNAMES=<hostname>`; no Worker request, Task, binding/proof packet or arbitrary parent environment supplies this value. Missing/noncanonical/multiple/URL/port/whitespace/wildcard/IP/numeric-final-label/localhost-label values fail before launch. Existing trusted config ownership and permissions checks remain authoritative. The existing stdlib `socket.getaddrinfo(..., flags=socket.AI_NUMERICHOST)` parser additionally rejects platform-recognized numeric address syntax, including mixed octal/hex abbreviated IPv4; this flag performs no DNS resolution while validating configuration.

This enables only the exact configured hostname in the existing native allowlist seam. Native SSRF validation for other hosts, TLS verification, configured CA trust, connector and gateway pins, exact `erpnext-private-proof` network, bounded stdin credentials and nonce, immutable image, deadline and forced-cleanup refusal remain intact. QA and production retain distinct root config, hostname and acceptance evidence. This host-operator-only change requires no Worker/API/schema change or helper image rebuild. The runnable offline hardening check first failed on the missing Docker env and then passed with the new wiring, malicious config rejection and existing confinement/deadline checks; the basic private workspace check also passes. These checks run without root, Docker or network. The previously observed QA positive-helper failure was not classified to its exact HTTP failure here: this repairs a necessary wiring gap and does not establish that it was the sole failure cause.

Source approval of this repair does not authorize or prove activation. No server/config/service/container/production mutation or real HTTP proof occurred in this slice. Any later isolated native QA must use its separately reviewed exact hostname configuration and preserve the native validation path; it must not bypass checks to manufacture acceptance. Production Worker remains stopped and Host remains paused per the root task's existing boundary; no activation claim is made here.

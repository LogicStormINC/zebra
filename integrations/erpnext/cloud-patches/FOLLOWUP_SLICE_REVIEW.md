## Concrete behavior

- The shared parser defaults to rejecting clarification attachments, preserving captured105 SQLite behavior; only the verified Cloud adapter explicitly opts in. The actual SQLite WAITING_INPUT regression requires400, unchanged events/projections/all table counts, and zero payload-store calls. Native Task append uses one shared cloud input adapter, including text-only followups. Native Session append resolves the root Task and checks the explicit active Segment. HTTP Session `/messages` requests with an `attachments` field enter this canonical input path and return201; text-only HTTP Session requests retain the existing queued command behavior. Local SQLite paths retain existing behavior.
- Official AGUI commands and queued raw commands reject attachment bytes or caller-supplied attachment refs before command acceptance. Their text-only command behavior remains. This release accepts bytes only through typed Task/Session input admission; it does not add an arbitrary session artifact proxy.
- The adapter verifies current native binding/grant evidence before a complete receipt lookup. Completed same-key/same-body replay returns the stored response before parsing, object writes, UUID generation or rollover. A changed body conflicts. Pending retries use deterministic event/file identifiers; concurrent losing immutable stages may remain unreachable reconciliation debt. Unknown object acknowledgements are verified through the existing object API and are never interpreted as permission to delete.
- Active input locks the native lease boundary and stream, rechecks highwater/projections, rebuilds the canonical event under the transaction, writes refs/metadata, rebuilds native Task projections and stores the complete receipt together. Fresh registry/binding/DB-clock authorization is checked at materialization.
- Terminal followup reserves the existing durable native handoff operation. Child bootstrap, active Task mapping, new human event/refs, attachment metadata, complete input receipt, committed handoff and dispatch outbox are one PostgreSQL transaction. The dispatch row is inserted after input materialization and is invisible until commit. A precommit failure leaves only a recoverable native preparing operation, without child/input/outbox state; retry keeps its reserved target. A lost postcommit acknowledgement returns the complete input receipt on retry. A committed old operation without the atomic receipt fails closed for reconciliation.
- Clarification uses the existing Core clarification event, now allowing canonical refs. Worker recovery retains the original user input and adds later clarification files. The original input plus clarification files share native limits (four files, image32MiB, extracted text128KiB, document originals8MiB); budget validation occurs before object reads. Image input requires the native Flash profile. Original source events/Runs are preserved apart from the native handoff audit event. The shared Task rebuild always uses the verified root ID, including subsequent active-child inputs; using the child as a root previously caused the actual PostgreSQL duplicate-Segment failure. Every new nonclarification input pins independently resolved model and effort from the latest native options plus explicit request overrides, without changing the original wire request hash. Unresolved options fail closed. Clarification recovery carries only the current response event’s attachment IDs into actual dispatch: native bounded untrusted-file rendering and verified image data URLs are appended after the paired tool result before either normal or rebased provider continuation. Existing conversation, tool pairing and counters are retained; previous response text files are not re-added. Native conversation serialization excludes provider image URLs, so dispatch additionally restores missing verified original/prior clarification images from canonical current-turn refs, deduplicated against existing conversation URLs. Earlier-turn images are excluded by native Task recovery. Data URLs stay out of durable events. The stored receipt now runs the existing named deferred Task-position allocator before recording root highwater; its active-child regression requires exact equality with both committed Task highwater and the canonical input event’s Task coordinate.

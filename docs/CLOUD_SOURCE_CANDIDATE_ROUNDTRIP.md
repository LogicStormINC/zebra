# 来源选择与候选答案往返最小优化

SOURCE-CANDIDATE-ROUNDTRIP-01，2026-10-17，基线 386772e0。

## 已核对根因

上一轮 B2 的 Redis 搜索首项为 Redis Software 企业版说明；同时另有正确的开源特性页。
模型并行抓取两者，再依据开源特性页中的准确链接取得 GA 博客日期。
企业版抓取非必需；GA 日期补证本身必要。另把搜索返回的 GitHub 文档文件路径
改写为 Redis 网站路径，导致 404；这不是原生 HTTP 重试，也没有必要修改爬虫处理。

第一候选仅因 PostgreSQL release-18.html 被判为未收集而重写，第二候选耗时 4745 ms。
该链接确实由成功工具结果的显式 evidence_refs 和可见正文返回，但随后被 128 条
检查点引用列表中的其它站点导航链接挤掉。不是缺少证据，也不是模型 Provider 重试。

## 最小实施

共享 evidence_ledger 在最终校验时，从本次 attempt 内存中已产生的成功工具事件元数据中找回
候选实际引用的显式地址，优先放进同一个 128 条列表；不把正文中的任意 URL 当证据。
检查点持久化上限不变，无新增 SQL、不读取历史事件、不重放 Run、不增加模型调用。
失败工具、普通文本、模型事件、辅助来源字段不能授予新引用；本次成功事件和检查点
均不存在的地址仍 fail closed。该边界不等于验证链接正文中的所有语义事实。

通用 Agent 指导补充产品/版本匹配、首选所需事实的原始公告、按具体缺口补证、
不把仓库路径猜改成网站 URL、事实充分后停止收集并引用实际成功来源。
没有固定站点、工具路由、轮数上限、自动跳过用户要求或降低高思考/质量门。

## 验证协议

原始 B2 工具元数据与第一候选进行纯函数复核：旧质量门只拒绝上述实际收集 URL，
修复后第一候选通过，未知 URL 仍拒绝；前后 128 条、模型调用 0。
单文件 scripts/check_candidate_citation_context.py 覆盖挤出引用、成功类型回执、
失败/伪造/普通文本拒绝及本次回执缺失时的保守行为。聚焦回归 66 项已通过。

固定四个新页面 Run A1/B1/B2/A2，同账户/探索/Flash/high/transient_v2/相同搜索问题，
两版使用同一个已验收 Worker 基镜像；只有三个 core 源文件不同。
API/Worker 诊断相同；搜索服务保留上一轮持久化缓存，诊断初始化后连续运行，
不在每个样本前重建或做额外种子查询。真实上游挑战/结果变化如实保留。
首正文为最终正文前 16 个归一化字符首次出现，包含普通临时草稿，不含进度文字；
Host 从点击到业务 completed，DOM 末次变化单列。
SQL 为本轮 Worker attempt 与点击至完成后 1 秒内 API observer 的 DriverSQL execute；
单列空探针，不代表整机数据库总查询量。真实页结果不混入上一轮冷重建样本。

私有证据在 .artifacts/source-candidate-roundtrip-20261017，不提交运行日志。

收尾将恢复来源从 TOOL 会话元数据缩到本次 attempt 的成功事件，避免历史回执参与；
A1/B1 早期版本保留，最终比较只用修订后 B2/A2，仍总共四个模型 Run。

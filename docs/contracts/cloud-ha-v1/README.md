# Cloud HA v1：DDD 与验收合同

状态：设计合同v1，待评审；未实现新接口，未运行验收，不是生产SLA。
基线d782039c；[静态发现、依赖和路径](../../CA-HA-01_baseline_and_scope.md)。
本合同细化[总方案](../../CLOUD_HIGH_AVAILABILITY_PLAN_v1.md)，机器可读规划见
[acceptance.json](acceptance.json)。定义变动须升revision，并使受影响的旧验收失效；
原始数据、原收据和旧证据保留，不能以更新合同改写历史通过/失败事实。

## 1. DDD 不变量与证明职责

| ID | 不变量 | 权威与否定证明 |
| --- | --- | --- |
| INV-01 | 同一原Task/Run/段、Definition/Bundle/资产精确版本恢复，不制造替代Run | 任务/事件/快照存储；启动成功不能证明历史未漂移 |
| INV-02 | 提交受保护事实必须匹配epoch、token、owner及数据库时间有效租约 | 原有lease/fence；不能以进程存活或客户端时间替代 |
| INV-03 | 幂等key和原操作定位不变；unknown只读原GET/授权发现/人工处置 | 持久原意图与原收据；404/超时/无日志均非非提交证明 |
| INV-04 | 失效fence停止新派发；已在途外部效果需原结果核对 | 工具原收据/dispatch边界；本地拒写不证明外部未执行 |
| INV-05 | 每次准入/接管/继续操作仍检查当前身份、授权和撤销 | 安全/Broker/Host公开合同；依赖故障不延长grant、不重领Controller |
| INV-06 | 接受请求、执行结果、执行器退出、资源释放、Coverage互相独立 | 各自权威收据；状态标签/HTTP200不能替代证明 |
| INV-07 | 旧事件、收据、Coverage定位与证明字节保持 | 只读兼容/摘要与原证明验证；不重算新证明冒充旧证明 |
| INV-08 | 回收只针对当前记录在案的精确资源，保留其他Task/业务卷 | 原owner/资源ID/daemon/fence；查无资源不证明未知创建永不晚到 |
| INV-09 | 所有队列、连接、恢复扫描和资源创建有预算；控制面不被长任务饿死 | 进程组合与资源指标；过载明确失败，不静默丢已提交任务 |

模型归属保持原样：agent-core定义既有执行/租约/原操作语义；agent-storage实现原子持久化；
agent-runtime证明执行器/资源生命周期；apps只组合与调度，deploy只做拓扑与资源配置。
不新造HA聚合、业务Tenant/Membership或第二执行队列。技术namespace隔离不替代业务权限。

## 2. 测量口径与首版目标

本轮锁定下面的“验收目标”，并未证明现有容量或环境能达到目标；达不到时记录失败，
不能运行中降低负载/扩大超时后继续沿用同一通过记录。配置调整须新候选/新证据。

| 指标 | 目标 | 计量点/计数方法 |
| --- | --- | --- |
| 控制面请求可用性 | 滚动30日≥99.9% | LB入口至完整响应；合法准入、原GET按操作类型分别统计，不用GET流量稀释写故障 |
| 普通准入p99 | ≤2000ms | 包络内未注入故障阶段，返回可验证原准入结果；unknown/超时计失败 |
| 原GET p99 | ≤1000ms | 原收据一致性检查通过；现有not_observed只能作为正确只读观测，不能冒充已提交成功 |
| API RTO | ≤60s | 注入已确认故障t0，到仍存活副本连续10次合法探测成功；保存全部失败样本 |
| 合法Worker接管 | ≤120s | t0到同Task/Run新有效fence实际执行且有持久事实，不以领取/等待状态替代 |
| 安全阻塞识别 | ≤120s | 权限过期/Worker不兼容/unknown等独立分类；必须有原因和原GET，绝不计接管成功 |
| 已确认准入/收据RPO | 单主节点故障模型内0 | 必须证明同步持久化、旧主隔离及接管后完整读取；仅异步副本不能通过 |
| 备份DR RPO/RTO | ≤15min / ≤4h | 参考隔离数据集的备份时点至最后受保护提交/恢复可读且权威隔离后可放写的实际时间；非生产承诺 |
| 资源泄漏 | owner可重建资源残留0 | 正常/异常/中断后均核对；保留数据资源必须停止并登记理由/期限/处置人 |

所有有效请求的5xx、超时、服务端过载拒绝均进入可用性失败；unknown响应即使安全也不计成功。
明确的调用者4xx单独统计，不能把服务端兼容/容量错误伪装成调用者错误以排除。
模型/业务服务成功率另算；平台有界、正确处置仍须验收，不把外部失败从原始样本中删除。

计时用注入器单调时钟；事件/收据保留UTC；租约使用数据库时间。
每个故障场景独立3次全部通过，记录最差值。样本不足不报告p99；必须记录样本数与算法。
持续负载24h和生产30日观测是不同出口，短测不能替代长期可用性。
Worker恢复样本必须在真实当前授权下可继续；30秒grant已过期时归安全阻塞，
需要合法续权则通过既有公开接口和显式授权办理，不扩大TTL或伪造新鲜度凑RTO。

## 3. 固定参考负载包络 E1

仅用于后续隔离候选，当前不启动：

- 2个API、2个Worker，分散到不同计算节点；每副本2vCPU/2GiB预算。
- migrated命令路径每Worker初始执行槽4，总执行槽8；32个活跃Task包括合法排队任务。
- 256个SSE连接；准入平均5请求/秒，最多16个并发准入；不自动重试POST。
- 输入上限64KiB，事件负载16KiB；隔离基线数据10,000个Task、1,000,000条事件，
  同时保留旧版快照/原收据/Coverage样本。人工构造数据不得覆盖真实历史。
- PostgreSQL/Redis/对象/Broker的版本、配额、连接上限、持久策略、RTT及故障域必须在
  环境清单中填实；缺一则状态environment_unverified，不得宣称E1通过。
- 数据库预算为所有API/Worker/子执行器/调度/控制和维护连接总和，预留控制容量；
  “池上限8”不是整个集群上限。实现前记录每条路径是否真正使用池。
- 上述是目标E1，不是现有生产容量；不得在资源紧张Mac上为了完成指标创建同等集群。
  后续可用专用隔离CI/集群；生产身份/端点/Secret仅通过受控引用配置。

## 4. 故障模型 F1 与排除边界

| ID | 注入点 | 必须结果 |
| --- | --- | --- |
| F-01 | 单API终止，含提交前/COMMIT后响应丢失 | RTO达标，原GET找回原结果；已接收不重复派发 |
| F-02 | 单Worker终止或失联后旧Worker恢复 | 合法同Run接管、旧fence拒写，外部在途保留unknown |
| F-03 | 单计算节点丢失 | 健康副本仍跨节点，旧任务/流恢复；无节点本地唯一权威依赖 |
| F-04 | PostgreSQL主节点故障/切换/旧连接半开 | 单主隔离、RPO/连接预算达标，未知事务不重放 |
| F-05 | Redis/对象服务短时中断与响应丢失 | 分清通知/权威角色，有界补读或拒绝，未知对象写继续核对 |
| F-06 | Broker/JWKS不可达、撤销或grant到期 | 安全阻塞，当前授权不放宽，不以旧缓存绕过撤销 |
| F-07 | 过载、blocked候选与恢复扫描洪泛 | 有界退避、namespace公平性、独立控制预算 |
| F-08 | SIGTERM、挂起执行器、清理响应丢失/晚到创建 | 排空/退出/清理各有证明；其他任务存活 |
| F-09 | SSE断流、换副本、多Scheduler争抢/领取者死亡 | 原游标/原触发/原操作恢复，不新Run/自动重领Controller |
| F-10 | 升级、回退和备份恢复后旧权威重连 | 兼容旧快照/收据/Coverage；旧权威隔离后才可放写 |

F1每次仅注入一个主要故障；组合故障、整AZ丢失、多区域双活、恶意全存储损毁不在首版
达标范围，不借排除理由掩盖授权/数据不变量失守。AZ目标需外部全部关键依赖支持后另立F2。
外部已经提交的业务效果不可撤回，不承诺全局exactly-once或强停取消所有外部请求。
备份恢复不是正常租约接管；恢复环境必须先隔离旧写入，再按既有epoch协议建立权威。

## 5. 就绪/存活与恢复合同决策

以下为02的设计输入，不是当前可调用API：保留/health兼容语义，拟增
GET /health/live、GET /health/ready；需02冻结响应/认证边界后实现。
readiness预算≤1s，只公开无敏感信息的reason code；依赖探测缓存≤5s，排空立即非就绪。
liveness只判断进程控制路径，不查询外部数据库，不把依赖故障变成重启风暴。
Worker本机观测需同时覆盖进程响应和有效调度能力；不能以一个Task等待审批判整个Worker死。
兼容旧/health客户端，未升级部署不得静默切换语义。

成功续权、准入收据、执行结果、安全终止、资源释放和Coverage分别记账。
unknown无自动到期成功/失败，不自动重发或重领Controller；人工处置需当前权限、原因、
原操作和审计，不能改写原收据。恢复代码不得通过“删除旧deferred”规避原业务意图边界。

## 6. 验收记录与出入口

每包含固定源/镜像/合同revision/配置、E1参数、故障注入时点和时钟、事件/收据/fence关联、
外部效果账、旧数据/证明摘要、当前权限、资源前后清单、失败与跳过原因、回退结论。
先保留事实证据，再按owner清单回收。禁止Secret、DSN、token、原始业务载荷进入证据包。

结果枚举：not_run、environment_unverified、pass、fail、blocked_dependency。
CA-HA-01只完成设计与静态检查；所有F1结果当前为not_run。
完整make test/check、受影响SDK/BFF联合、真实多进程/存储与24h持续测试在授权后串行执行。
遗留ERP门禁按基线登记并独立修复，未解决不能报全绿。
生产SLA启用、故障注入、部署、迁移和此前暂停的重型任务均未获本卡授权。

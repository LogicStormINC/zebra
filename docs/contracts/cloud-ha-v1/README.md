# Cloud HA v1：DDD 与验收合同

状态：cloud-ha-v1 revision 4，仅02获代码实施授权并形成候选；其余性能目标仍待验证；新健康接口为候选实现，仅定向验证，不是生产SLA。
基线d782039c；[静态发现、依赖和路径](../../CA-HA-01_baseline_and_scope.md)。
本合同细化[总方案](../../CLOUD_HIGH_AVAILABILITY_PLAN_v1.md)，机器可读规划见
[acceptance.json](acceptance.json)。定义变动须升revision，并使受影响的旧验收失效；
原始数据、原收据和旧证据保留，不能以更新合同改写历史通过/失败事实。

## 1. DDD 不变量与证明职责

| ID | 不变量 | 权威与否定证明 |
| --- | --- | --- |
| INV-01 | 同一原Task/Run/段、Definition/Bundle/资产精确版本恢复，不制造替代Run | 任务/事件/快照存储；启动成功不能证明历史未漂移 |
| INV-02 | Worker拥有的执行提交须匹配epoch、token、owner及数据库时间有效租约；API准入/控制按其原事务、当前授权、原收据和CAS约束 | 原有lease/fence及各操作事务；控制准入不等待Worker持有租约，不强加全局执行租约 |
| INV-03 | 幂等key和原操作定位不变；unknown只读原GET/授权发现/人工处置 | 持久原意图与原收据；404/超时/无日志均非非提交证明 |
| INV-04 | 失效fence停止新派发；已在途外部效果需原结果核对 | 工具原收据/dispatch边界；本地拒写不证明外部未执行 |
| INV-05 | 每次准入/接管/继续操作仍检查当前身份、授权和撤销 | 安全/Broker/Host公开合同；依赖故障不延长grant、不重领Controller |
| INV-06 | 接受请求、执行结果、执行器退出、资源释放、Coverage互相独立 | 各自权威收据；状态标签/HTTP200不能替代证明 |
| INV-07 | 旧事件/原收据/不可变快照/原Coverage证明保持；可重建投影保留来源与语义一致 | 原始证明字节/摘要不变；投影重建不等于改写旧事实，不重算新证明冒充旧证明 |
| INV-08 | 回收只针对当前记录在案的精确资源，保留其他Task/业务卷 | 原owner/资源ID/daemon/fence；查无资源不证明未知创建永不晚到 |
| INV-09 | 所有队列、连接、恢复扫描和资源创建有预算；控制面不被长任务饿死 | 进程组合与资源指标；过载明确失败，不静默丢已提交任务 |

模型归属保持原样：agent-core定义既有执行/租约/原操作语义；agent-storage实现原子持久化；
agent-runtime证明执行器/资源生命周期；apps只组合与调度，deploy只做拓扑与资源配置。
不新造HA聚合、业务Tenant/Membership或第二执行队列。技术namespace隔离不替代业务权限。

## 2. 测量口径与首版目标

本轮锁定下面的“验收目标”，并未证明现有容量或环境能达到目标；达不到时记录失败，
不能运行中降低负载/扩大超时后继续沿用同一通过记录。配置调整须新候选/新证据。

| 指标 | 目标 | 计量点/计数方法 |
| --- | --- | --- |
| 控制面请求可用性 | 滚动30日≥99.9% | LB入口至完整响应；合法准入、原GET按操作类型分别统计，不用GET流量稀释写故障 |
| 普通准入p99 | ≤2000ms | 包络内未注入故障阶段，返回可验证原准入结果；unknown/超时计失败 |
| 原GET p99 | ≤1000ms | 原收据一致性检查通过；现有not_observed只能作为正确只读观测，不能冒充已提交成功 |
| API RTO | ≤60s | 注入已确认故障t0，到LB经存活副本连续10次数据路径请求成功（每秒1次，末次计恢复）；保存全部失败样本 |
| 合法Worker接管 | ≤120s | t0到同Task/Run新有效fence实际执行且有持久事实，不以领取/等待状态替代 |
| 安全阻塞识别 | ≤120s | 权限过期/Worker不兼容/unknown等独立分类；必须有原因和原GET，绝不计接管成功 |
| 已确认准入/收据RPO | 单主节点故障模型内0 | 必须证明同步持久化、旧主隔离及接管后完整读取；仅异步副本不能通过 |
| 备份DR RPO/RTO | ≤15min / ≤4h | 参考数据集上最后共同可恢复水位与故障前最后已确认提交之差/故障t0到完整校验并隔离后可放写的实际时间；非生产承诺 |
| 资源泄漏 | owner可重建资源残留0 | 正常/异常/中断后均核对；保留数据资源必须停止并登记理由/期限/处置人 |

所有有效请求的5xx、超时、服务端过载拒绝均进入可用性失败；unknown响应即使安全也不计成功。
明确的调用者4xx单独统计，不能把服务端兼容/容量错误伪装成调用者错误以排除。
模型/业务服务成功率另算；平台有界、正确处置仍须验收，不把外部失败从原始样本中删除。

计时用注入器单调时钟；事件/收据保留UTC；租约使用数据库时间。
每个具体故障子场景独立3次全部通过，记录最差值；并非一个F编号任选一种故障跑3次。
p99用nearest-rank（排序后第ceil(0.99*N)个），每种操作/每个配置至少1000个样本；
超时/错误不能被剔除以美化延迟，超时按配置deadline计入并另判失败；并报成功样本分布。
测量采用固定5分钟预热、30分钟稳态；24h持续测试使用相同分型和原始样本保留规则。
API恢复探测每秒1组，组内检查已存在的原收据及隔离只读权威事实，不能只请求/health。
任何一次失败重置连续成功计数；恢复时间取第10组完成，故障期间超时/错误均进入可用性分母。
写可用性必须独立使用显式新意图的隔离准入样本和原收据验证，不重复未知POST。
持续负载24h和生产30日观测是不同出口，短测不能替代长期可用性。
Worker恢复样本必须在真实当前授权下可继续；30秒grant已过期时归安全阻塞，
需要合法续权则通过既有公开接口和显式授权办理，不扩大TTL或伪造新鲜度凑RTO。

## 3. 固定参考负载包络 E1

仅用于后续隔离候选，当前不启动：

- 2个API、2个Worker，分散到不同计算节点；每副本2vCPU/2GiB预算。
- migrated命令路径每Worker初始执行槽4，总执行槽8；按下面两个独立场景分别验收，
  不把结果拼成“32个长期任务下还能持续5次/秒准入”的未经验证结论。
- E1-A准入：开环5次/秒、最多16个在途请求、256个SSE连接；使用确定性短任务，
  将模型/工具替身的响应预算和结果写入清单。是真实API/PG/Worker组合，非真实模型容量证明。
  任务完成后退出活跃集；32为场景目标活跃上限，超限/拒绝即容量目标失败，不能删样本。
  客户端在途上限使计划请求未发出时，记录offered/issued/completed及生成器饱和，
  该次包络测量不可判通过，不暂停开环时钟来隐藏排队；POST仍不自动重试。
- E1-R恢复：先显式创建32个活跃Task（含24个排队）、256个SSE连接，再注入单故障；
  不额外持续灌入5次/秒新任务。按合法可恢复/安全阻塞分型，保留所有旧原操作。
  两场景均需单独验完整故障子项；真实模型/业务长任务在独立小样本验正确性。
- 输入上限64KiB，事件负载16KiB；隔离基线数据10,000个Task、1,000,000条事件，
  同时保留旧版快照/原收据/Coverage样本。人工构造数据不得覆盖真实历史。
- PostgreSQL/Redis/对象/Broker的版本、配额、连接上限、持久策略、RTT及故障域必须在
  环境清单中填实；缺一则状态environment_unverified，不得宣称E1通过。
- 数据库预算为所有API/Worker/子执行器/调度/控制和维护连接总和，预留控制容量；
  “池上限8”不是整个集群上限。实现前记录每条路径是否真正使用池。
- 上述是目标E1，不是现有生产容量；不得在资源紧张Mac上为了完成指标创建同等集群。
  后续可用专用隔离CI/集群；生产身份/端点/Secret仅通过受控引用配置。

## 4. 故障模型 F1 与排除边界

| ID | 注入点 | 必须结果 |
| --- | --- | --- |
| F-01 | 单API终止，含提交前/COMMIT后响应丢失 | RTO达标，原GET找回原结果；已接收不重复派发 |
| F-02 | 单Worker终止或失联后旧Worker恢复 | 合法同Run接管、旧fence拒写，外部在途保留unknown |
| F-03 | 单计算节点丢失 | 健康副本仍跨节点，旧任务/流恢复；无节点本地唯一权威依赖 |
| F-04 | PostgreSQL主节点故障/切换/旧连接半开 | 单主隔离、RPO/连接预算达标，未知事务不重放 |
| F-05 | Redis/对象服务短时中断与响应丢失 | 分清通知/权威角色，有界补读或拒绝，未知对象写继续核对 |
| F-06 | Broker/JWKS不可达、撤销或grant到期 | 安全阻塞，当前授权不放宽，不以旧缓存绕过撤销 |
| F-07 | 过载、blocked候选与恢复扫描洪泛 | 有界退避、namespace公平性、独立控制预算 |
| F-08 | SIGTERM、挂起执行器、清理响应丢失/晚到创建 | 排空/退出/清理各有证明；其他任务存活 |
| F-09 | SSE断流、换副本、多Scheduler争抢/领取者死亡 | 原游标/原触发/原操作恢复，不新Run/自动重领Controller |
| F-10 | 升级、回退和备份恢复后旧权威重连 | 兼容旧快照/收据/Coverage；旧权威隔离后才可放写 |

每行含多种故障时逐项拆分：F-01为进程终止/COMMIT前应答丢失/COMMIT后应答丢失；
F-05分别对Redis、对象读故障和对象写应答丢失；F-06分别为不可达/撤销/到期；
F-08分别为正常SIGTERM/挂起/清理失联/晚到创建；F-09分别验SSE与Scheduler；
F-10分别验滚动升级/回退/备份恢复及旧权威重连。其余行也按实际注入点建唯一case_id。
同一case每次只注入一个主要故障，不能一次切断所有依赖后声称逐项通过。

RPO=0仅约束事先声明的故障模型和同步提交策略；不得自动提升落后的异步副本。
没有安全升主条件时保持拒写，正确性通过不代表可用性通过。对象与PG必须有共同恢复水位、
内容摘要/索引和不可变Coverage证据的读回证明，不能用PG备份时间推断跨存储一致性。

F1每次仅注入一个主要故障；组合故障、整AZ丢失、多区域双活、恶意全存储损毁不在首版
达标范围，不借排除理由掩盖授权/数据不变量失守。AZ目标需外部全部关键依赖支持后另立F2。
外部已经提交的业务效果不可撤回，不承诺全局exactly-once或强停取消所有外部请求。
备份恢复不是正常租约接管；恢复环境必须先隔离旧写入，再按既有epoch协议建立权威。

## 5. 就绪/存活与恢复合同决策

以下设计已在02候选接线，未部署：保留/health兼容语义，新增
GET /health/live、GET /health/ready；实际范围和验证见第8节。
readiness响应预算≤1s；从有界后台依赖观测取结果，观测过期/未完成返回非就绪，
不在探针线程直接执行可能受libpq最短超时/DNS阻塞影响的数据库连接。
后台探测并发/队列有界，不能每次HTTP请求创建新线程；观测最大年龄5s，排空立即非就绪。
匿名健康路径仅精确匹配GET /health/live、/health/ready，禁止按/health前缀放行其他业务路径；
方法/路径/认证拒绝回归必须覆盖。公开响应仅汇总状态，不返回依赖名、配置版本或内部拓扑；
详细reason code仅本机/管理授权观测，并避免Secret/租户信息。
liveness只判断进程控制路径，不查询外部数据库，不把依赖故障变成重启风暴。
Worker本机观测需同时覆盖进程响应和有效调度能力；不能以一个Task等待审批判整个Worker死。
兼容旧/health客户端，未升级部署不得静默切换语义。
定义Worker采样生命周期：启动为unknown，受控tick/控制通路有进展才刷新；时间戳不由
探针读取本身刷新。长任务/HITL/空队列不直接判死，维护失败、调度能力失效须反映为非就绪。
02只观测已有排空/能力状态，不创建排空控制接口、改变领取/队列或依赖未合入强停。
Worker观测本机只读，不新增公网端口；采样失效/未知一律不报告可调度。

成功续权、准入收据、执行结果、安全终止、资源释放和Coverage分别记账。
unknown无自动到期成功/失败，不自动重发或重领Controller；人工处置需当前权限、原因、
原操作和审计，不能改写原收据。恢复代码不得通过“删除旧deferred”规避原业务意图边界。

## 6. 验收记录与出入口

每包含固定源/镜像/合同revision/配置、E1参数、故障注入时点和时钟、事件/收据/fence关联、
外部效果账、旧数据/证明摘要、当前权限、资源前后清单、失败与跳过原因、回退结论。
先保留事实证据，再按owner清单回收。禁止Secret、DSN、token、原始业务载荷进入证据包。

结果枚举：not_run、environment_unverified、pass、fail、blocked_dependency。
CA-HA-01只完成设计与静态检查；所有F1结果当前为not_run。
完整make test/check、受影响SDK/BFF联合、真实多进程/存储与24h持续测试在授权后串行执行。
遗留ERP门禁按基线登记并独立修复，未解决不能报全绿。
生产SLA启用、故障注入、部署、迁移和此前暂停的重型任务均未获本卡授权。

## 7. 用户卡顿、卡死与并发性能合同（revision 3补充）

本节为设计目标，全部未运行；不能以健康探针正常、心跳不断或有新文本就认定执行有进展。
复用Task/Run、原准入/调度事实、工具原收据、SSE游标和当前scope，不另建执行状态机。
新增用户展示是事实的派生视图，不赋予执行权、不修改历史状态枚举或原证明。
平台前端mock保持；真实SDK/BFF/Host UI验收必须另登记消费任务和固定源，不能用mock冒充。

### 7.1 时间线、指标分母和场景

记录同一原操作的以下关联点；只保存技术坐标/计时，不保存token或业务全文：

- T0：参考客户端显式提交；T1：LB收到；T2：权威准入/原收据提交；T3：原排队事实可观察。
- T4：持有效fence开始该次执行；T5：模型请求实际派发；T6：供应商首个可用内容到达。
- T7：对应持久事件可读；T8：客户端收到对应帧；T9：参考界面实际呈现。
- S0：显式停止进入LB；S1：原控制收据提交；S2：被授权的精确执行器及后代退出；
  S3：租约撤销/精确资源回收/权威同步分别完成。停止接受不等于S2/S3成功。

同进程时间用单调时钟，跨主机分段分别采样并记录时钟同步误差；不得直接相减无校准的
单调时钟。端到端由参考客户端测量。排队时间用可比的存储时钟/同一测量器，不能因换Worker
重新计时；任务的合法审批/授权等待单列，但不从用户端总等待记录中删除。
每种指标/每个负载与配置至少1000样本，nearest-rank p99；
每scope分桶不足1000时不输出该scope的p99或容量通过结论，只报样本数/最长等待/未验证。
固定30min初测不足时保留不完整结果，后续同配置补测或24h证据独立报告，不混拼不同负载。错误、超时、缺失帧、观测不到
起点/终点保留并分别判失败或测量无效，不能从成功样本中掩盖。沿用F1逐子场景3次规则。

E1-A延续短任务开环场景，声明模型替身TTFT≤100ms/完整响应≤300ms、单次工具≤200ms，
Task累计执行槽占用目标≤1s；实际API/PG/Worker和传输链路仍须真实。冷沙箱/脚本、长任务、
真实模型、HITL与UI Effect各自分桶，不套用该短任务首内容目标或混合计算p99。
浏览器参考配置、SDK/产品UI源、CPU/内存、网络RTT≤50ms及丢包情况必须写入环境清单；
不满足则不得声称端到端目标通过，仍保留失败/延迟原始数据。上游模型性能单独报告。

### 7.2 多用户场景 E1-C / 过载 E1-O

- 在线用户、SSE连接、排队Task和实际执行槽四项分开记录；256连接不代表256个执行槽。
- E1-C在E1-A相同总5rps和硬件上，分别使用1/16/32个已合法绑定的principal/scope，
  固定256条流连接总数，不随用户数额外加流量。scope从可信签名与当前绑定取得，
  不接受客户端任意scopeKey，也不新增Tenant/Membership领域。
- E1-C混合样本：一个低负载scope1rps，其余scope合计4rps；另测一个scope不断请求额度，
  多余请求应按声明技术限额有界拒绝，不能挤占低负载scope和控制预算。
  证据列出每scope发出/接受/拒绝/排队/执行及最长等待，不用总体均值遮蔽单用户饥饿。
- E1-O按0.5x/1x/1.5x/2x的E1-A准入速率分档，每档独立5min预热+30min稳态；
  在硬件/依赖清单限额内运行，首次触及任一安全阈值即停止升压并判该档容量目标未通过。
  2x未触顶仅证明已测包络，不推断无限容量；低档/高档结果不得合并作同一SLO样本。
- 达到已声明的拒绝阈值前，准入必须完成持久判定；确定未准入才可明确拒绝/提示稍后重试。
  客户端对有歧义提交仍只查原GET，不因429/503文本就自动重发原业务意图。
- 全副本连接、排队字节/条数、线程与运行中调用、执行器、SSE缓冲、每scope份额均须填
  硬上限/独立控制预留；任一空缺为environment_unverified，禁止以压测未崩溃认定有界。
- E1-R的32活跃Task恢复仍独立测，不与E1-C开环容量拼接成新的承诺。其他负载需新包络。

### 7.3 卡死与停止的正确性边界

疑似停滞是观测，不是新的Task终态或非提交证明。复用既有事实区分：排队、模型等待、
工具执行、等待审批、等待前端效果、连接中断、权限阻塞、unknown、实际执行无进展。
仅在所属合同的deadline/权限/fence与停止规则允许时处置；不能对合法长任务统一60秒强杀。
诊断含当前阶段、阶段年龄、最近实质进展和可用原操作查询，不伪造精确完成时间。
Worker safety net有影子模式，须核对实际开关与负面样本；日志记录不当作真实阻断。

请求返回超时不证明底层线程、数据库查询、模型请求或工具进程已停止。
复核所有to_thread/线程池调用和下层I/O deadline；准入、执行、观测/控制预算分离，
重试结构性失败不应忙循环，暂时依赖失败应有界退避而不是擅自终止原任务。
恢复/超时不能扩大grant、重领Controller或重放原POST；停止未知只读原停止进度。

执行器退出、外部业务效果与资源清理分别证明；已发往外部的请求不能保证撤回。
Docker/节点失联或未知晚到资源时，保留原清理义务与requires_reconciliation；UX-06目标
判未通过，而不是改写收据伪造释放。强停候选未合入前相关场景blocked_dependency。
保留原Task/Run、历史/收据/unknown/Coverage；需要新业务意图必须由业务显式发起。

# Zebra Cloud Agent 100 分严格验收闭环计划 v1.0

状态：本地闭环完成，生产验收受外部环境阻塞
基线日期：2026-09-26

## 1. 目标

将 `Zebra_Cloud_Agent与React组件库优化实施方案_v1.0.md` 从“本地框架已搭建”
推进到可审计的严格验收。只有对应出口产生了真实证据，才计入完成分数；代码存在、
模拟通过、HTTP 200、模型自述、描述性 manifest 和环境跳过均不计作真实验收。

保持既有模型和思考强度。PostgreSQL 继续作为 Cloud 执行与受治理记忆权威源，Redis
只可作为可降级缓存。不得伪造真实模型、浏览器、gVisor、canary 或 rollback 证据。

## 3. 执行阶段

### A. 包工程供应链闭环

1. 统一并冻结 SDK 的 Node、pnpm、TSDX 和 TypeScript 版本，删除未使用构建依赖。
2. 增加 tarball 审计：只允许发布清单内文件；拒绝 `.env`、测试数据、密钥样式、
   绝对仓库路径和源码旁路。
3. 增加 tree-shaking 消费 fixture，证明单组件导入不会保留未使用组件 JavaScript。
4. 将 build、test、pack 审计、React 18/19 Vite/Next 矩阵接入 CI。

出口：clean install 后一条 SDK CI 命令完成全部检查，真实 tarball 通过审计和消费矩阵。

### B. React 与 Trench 浏览器闭环

1. 建立真实浏览器 fixture，不用 JSDOM 代替布局与 hydration 验收。
2. 覆盖桌面和窄屏、中文 IME、附件上传/移除、Enter 发送、焦点保持、切换会话、
   自动滚动、执行中展开、完成后折叠、reconnect/resume/retry 和键盘导航。
3. 在 Trench Host adapter 中验证这些流程消费正式 tarball；业务路由和权限仍归 Trench。
4. 生成机器可读结果和失败截图/trace，不以 Next build 代替浏览器验收。

出口：React fixture 与 Trench 真实页面浏览器矩阵全绿，无 hydration 错误和内容丢失。

### C. 可执行真实任务评测

1. 将描述性案例升级为版本化 fixture bundle；每个输入必须是实际文件、服务或权威快照。
2. 提供一个真实 Zebra runner：创建隔离工作区和 durable Session/Turn，调用当前配置模型，
   捕获模型调用、工具、Artifact、Effect、Memory 和终态 ID。
3. 提供独立 verifier registry；verifier 只读权威结果，不接受模型自述。
4. 先运行 12 个代表任务各 3 次；修复失败后再运行 60 个任务各 3 次。
5. 开发集用于修复；留出集在冻结实现后运行。禁止用重复 Session/Turn/model-call 填充次数。

出口：180/180 真实尝试完整，报告首次/最终成功、人工介入、误报完成、恢复、引用、
重复工具、首反馈、总耗时和可用成本，并保留逐例失败归因。

### D. 结果质量、记忆和效率闭环

1. answer/research/change/create/operate 分别由独立 postcondition 验证。
2. 运行同义召回、偏好反转、临时偏好、跨项目/租户隔离、删除抑制和无关记忆干扰。
3. 对冷启动、热循环、恢复、压缩和子任务唤醒分别统计 token、延迟、重复工具和成功率。
4. 只有真实结果提升且无隔离/权限回归时，才确认质量和效率收益。

出口：结果验证和记忆矩阵全绿；各缓存边界具有可比较的机器可读证据。

### E. 可靠性与发布闭环

1. 在真实 `runsc` 环境执行全部 Effect/gVisor 场景，包括工具前、外部写后和终态落库前故障。
2. 将干净 Zebra/Trench commit、四个包版本、镜像 digest、迁移、协议、配置 digest 和
   测试 Artifact 冻结为一个不可变候选。
3. 在真实 Trench 页面验证新旧会话、审批、记忆、Artifact、恢复和诊断信息。
4. 按 internal 0% -> canary 5% -> full 100% 执行并记录观察窗口。
5. 使用同一候选完成应用回滚和能力关闭演练，确认无重复副作用和数据库向前兼容。

出口：候选验证、gVisor、浏览器、canary 和 rollback 均绑定同一 digest；线上健康与业务
后置条件通过。

### F. 最终门禁与交付

1. Zebra `make check`、完整测试、PostgreSQL/Compose、SDK 和浏览器门禁全绿。
2. Trench 测试、lint、生产构建、离线 frozen install 和浏览器验收全绿。
3. 显式路径暂存，提交到正确分支；不混入来源不明文件。
4. 文档分别报告实现、验收、真实任务成功率和生产发布，禁止再次混写为单一百分比。

## 4. 停止条件

以下任一条件只会将对应阶段标为 `blocked`，不会伪造 PASS：缺少模型凭据、真实 fixture
无法构造、`runsc` 不可用、远端不可达、发布坐标不干净、浏览器或回滚失败。

严格 100 分要求 A-F 全部出口通过；外部阻塞存在时，最高只能报告已验证分数。

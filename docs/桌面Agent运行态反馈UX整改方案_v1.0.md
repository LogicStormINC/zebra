# Zebra Agent 桌面端运行态反馈 UX 整改方案 v1.0

## 1. 文档目的

本方案定义 Zebra Agent 桌面端从用户提交任务到最终结果到达期间的运行态反馈标准。
目标不是增加装饰性加载动画，而是让用户持续知道：任务是否已接收、Agent 当前是否仍在工作、
最近发生了什么、是否需要用户介入，以及如何停止或继续。

本方案的第一阶段只消费现有持久化会话事件和会话投影，不新增虚构阶段、百分比或思维链展示。

## 2. 当前问题

当前前端在会话创建后、模型结果尚未返回时，插入一条内容为“暂无返回”的临时 Assistant 消息。
该内容同时获得 Agent 身份、执行中标签和复制操作，形成三个错误暗示：

1. 用户误以为 Agent 已经返回了一个空答案。
2. “暂无返回”描述结果缺失，而不是系统正在工作的事实。
3. 临时占位与真实 Assistant 内容共享同一视觉层级，完成后容易造成跳变或重复感。

此外，运行状态分散在任务标题、时间线、Assistant 标签、右下角图标和侧边栏色点中，
但缺少一个明确的“当前状态 + 最近进展 + 可执行操作”焦点。

## 3. 商业 Agent 参考结论

- Codex 强调实时进度、任务清单、工具/终端证据、Diff、测试结果和审批，而不是使用空回复占位。
  参考：<https://openai.com/index/introducing-codex/>、
  <https://openai.com/index/introducing-upgrades-to-codex/>。
- Cursor 将真实动作逐条流式展示，并允许查看状态、补充要求或接管后台 Agent。
  参考：<https://docs.cursor.com/background-agent>、
  <https://docs.cursor.com/en/cli/reference/output-format>。
- Devin 明确区分 `working`、`waiting_for_user`、`waiting_for_approval`、`finished`，
  并将需要用户介入的状态提升为显著信号。
  参考：<https://docs.devin.ai/api-reference/v3/sessions/get-enterprise-session>。

Zebra 不复制这些产品的视觉外壳，而采用一致的产品原则：运行态必须真实、可追踪、可打断，
等待用户的任务必须比普通运行任务更醒目。

组件选型采用项目已安装的 Ant Design X `ThoughtChain.Item`。该组件的官方用途就是追踪
Agent 对 Action 和 Tool 的调用链，能够复用现有主题和语义状态。Lobe UI `HTMLPreview`
适合沙盒化渲染 HTML 结果，不承担本阶段的运行状态；以后出现 HTML 交付物预览需求时再引入。

## 4. 设计方向

视觉方向采用“克制的工业工作台”：深色中性背景、低噪声层级、事件证据优先。

- 橙色只表示正在运行。
- 黄色表示等待用户操作。
- 红色表示失败。
- 绿色表示完成。
- 灰色表示草稿、暂停或尚未开始。
- 不再使用含义不明确的独立紫色状态点。
- 动效仅用于轻量运行脉冲，并尊重 `prefers-reduced-motion`。

## 5. 核心组件边界

### 5.1 `AgentActivityCard`（Ant Design X `ThoughtChain.Item` 实现）

运行期间唯一的当前状态焦点，位于事件流末尾、Composer 上方。视觉上采用对话流中的轻量
单行节点，不使用大面积背景、强调边框或独立卡片容器。

显示内容：

- 当前阶段文案
- 最近一条可公开事件与已运行时间
- 悬停或键盘聚焦时出现 `查看运行日志`

该卡片不是聊天消息，不提供复制按钮，不进入最终对话内容。

### 5.2 `AssistantMessageBlock`

只渲染真实的 `model_response_received` 内容或后端明确返回的 Assistant 消息。
不得用“暂无返回”“等待中”等占位文本创建 Assistant 消息。

### 5.3 Inspector `运行` 页签

第一阶段不新增页签；运行详情继续由时间线和现有日志承载。
后续当运行事件密度明显增加时，再评估把 `运行` 作为活动会话的默认 Inspector 页签。

## 6. 事件到用户文案的映射

| 真实状态或事件 | 主文案 | 辅助文案 |
| --- | --- | --- |
| 提交后尚未收到持久事件 | 正在开始任务 | 已收到你的请求 |
| `session_created` | 正在准备任务 | 会话已创建 |
| `model_request_started` | 正在生成答复 | 等待模型返回 |
| `harness_attempt_started` | 正在处理任务 | 第 N 次执行 |
| `tool_call_proposed` | 准备使用工具 | 友好工具名称 |
| `tool_execution_started` | 正在使用工具 | 友好工具名称 |
| `approval_requested` | 需要你的确认 | 确认后才能继续 |
| `clarification_requested` | 需要补充信息 | 回答问题后继续 |
| `session_suspended` | 任务已暂停 | 可以恢复或停止 |
| `session_failed` | 任务未完成 | 查看日志后重试 |
| `session_cancelled` | 任务已停止 | 已保留现有记录 |
| `session_completed` | 处理完成 | 卡片退出，保留完成事件 |

约束：

- 只有真实网络工具进入 `tool_execution_started` 后，才能显示“正在搜索网络”。
- 没有工具事件时不得猜测 Agent 正在读取文件、搜索或测试。
- 不显示不可验证的完成百分比。
- 不展示隐藏思维链；只展示事件、工具和用户可验证的执行摘要。
- 用户刚提交继续任务但新事件尚未同步时，当前请求的 `isRequesting` 状态临时覆盖标题栏与摘要中
  上一轮的终态文案；收到新投影后立即回到服务端状态。

## 7. 长等待与连接状态

活动会话超过 8 秒没有新事件时，主状态保持不变，辅助文案切换为：

> 仍在处理，暂时没有新的运行记录

同时继续显示真实累计耗时。该状态表示事件静默，不宣称模型卡死。

如果 SSE 断开但 API 健康检查仍正常，应显示“正在重新同步运行记录”；
如果 API 也不可达，应显示“本地运行时连接中断”，并提供重试连接入口。
连接状态不得伪装成 Agent 执行状态。

## 8. Composer 行为

第一阶段保留 Ant Design X `Sender` 的原生取消能力，执行中只提供一个主要停止入口，
避免运行节点与输入框出现两个同义按钮。

- 空闲：显示发送按钮。
- 正在执行：`Sender` 发送按钮切换为停止按钮，Tooltip 与 `aria-label` 均为“停止任务”。
- 等待审批或澄清：使用现有内联面板完成交互。
- 当前后端未承诺运行中消息队列，因此不使用“稍后发送”或“已加入队列”等文案。

后续只有在 API 提供持久化 follow-up 队列后，才允许运行中追加指令，并显示队列状态。

## 9. 第一阶段实现范围

### 必须实现

1. 删除创建会话和终止会话续问路径中的“暂无返回”临时 Assistant 消息。
2. 新增纯事件驱动的运行状态投影。
3. 在事件流末尾使用 Ant Design X `ThoughtChain.Item` 渲染轻量运行节点。
4. 显示真实累计耗时，并在事件静默超过 8 秒后显示长等待提示。
5. `Sender` 停止操作使用明确 Tooltip 和可访问名称。
6. 完成、失败、取消、暂停、等待用户等状态不渲染为普通运行卡。
7. 补充确定性检查和浏览器回归。

### 明确不做

- 模型 token/delta 流式协议
- 虚构阶段和进度百分比
- 思维链展示
- 运行中 follow-up 队列
- 新的 API 状态机或事件类型
- Inspector 信息架构重做
- 新依赖

## 10. 后续阶段

### 第二阶段：真实文本增量输出

在 API 提供可恢复的模型输出 delta 事件后，Assistant 内容可以逐步展示；断线恢复仍以持久事件为准。

### 第三阶段：可转向执行

增加持久化 follow-up 指令队列、运行中改变方向、跨设备通知和后台任务接管。

## 11. 验收标准

- 提交任务后立即出现运行反馈，不出现“暂无返回”。
- 结果到达前不存在可复制的伪 Assistant 消息。
- 当前阶段文案可以由会话状态或持久事件解释。
- 工具名称只在真实工具事件存在时显示。
- 运行卡显示真实累计耗时；8 秒静默提示不会误报失败。
- `waiting_input`、`waiting_approval`、`suspended`、`failed`、`cancelled`、`completed`
  使用各自语义，不继续显示普通“执行中”。
- 停止操作可被键盘聚焦并具有明确可访问名称。
- 最终 Assistant 回复只出现一次，现有事件时间线、审批、澄清、任务计划和 Inspector 不回归。
- Node 22 前端检查、生产构建和浏览器验收通过。

## 12. 设计决策

本阶段选择“删除伪消息 + 增加 Ant Design X 运行节点”，而不是把“暂无返回”改为“正在思考”。
原因是运行状态和对话内容属于不同的信息类型；继续共用 Assistant 消息组件会保留复制、内容语义、
持久化和完成切换上的歧义。

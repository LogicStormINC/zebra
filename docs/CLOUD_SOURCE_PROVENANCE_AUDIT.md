# 来源路径与重复取证：真实链路审计（2026-10-17）

## 结论

结构化结果路线停止，本轮没有运行任何结构化结果对照。
发现并修复的是**回放遗漏公开会话状态**：原 Node 会话已经明确确认首次发布日期，
旧回放却删去该结论，并额外拆出一条 assistant 确认消息。这会影响下一步选择。
不能依据该回放把“反复核对首次发布日期”认定为生产 Cloud 的固有行为。

最小已证实改动是忠实保留原公开消息与工具批次的配对，复用原生会话语义；
不增加摘要指令、事实分类器、工具数量限制或来源硬编码。该修复属于诊断工具，
**不是生产性能提升**。生产主循环本来就保留这些公开结论，本轮没有找到需要
修补的同类生产丢失点，也没有可证明稳定收益的生产优化可以上线。

原 B1 的产品页绕路和公告＋文档并行抓取是真实执行，仍然存在；这次审计没有
把它们宣布解决。它们不是相同请求被重复派发，也没有本轮新证据证明唯一的模型
内部原因。不要以修复回放为由宣称首正文、模型轮数或 SQL 已降低。

## 未出现的 URL 来自哪里

审查实际完整工具元数据，而非只看此前缩减病例。Node 初决策中的
`.../en/blog/release/v22.11.0`，以及后决策提议的 v22.0.0／v24.0.0 页面地址，
在相应决策点的公开正文和完整 metadata.evidence_refs 中均不存在。
因此不能归因于这些具体地址在模型投影时丢失。

原 Node Run 的第二轮确实直接提议了未观察到的 v22.11.0 地址；请求成功，
随后得到最终答案。公开记录只证明模型提供了一个未观察到的路径；“根据已知
版本规律或记忆生成”是合理推断，不是对私有思考的读取或唯一原因证明。

相关实际实现：

- `web_fetch_contract` 接受 URL 字符串；它不要求携带搜索命中或用户原文的来源凭据。
- WebFetchTool 解析合法目标后执行，结果元数据记录实际 URL。
- 授权／DNS／SSRF 校验处理是否允许访问该目标，不判断该路径是否出现在先前证据中。
- EvidenceLedger 登记成功工具的来源引用；最终质量门检查引用是否来自成功证据，
  不是抓取前的 URL 来源证明，也不判断两个页面是否语义重复。

所以，成功抓到一个先前未观察到的 URL 后，它就能成为有效引用来源。
这是来源依据与网络授权的不同边界，不能称为授权绕过。也不能把所有直接访问
已知官网地址都当成错误：没有搜索前直接读用户指定 URL 或已知文档入口是合法需求。

不推荐“一律先搜索”或“仅允许已观察 URL”：这会增加本来可直接读取的请求和
模型往返，改变工具能力边界；当前成功样本不能证明它带来性能收益。

## 已有证据为何还会取证

需要区分三类：

1. **相同请求重复执行**：现有 fingerprint、freshness 和 loop guard 已处理。
   在原 B1 八次调用中，没有相同参数的重复派发；增加一层 URL 缓存解决不了它。
2. **同批预期重叠取证**：B1 在读到 GA 正文之前就同时提议 GA 与版本文档。
   事后知道 GA 足够，不等于当时已经掌握全部证据。当前无新增丢失机制可修复。
3. **公开完成状态丢失引发再核对**：Node 的旧回放存在这个可复现缺陷；
   不能用它推断原生产会话同样丢失状态。

## 最小修复与固定验证

共享回放修复：每个工具批次只生成一条 assistant 消息；使用对应原始
model_response_received.assistant_message 公开内容；不额外拆出确认消息。
仅为协议提供同样的空 reasoning_content，占位不是原始私有思考。
工具结果、顺序、目标问题和原工具说明均保持不变。

生成前冻结16次比较：Node 初决策与 LTS 公告后决策，Python／SQLite 正文齐全后的
决策；每点2次重复、旧重建L和修正C交替。原生 high／Flash／auto 流式调用，
零工具执行、零 Provider 重试，16次均成功。

随后事先冻结4次因子隔离，仅 Node 公告已读决策：

- N：恢复公开批次内容，但保留额外确认消息，2/2仍提议两份首次发布页。
- T：移除额外确认消息，但批次内容仍为占位文本，2/2同样提议两份首次发布页。

因此只能说在这个小样本中，**同时恢复公开内容和正确消息拓扑**消除了该类额外
提议；不能单独断言“增加一句已确认摘要”就是解法。没有加入新事实或新指令。
初决策的未观察 URL 行为并未消失，不能把两个问题混为一个已修复问题。

共20次有效模型响应，所有旧重建、修正和不利因子结果均保留。未替换样本，
未执行所提议工具，也没有重新运行原任务。原 Host 完整上下文、目录与私有

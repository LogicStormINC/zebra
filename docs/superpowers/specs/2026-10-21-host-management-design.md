# Scoped Host Registry Management — CA-P1-01B1

Date2026-10-21; owner Luke Ding. Approved task scope follows the user's continuation/autonomous-decision instruction. Native Host registry trust is distinct from outbound connector profiles; connectors follow in B2. Go consumption follows publication, never Python imports or Runtime SQL.

## Decision and alternatives

Reuse HostRegistryRecord and host_authority_registries. Add a bounded native HTTP adapter with explicit operator-approved mounted template and shared PostgreSQL approval. Direct database writes from Go violate ownership; reusing target.describe credentials would grant unintended authority. Neither is acceptable. No framework/dependency/JWT signer.

## Public use case

GET/PUT /management/v1/host-registry, contract host-registry-management/1. Dedicated rthm_ plus43 URL-safe characters; never rtmg_/operator/Agent credentials. Required existing X-Runtime deployment/audience/product/environment/trust-revision headers must match private configuration. No cookies, query parameters or duplicate authentication/scope headers. GET has no body; PUT accepts exactly expectedRevision integer0..2^53-2, operationId canonical UUID and active boolean.16KiB maximum, JSON only, duplicate/unknown/missing/null fields rejected.

One credential/config binds one deployment/product/environment/HostApp/namespace, with an approved full HostRegistryRecord template. Request cannot select issuer/JWKS/origins/algorithms/scope; PUT changes only active and the approved template. Operator rotates template by next trustRevision+CAS approval. API update may reactivate explicitly with active=true; this is not an irreversible identity tombstone. Existing privileged CLI still manages registry and is not credentialed by this API.

Response contains contractVersion, registry (null before creation, otherwise camelCase fields hostAppId,namespaceId,issuer,audience,jwksUri,allowedOrigins,algorithms,policyVersion,active), revision (0 when missing), replayed boolean. Replayed success returns its original snapshot; it is not current state. GET always current. All no-store.400 invalid;401 credential;403 scope/action/expiry;409 CAS/idempotency mismatch;429 local capacity;503 unavailable/stale approval/unknown commit. No raw errors/secrets/DSN.

## Private configuration and approval

ZEBRA_HOST_REGISTRY_MANAGEMENT_CONFIG optional absolute private regular JSON,0600/0400,max16KiB. Fixed fields deploymentId,deploymentNamespace,audience,productId,environment,trustRevision,credentialSha256,expiresAt,actions,registry. Registry uses existing HostRegistryRecord validation with active=true template; actions a unique subset host-registry.read,host-registry.write (empty explicitly disables all requests); registry hostAppId128/namespace512. Expiry UTCZ future checked currently. Fingerprint canonical sorted compact JSON bytes (original string expiry included), SHA256; strict duplicate fields rejected before canonicalization.

An explicit native operator command loads this private file and uses existing PostgreSQL database_url from settings. -expected-revision approval initializes0→1 or CAS increments; approved scope (deploymentId/deploymentNamespace/audience/productId/environment/hostAppId/namespaceId) cannot change. New token/template/actions/expiry requires revision+1; missing file or DB approval fails closed. To revoke, approve a current config with no actions (empty actions is explicit disabled approval; all API calls forbidden), retaining history. Operator command has no startup DDL; existing migrate command applies additive v108 explicitly. Approval record stores scope/fingerprint/revision/expiry (no secret), per deployment+HostApp+namespace. Old replicas with stale fingerprint/revision fail even with a valid old file.

## Storage/consistency

Add registry revision BIGINT NOT NULL DEFAULT1. Legacy existing upsert increments revision on every successful update; INSERT starts1; no data/JSON/history rewrite. Existing upsert does not acquire a new separate lock: its native INSERT/UPDATE row locking is enough with the API's SQL CAS UPDATE/INSERT guarded by unique key. Missing-row concurrent creation uses INSERT ON CONFLICT DO NOTHING and yields409 for loser. No delete; disabling keeps registry, grant ledger and audit.

New host_management_approvals stores binding,immutable scope,current revision/fingerprint/expiry. Explicit approval uses one per-binding advisory transaction lock then SELECT FOR UPDATE/upsert; no caller network. API transaction SELECT approval FOR SHARE, verify exact scope/revision/fingerprint and clock_timestamp expiry. Locks held until mutation/read/audit/receipt commit. Auth checked BEFORE reading receipts, so revoked/stale credential cannot replay prior success. Effective monotonic DB deadline is min(request deadline, current config/approved expiry); recheck clock_timestamp expiry after registry row locks and before audit/receipt return, including replay. A transaction which waits on a registry lock until expiry must roll back, never mutate after the credential deadline. Registry mutation uses expected revision, max safe bound; trust approval and mutation serialize, different Hosts do not serialize globally.

host_management_receipts key deployment+host+namespace+operationId, payload digest includes current trustRevision/fingerprint and expectedRevision/active/template. Same operation/payload returns original snapshot; different rejects409. Serialize API same-binding operations using the SAME per-binding advisory lock as approval, BEFORE approval FOR SHARE; this is short metadata-only work, never external I/O. This also prevents two identical operations racing on receipt insert. Legacy writer relies on row CAS, not advisory lock. Audit and receipt in same transaction, no tokens. Approval audit also atomic. Lost COMMIT is503 UNKNOWN outcome, no retry; exact operation replay/current GET reconcile after reauthentication. One mutation committed once.

## Bounds and composition

Eight request slots/instance covering config+DB thread completion, immediate429 withRetry-After1; caller budget5s, body budget0.2s, configuration bytes bounded and nonblocking regular-file check. Slot remains held if timeout/cancelled thread still running. All approval/receipt/advisory keys use native identity (deployment_namespace, host_app_id, namespace_id). Store uses existing PostgresDatabase.connect_task_io(deadline=effective_deadline) for5s total, statement/lock bounds, no application retries. Existing Task I/O DNS/transaction deadlines are reused; slots still retain actual completion for cancellation safety. Multiply by replicas; no performance/HA claims.

Only optional config composes B1. If absent route still denies503 without forcing execution stores. Configured route requires PostgreSQL database_url; local SQLite returns503, never writes fallback. HTTP app determines namespace only when A or B1 configured. No startup migration/approval. New code requires v108 before B1 use; Existing SQL readers ignore the additive column, but native startup requires the exact schema catalog; unmodified v107 binaries may reject v108 and are not a promised rollout/rollback set. Feature rollback uses a v108-compatible binary with B1 closed. Old privileged writers do not increment revision. Coordinate ALL privileged registry writers to new version before enabling API; old writers are an unsupported mixed-version writer set. Disable optional B1 and retain schema for rollback; do not promise safe CAS with older writer binaries.

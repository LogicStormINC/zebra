## 1. 复核结论与范围

核心架构已覆盖运行定义、原生脚本、附加能力、独立部署与认证，但此前不能认定业务流程已经闭合。
本轮按“产品接入→开发→上线→业务用户使用→长期运行→升级→退出”复核，补齐以下十个流程域。
“缺少”指此前设计缺少可执行流程，不代表 cloud-agent 中完全没有对应底座。

| 流程域 | 复核判断 | 补齐位置 | 范围要求 |
|---|---|---|---|
| 页面上下文与前端动作 | 缺少产品接入流程，已有 Client Integration 底座 | §2 | 嵌入式首版必需 |
| 澄清、审批、待办 | 已有底层能力，缺少用户闭环 | §2 | 有相应交互/写入的首版必需 |
| 会话与 successor Task 交接 | 缺少具体交接流程 | §3 | 支持会话内换能力/重新准入前必需 |
| 业务写入与部分成功 | 已有 Effect 原则，缺少用户可见处置 | §4 | 有业务写入的首版必需 |
| 知识、文件、记忆的生命周期 | 已有检索/Memory/Artifact，缺少派生内容治理 | §5 | 首版采用受控读取；持久索引另设门禁 |
| 长任务、触发器、结果送达 | 后台委托已有原则，缺少任务入口和触发范围 | §6 | 长任务首版必需；定时按需启用 |
| 环境晋级与部署路由 | 已有部署原则，缺少使用步骤与基数约束 | §7 | 独立部署与生产发布必需 |
| 模型、配额和运营处置 | 配置域已有，缺少异常时的业务行为 | §8 | 声明支持的生产运行能力必须闭合 |
| 产品停用、解除管理与退出 | 有删除边界，缺少完整流程 | §9 | 产品独立运维必需 |
| 业务回归与交付验收 | 已有技术门禁，缺少跨用户旅程的证据 | §10–11 | 相应业务上线前必需 |

首版仍限定可信内部开发者、Python、cloud-agent 引擎、Compose、单 IdP 和内部 Catalog；不因此新增通用工作流平台。
销售 CRM、工单、电商、内容生产等各业务动作由原生能力包和 Host API 实现，Jorice 不分别内建这些业务系统。
公共 Marketplace、商业计费、低代码编排、多地区、多主 Agent 自动路由、跨引擎透明迁移和任意格式解析不进入首版。
前端首版复用类型化 Readable/Action/Approval/Clarification 与现有组件；任意生成组件、DOM selector、任意浏览器 JS 不作为默认能力。

## 2. 嵌入业务 UI：身份、上下文、交互和结果

### 2.1 产品接入步骤

1. 业务方配置认证 adapter、同源 BFF、允许的 Agent/资源与 EmbeddedAgentAuthProfile，沿用认证补充 §2。
2. 发布不可变 Frontend Capability Profile，声明 Readable、Action、schema、敏感等级、资源绑定、大小、时限和支持 SDK/协议版本。
3. 后台创建前端接入并确认到目标，生成该环境公开 Key；业务页面经 npm Provider/bootstrap 和已有 React SDK/AG-UI 注册 Hook，只上报实际挂载子集，Key 不单独赋予操作权。
4. 以业务用户会话建立 Client Session 和 Task Run Binding；将 Profile digest、挂载快照、Origin、部署与用户绑定。
5. 完成上下文、动作、审批、断线恢复与多 Tab 验收后，才将该前端版本列为发布兼容版本。

Jorice 管理 Profile、兼容矩阵和接入证据；业务前端拥有本地处理函数；Runtime 拥有准入、Controller、Effect 与收据校验。
SDK 升级、页面发布和 Runtime 发布分别有版本；Profile 不匹配时明确拒绝或显示具体不可用能力，不能静默运行未知合同。
已有 TypeScript/React SDK 是优先复用对象，不另建一套聊天框架；不同 UI 技术通过公开客户端合同接入。

### 2.2 页面上下文与动作

Readable 可以表达路由、已选对象、筛选条件、表单草稿或业务摘要；每份快照保留来源、资源引用和 UI revision。
输入执行 schema/大小/敏感字段校验；不接收整份 Redux/Zustand store、全量表格、Cookie、Token 或隐藏页面数据。
页面状态是上下文，业务接口仍是业务事实与权限权威；浏览器传入某个 object_id 不证明用户能访问该对象。
页面切换/对象修改后，旧快照失效或降为明确历史；需要最新状态的动作必须匹配 expected UI revision。

Client Action 只执行受控导航、展示、本地状态和交互，不承接正式业务写入；业务写入走 Host Backend Tool。
每个 Run 最多一个 Active Controller，其余 Tab 是 Observer；Controller 续租、切换和 Receipt 使用现有 fence/CAS。
卸载页面释放控制权；崩溃通过有界 TTL 失效。重新挂载需核对 Task/Run/能力版本，不能让旧 Tab 执行新任务动作。
动作未挂载、UI 已变化、超时、用户拒绝和执行结果不确定分别显示，不把“事件送达浏览器”显示成“操作成功”。

### 2.3 澄清、审批与用户待办

需要用户输入时创建持久交互记录，至少固定 Task/Run、问题或动作合同、参数/资源版本摘要、可回答主体/角色、期限和状态。
澄清使用受限问题/选项/表单合同；审批展示将修改的对象、动作、影响范围、风险及有效期，回答后通过同一 BFF 当前会话提交。
服务端重新鉴权并校验交互 revision、身份、参数摘要和期限；重复提交幂等，错误主体/旧 fence/过期/参数变化均拒绝。
批准、拒绝、修改建议分别记录；修改参数先生成新提案和新确认，旧批准不能用于不同写入。
审批只是针对该动作的 Policy 输入，不扩大用户/Task 权限，不替代执行时 ACL、资源版本和预算检查。

业务 UI 提供“当前会话待处理”和“我的任务/待办”入口；刷新/重连从 Runtime 查询同一交互状态，不能只靠前端弹窗内存。
离线后释放 Worker 执行租约并持久等待；浏览器专属动作不能由后台伪造完成。
重新登录可按同一授权主体恢复待办；登出后是否继续其他后台步骤依照显式委托策略，不能混同于 Controller 在线状态。
完成、拒绝、失效与被后继任务取代都具有可见状态；没有受支持的交互组件时暂停并解释下一步，不让模型猜答案继续。

验收：重复批准只产生一个受控业务 Effect；刷新仍看到同一待办；两个 Tab 只有 Controller 能执行；旧对象版本和旧确认均不能写入。

## 3. 业务会话、消息与 Task 交接

### 3.1 会话管理与基础交互

业务 conversation 是稳定的产品体验标识；Task 是冻结执行配置/授权的工作单元，Turn/Run/Segment 是引擎执行标识，不能相互代替。
业务 BFF 保存 conversation 到目标 deployment/当前 Task/历史 Task 的受权绑定或其引用；Runtime 继续拥有 Task 执行事实。
创建、列表、继续、重命名、归档、读取历史和删除各自授权；会话归档不代表取消任务，取消也不代表删除业务结果。
请求携带 client_message_id/幂等键和预期会话 revision；重连/重发不能重复接受消息或重做写入。
首版同一会话串行接收执行输入；运行中输入按公开合同入队或明确拒绝，显示已接收/排队状态，不静默丢弃，也不让两个 Worker 并行解释同一指令。
删除操作按数据保留策略处理：先停止新的会话交互，再处理在途工作和可删除数据；安全审计及不可删除业务收据按规定保留受限元数据。

### 3.2 successor Task 的交接协议

更换包 digest/逻辑连接、扩大权限或切换不兼容版本需要新 Task；原 Task 的后续 Turn 不能悄悄换入新组件。
仅刷新同一受限连接的短时凭据且不改变固定绑定时，按认证补充的 lease 合同执行，不无条件创建新 Task。

1. 记录交接请求、原因、原 Task、候选 Bundle/能力、期望 conversation revision 和幂等键；向用户说明需重新授权或确认的变化。
2. 停止向原 Task 提交新输入；原 Task 在检查点暂停/排空，由目标持久确认并推进执行 fence，使旧 Worker/脚本的晚到决策与新调用失效，同时收紧旧 Controller 和未执行待办。
3. 查询全部已发写入：成功保留收据、失败按合同处理、unknown 先对账；未能确认的冲突写入阻止新 Task 执行相关写操作，无法证明范围互不冲突时暂停全部新写入。
4. 重新校验当前用户/工作区/资源/连接，按明确白名单交接摘要、检查点和附件引用；来源与权限不丢失，不复制旧授权或未经确认的可执行指令。
5. 目标准备候选 Task，记录 predecessor/successor 关系和交接标识；候选处于持久 hold，不能被 claim、排队执行、调用模型/工具或下发 Client Action。conversation 指针以预期前驱/revision CAS 选中唯一候选。
6. 仅 CAS 获胜的交接可通过受信 BFF 发出绑定 conversation/前驱/候选/交接 revision 的幂等激活；目标复核精确绑定和新鲜授权/撤销后解除 hold，失败候选废弃且拒绝其激活。前端确认激活后再建立新流游标、Client Binding/Controller；旧待办、Receipt、命令与游标不能当作新 Task 输入使用。
7. 新任务从交接检查点继续；已完成业务动作作为带收据事实引用，不能通过重放自然语言请求再次执行。

交接操作本身持久、可查询、可恢复；BFF 持久串行化同一 conversation 的交接，激活结果未对账前不能开始下一次切换。CAS 后宕机恢复同一激活，创建成功但响应丢失用原标识查询；目标 hold/激活/fence 合同需新增，不能假定现有 TASK_PREPARED 自动满足。
已接收未处理消息逐项标记由原任务完成、明确取消或经用户/Policy 确认移交新任务，保留原 client_message_id 与交接关联；不能漏掉已确认接收的输入，也不能在两任务各执行一次。
新 Task 未就绪则保留“等待交接/授权”的原会话状态，不假称已经切换；已冻结旧 Task 不自动恢复写入，恢复也需新鲜授权及明确操作。
无法可靠交接某引擎的内部状态时，只允许显式结束旧任务后以受权摘要新建，不宣称透明恢复。
旧任务历史可按当前权限查询；新身份不能通过 conversation 关联获得旧任务权限。

验收：会话中新装 Plugin 后可继续；旧任务成功写入不重做；unknown 不越过；旧页面无法驱动后继任务；交接任一步重启可对账。

## 4. 业务写入、撤销和部分结果

读操作、写提案、批准、实际执行、业务收据、结果验证分开记录；脚本输出和浏览器 Receipt 不能代替业务提交证据。
高风险写入先生成对象/字段/数量/预期版本的差异预览，并按 Policy 请求确认；低风险免确认也仍需完整授权和审计。
Host API 执行时复核用户委托、当前 ACL、对象版本及业务规则；对象已变返回冲突，由用户/策略重新规划，不能沿用旧批准覆盖。
每个业务步骤使用稳定 Effect/幂等标识，网关记录真实响应和必要回读；不以 HTTP 200 或模型自述作为完成证明。

多步任务显示逐步成功、失败、未执行及 unknown；批次有任何未满足完成条件时不得显示“全部成功”。
网络超时、取消、Worker 崩溃之后先对账；“取消成功”只能说明停止后续受控执行，不能承诺撤回已在外部完成的写入。
补偿仅在业务接口提供明确反向操作和权限时可用；补偿也是新受控 Effect，必要时再次审批，不能声称数据库式全局回滚。
用户能从任务详情查看已产生的业务结果、待对账项和允许的处置；运维重试入口复用此状态，不另开绕过幂等的脚本。

验收：对象版本冲突不会覆盖新值；收到成功响应后断流不会重复写；部分成功/补偿失败/unknown 的界面与真实业务结果一致。

## 5. 知识、附件、内容和记忆治理

### 5.1 首版可落地范围

区分外部知识源、用户上传、项目维护上下文、运行产物和长期 Memory；配置分别声明来源、scope、格式、版本、保留和写入规则。
首版优先调用已有受权 Host 检索/内容 API 和已支持的 Artifact/解析器；不为“支持各种内容”预先建设完整知识库平台。
未提供 ACL/删除同步及派生追踪合同的来源，禁止开启持久索引或长期 Memory 写入，只允许受限实时读取和相应保留策略。
格式支持矩阵展示“已实现/需外部解析器/不支持”，包括大小、编码、分页、OCR/音视频等限制；有配置字段不代表已有解析能力。
外部网页/文件文本是带来源的不可信数据，不能通过文内指令扩大权限、安装 Plugin 或改变执行 Policy。

### 5.2 接入、更新与派生关系

接入流程：登记授权源与数据范围→校验连接→试读→明确解析/检索/引用策略→首批处理→增量更新→监测失败/滞后→撤销或删除。
每份内容记录来源 ID、版本/digest、权限权威、读取时间和派生关系；提取文本、chunk、embedding、缓存、Capsule、Memory 和产物引用保持可追溯性。
索引是派生物，源业务系统继续拥有数据与 ACL；检索和 context build 在使用边界核验当前访问权，缓存命中不能跳过权限检查。
上传授权、完成确认、内容/摘要校验、任务绑定和下载分别校验；上传句柄不能跨用户/环境/任务任意使用，未完成孤立上传按期限清理。
批处理/同步记录任务状态、处理版本与失败项；部分索引不能展示为完整，重复处理用稳定来源/版本身份去重。

冻结 Bundle 约束处理行为，不自动冻结业务数据版本。需要固定数据快照的任务显式记录来源版本与范围，实时数据任务标明读取时点和刷新策略。
权限收紧永远可以阻断后续使用；历史 Task 的旧快照不赋予继续访问源数据的永久权利。
Memory 写入明确个人/工作区边界、候选/确认、来源、期限和删除规则；不能把个人对话默认转成团队共享记忆。

### 5.3 撤权、删除和历史产物

源 ACL 改变/删除后建立限制或墓碑，后续检索、重放上下文、缓存读取、Memory 使用、历史产物下载均执行传播后的约束。
业务 API 可同步拒绝；异步索引设置最大 ACL 新鲜度，超限停用该读取路径，不能把“稍后同步”当作继续访问的依据。
产物记录源依赖与输出受众；内容派生默认采用相关来源访问条件的交集，只有源业务明确允许的脱敏/发布策略才可改变输出受众。
无法可靠拆分受限来源的摘要/Memory/产物先整体阻断，再重建获准版本；必要时停止受影响执行并经新准入继续，不能让模型自行声称已忘记。
删除保留期内的受限审计元数据与删除正文分开；清理失败可重试并可查看，不将失联存储标记为已删除。
保留/删除检查覆盖 Event/Trace/模型请求记录和备份，不只删除 Artifact；新内容合同将可删除正文与不可变执行元数据分离，以受权 payload 引用保留来源关系。
历史内联正文或外部模型留存不能满足产品策略时，限制该来源/Provider 或阻止准入，不能声称应用隐藏等于物理删除；备份到期清理及恢复后墓碑重放同样需要验收。
不承诺撤回已经交付到用户屏幕或下载到外部的内容；设计控制的是后续读取、执行与平台持有副本。

验收：资料撤权后缓存、已派生 Memory 和产物下载不能绕过；删除不会留下公开提取文本；不支持的格式不会被标记为处理成功。

## 6. 长任务、调度与结果送达

业务 UI 的“我的任务”至少显示排队、运行、等待输入、等待审批、等待认证/客户端、暂停、取消处理中、完成、部分成功、失败和待对账。
这些是对真实引擎事件的投影及等待原因，需有公开映射；不能为实现状态文案另建一套可写执行状态机。
SSE/订阅支持游标和断线恢复，同时提供受权查询兜底；结果/通知只携带受控引用，打开后仍查当前权限。
页面关闭后按 bounded_task_delegation 决定是否继续；重新登录能定位结果和下一步，认证失效不会偷用其他用户或产品凭据。
首版必需交互/手动/API 触发；定时任务按产品需求启用既有 once/interval/calendar 能力。签名 Webhook 是后续 adapter，未实现时明确不支持。

启用定时时的完整流程：

1. 有权主体选择 Agent、输入模板、资源范围、时间/时区、missed-run、重叠策略和有效期，确认这是独立的后台委托。
2. 服务端保存无秘密的 schedule 与受限 authority template，不保存浏览器 Cookie、长效 HostGrant 或明文 Token。
3. 每次触发重新核验委托主体/成员关系、产品状态、资源、凭据和预算，再准入一个固定版本的新 Task。
4. 首版保留现有精确 Definition digest 绑定，v2 同时固定 Bundle；当前生效版本不匹配则拒绝触发并显示待重绑定。发布新版本后由有权主体审阅差异、重新授权/绑定计划，不能自动跟随 latest。
5. occurrence ID/预期时间/输入摘要持久去重；重投返回同一任务，skip/coalesce 和 forbid/allow 按已声明规则执行。
6. UI 支持暂停、恢复、修改未来计划、查看触发历史/失败与人工补跑；已接受任务取消与计划停用分开处理。

时区、夏令时重复/缺失时点和停机漏跑行为必须与实际 scheduler 合同一致并可预览；不能由浏览器本地时区猜测。
现有 scheduler 的 `agent_definition_drifted` 拒绝语义保持兼容；未来若支持跟随当前 Release，需独立版本化选择策略、固定授权上限并逐次保存实际 Bundle/准入证据，不混入首版复用范围。
账号禁用/委托到期/产品停用后不再接受新触发；安全撤销继续影响已有任务后续调用。
Webhook adapter 将来需额外实现来源签名、重放时间窗、事件 ID 去重、schema/大小限制及固定目标映射；外部事件本身不构成用户授权。
默认交付入口是业务产品内任务/待办；邮件、IM、回调只作为显式配置并授权的通知适配器，不为首版另建通知平台。

验收：相同 occurrence 不重复创建动作；离线后能找到结果；重新授权停在受控检查点；停用计划不假称取消已提交业务写入。

## 7. 环境晋级、部署与路由

### 7.1 开发→测试→生产

锁定同一源码/包版本，再逐环境解析 endpoint、Secret 引用、外部 scope、资源范围、SDK/引擎版本和运行限制；不复制登录会话、用户授权或生产密钥。
UI 展示环境差异和最终配置；每个环境独立生成 Bundle/DefinitionVersion，并取得对应的构建、目标及业务验证证据。
测试环境必须使用测试账号和业务沙盒；无业务沙盒时只读试跑或拒绝写入，不把容器隔离视为业务无副作用。
生产真实写入验收采用明确许可的测试对象和范围；mock、回放、只读检查与真实写入证据分别标记。
包、最终 Bundle、环境、Policy、公开合同或前端 Profile 变化时，相应门禁证据失效并重验；不能把开发环境 passed 直接带到生产。
生产激活仍由目标 AgentRelease CAS 确认；Jorice 环境流程不新增第二个版本生效权威。

### 7.2 路由基数与故障

首版一个 `(product, environment, authority_issuer, namespace)` 准入映射只有一个活动 deployment 身份；一个 deployment 可有多个共享权威的 API/Worker 副本。
真实 scope/用户绑定完成后由受信入口选择 deployment；浏览器不能传任意 runtime URL，歧义、未知或跨环境映射拒绝。
已接受 Task 固定 deployment/Registry/执行库身份，URL 改变不能把任务迁往另一个独立运行库；同部署副本接管继续核验 Bundle/Lease。
多 scope 发布记录逐 scope 准备/激活/失败结果，任何部分成功都显示具体范围，不能声称全产品原子生效。
首版跨 scope 版本切换先在各目标持久设置本地准入 hold 并排空，再逐项激活与核对；全部达到目标后逐项恢复入口，失败显式恢复或继续对账。入口恢复也逐项记录，不承诺跨目标原子切换，不依赖每次请求回查 Jorice。
多版本并行/灰度需先完成 Worker claim 版本匹配和旧版本支持，不能仅用负载均衡比例实现。
漂移区分被批准的目标变更与未知修改；观察后明确申请接纳或重应用，不直接覆盖现场数据库/配置。

验收：同 namespace 不同环境不能串线；副本故障不丢任务；独立 deployment 不靠换 URL 接管；部分激活、响应丢失和重启可逐项对账。

## 8. 模型、配额、可用性和运营处置

模型配置分别固定 Provider 连接引用、模型/角色、能力要求、参数、区域/数据策略、超时、重试和允许 fallback。
能力发现和调用前检查工具调用、上下文长度、视觉等必需能力；未配置且未通过兼容验证的模型不能自动替换，错误不得被包装为正常答案。
同一固定连接的密钥轮换遵循凭据合同；变更模型、逻辑 endpoint/账号/能力集合按新 Bundle 或新 Task 规则处理。
Provider 故障或限流显示受控重试/暂停/失败；已经形成的模型决策在恢复时重放，不能因为切换模型重做已提交步骤。

预算至少覆盖 Task 的调用/token/时长/产物和并发限制；生产跨 Task 的产品/工作区配额需在目标权威侧持久预留、消耗、释放和对账。
跨 Worker 并发采用原子占用和有界 lease/fence；Redis 可加速，不能作为唯一计数事实；Jorice 只聚合读数，不进入每次调用路径。
取消、超时、接管和用量未知时保留预留/待对账，不能通过重试清零；达到预算停止后续受控动作并保留真实部分结果。
暂不支持某全局配额时 UI 明示不可配置，不能接受数值却只在单 Worker 内检查。商业价格、套餐、发票与支付继续由业务系统拥有。

| 运营事件 | 用户状态与最小处置 |
|---|---|
| 排队阻塞/容量不足 | 展示排队原因；运维查目标 Worker 能力、租约和资源，按限定范围扩容/排空 |
| 授权/连接失效 | 等待当前用户或指定连接管理员重新授权；不换账号、不扩大 scope |
| Client 无法恢复/审批过期 | 待办说明所需页面/动作；重新绑定或重新提案，拒绝旧 Receipt |
| 预算/速率耗尽 | 显示已发生用量和未完成步骤；收紧/调整后依照任务版本合同继续或新准入 |
| unknown Effect | 保持待对账；查询业务结果，不能直接按失败重试写入 |
| 包撤销/部署漂移/合同不兼容 | 阻断受影响路径；定位 digest/目标/版本，走正式发布或恢复操作 |
| PG/对象存储/Secret 不可用 | 按依赖拒绝/暂停；恢复后核验状态，不降级到另一份空库或凭据 |

告警阈值、责任人、去重/确认与处置链接可配置，记录投递和确认；不预设未经测量的可用性或时延承诺。
诊断通过 operation/Task/Effect/Trace 关联 ID；只导出获授权的脱敏证据。支持人员不因管理角色自动获得业务内容或真实写入权限。
备份/恢复明确各部署的 RPO/RTO 目标与实测；恢复检查撤销新鲜度、包引用和 unknown Effect，不能把旧快照恢复当作权限复活。

验收：Provider 失败不静默降级；多 Worker 不能超领同一并发名额；预算耗尽保留部分事实；运营重试遵守同一授权/版本/幂等边界。

## 9. 产品停用、解除管理、归档与销毁

这些是不同语义操作，不用一个“删除产品”按钮隐含全部副作用；每个操作持久记录范围、预计影响、保留策略和目标确认。

| 操作 | 明确结果 |
|---|---|
| 停止接入/暂停运行 | 关闭新会话、新 Task 和触发器；在途任务按选定的排空/暂停/取消策略处理 |
| 解除 Jorice 管理 | 回收 Jorice 管理/部署权限；Runtime 可按明确交接方案独立保留，不自动撤销业务运行信任或删除数据 |
| 归档产品 | 停止可执行入口，保留按授权可查询的配置、结果和审计；禁止新准入 |
| 彻底退出/销毁 | 执行批准的授权撤销、资源销毁与数据清理，逐项给出成功/失败/待保留结果 |

彻底退出的顺序：

1. 生成目标、scope、依赖资源、在途任务/Effect、计划、凭据、包引用和保留要求清单，检查执行身份与资源所有者授权。
2. 先关闭受影响的新入口和定时/外部触发器，再排空/取消/暂停在途任务；未决业务 Effect 对账或明确移交受限处置。
3. 撤销该产品目标的运行信任、Client 会话、委托与专属连接，停用 Plugin；共享账号/凭据/包不得因单产品退出而全局删除。
4. 按授权导出配置、包引用、审计和必要结果；默认不导出明文 Secret、第三方 refresh token 或其他用户数据。
5. 停止目标进程，按依赖顺序销毁专属资源；保留/删除运行数据分别执行，墓碑和撤销记录在规定期限内保留。
6. 核对包/镜像/对象的所有 Bundle/Task/备份引用，满足 retention 和共享保护后再 GC；失败项可重试，不显示虚假“已清空”。

旧 URL、签名键、BFF 绑定和计划不能复活新任务；重新接入走新登记/受控恢复，不通过恢复旧目录记录自动开通。
解除管理、迁移、销毁均不承诺在外部业务 API 自动撤回已有写入；业务资源所有者决定业务结果是否需补偿/保留。
Jorice 目录删除不直接删 Runtime 库；产品 A 的停用、解除管理或 GC 都不能影响 B。

验收：新任务停止、在途有明确结果、共享资源保留、旧授权不可再用、销毁失败可定位和续作；解除管理后按交接合同独立运行。

## 13. 产品接入清单与责任分配

### 13.1 每次接入必须提交的信息

业务类别模板可以复用运行组合、能力包和表单 schema；真实身份、授权、接口、Secret 与数据范围必须逐产品/环境绑定，不能从模板继承生产账号。
Jorice 的首次接入向导以本清单逐项检查，不要求运营人员手填内部 digest；由服务端解析版本并展示业务可理解的差异。

| 信息域 | 最小提交内容 | 提供方与验收责任 |
|---|---|---|
| 业务目标 | 代表性问题、允许动作、禁止动作、成功/部分完成条件、首版不支持场景 | 业务负责人定义，集成负责人形成验收样例 |
| 身份/权限 | 登录校验入口、稳定主体/工作区映射、Agent 使用权、对象 ACL、退出/撤销来源 | 业务后端负责事实；安全人员与 Runtime 验证求交 |
| 业务 API | Tool 合同、环境端点、资源版本、幂等/查询收据、错误和限流语义 | 业务后端提供，原生脚本开发者适配 |
| 业务 UI | 前端接入/环境公开 Key、BFF/bootstrap、Origin、路由/Readable/Action、支持 SDK/Profile、审批/待办入口 | 业务前端提供，接入团队联合验收 |
| 数据与内容 | 来源/格式/大小、敏感等级、允许出境/模型范围、引用、ACL 新鲜度、保留/删除 | 数据所有者确认，目标执行约束 |
| 原生/附加能力 | 必需包、组件入口、允许的 Plugin、风险/权限上限、连接账号的归属 | 产品管理员批准，Runtime 独立再校验 |
| 运行资源 | 引擎/沙箱、模型、CPU/内存/磁盘、并发/预算、域名/网络/存储和环境隔离 | Runtime 运维提供，业务确认容量目标 |
| 运维/退出 | 值班责任、告警入口、备份 RPO/RTO、在途处理、交接与删除保留要求 | 产品资源所有者和运维共同确认 |

业务方至少完成 BFF/认证接入、受控 Host API、所需前端 Hook 和权限源连接；不承诺只填后台表单即可替代这些业务开发。
已有 API/SDK/认证 adapter 可复用；只有数据库而没有受控接口时，先提供 Host adapter，不给脚本生产数据库连接。
没有资源级 ACL 或不能核验用户委托时，只能进入受限开发验证；不能以 Agent 服务账号管理员权限替代用户权限后上线。
没有远端幂等/查询收据能力的写接口，必须声明无法确认的窗口并采用禁止自动重试/人工对账；无法满足业务要求时不开放该动作。

### 13.2 谁拥有最终决定权

| 决策/操作 | 业务系统/团队 | Jorice | cloud-agent Runtime |
|---|---|---|---|
| 用户、成员关系、对象权限 | 权威，提供验证/撤销 | 保存接入配置与外部主体引用 | 验签、求交、执行前复核；不复制用户目录 |
| 技术产品、环境、模板/脚本意图 | 提需求并确认范围 | 权威、版本化并审计 | 接收公开合同，验证兼容性与上限 |
| 生效 AgentRelease | 按部署流程授权发布 | 请求、跟踪、展示确认 | 目标 Registry 唯一权威，执行 CAS |
| Task/Event/Effect/Artifact | 提交受权请求、拥有业务数据 | 按授权聚合只读信息 | 执行事实与状态转换权威 |
| 正式业务写入及补偿 | 业务 API 校验并产生业务收据 | 不直接执行业务写入 | 经网关提交受控 Effect，持久记录/验证 |
| Secret/第三方账号授权 | 账号所有者授权/撤销 | 管理引用、流程与可见状态 | 目标 Credential Gateway 按绑定释放 |
| 暂停/销毁与数据保留 | 资源所有者批准范围 | 形成 operation、分步编排 | 本地阻断、对账并确认执行；不替业务撤回既有写入 |

任何一方的管理员身份都不自动成为另一方的数据权限；管理接口、运行接口和业务接口分别鉴权。
Jorice 不可用时业务 BFF 与目标 Runtime 仍能执行已部署合同；外部认证/业务接口失效时照常遵守安全边界，不转到万能后台账号。

## 14. 状态、操作和用户展示合同

### 14.1 分开记录四类状态

1. 产品管理意图：可接入、暂停、归档、解除管理、待销毁；由 Jorice 管理操作记录，不充当执行许可。
2. 部署/发布观察：期望 Bundle/Release、目标实际 revision、操作阶段、确认时间、未确认 scope 和漂移；来自目标。
3. 任务执行事实：Task/Run/Session、已有事件、等待原因、Effect 结果及交接状态；由 Runtime 提供。
4. 页面显示：以上事实的受权投影和最后观察时间；失联显示未知/陈旧，不把旧的 active/成功显示成当前确认。

产品暂停必须得到目标本地准入 hold 的持久确认；只改 Jorice 目录字段不算已经停用。
多目标暂停一部分失败时显示具体范围，并阻止平台宣称整体停用；可恢复的本地限制不依赖 Jorice 每请求在线。

| 展示状态 | 证据与允许操作 |
|---|---|
| 排队/运行 | 目标已接受的命令与当前租约/运行事件；可查询、按权限取消，不按 SSE 在线推断 |
| 等待输入/审批/客户端 | 当前有效交互/Client Effect；只展示该用户可处理的事项，不能拿等待状态绕过 Controller |
| 等待认证/暂停 | 明确原因和受限恢复入口；重新认证后再核验固定绑定，不自动借用连接 |
| 取消处理中 | 取消命令已接受，但在途调用/租约尚未确认；保持真实未知 Effect |
| 成功/部分成功/失败/取消 | 结合终止事件、完成条件和业务 Effect 证据，不以 Session.completed 单独判定业务全成功 |
| 待对账 | 存在未知写入/激活/部署结果；优先查询同一标识，不提供无条件“重跑全部” |

现有 SessionStatus、ClientEffectStatus 等原样通过版本化适配映射；新增等待原因先有目标合同，不能在 Jorice 数据库伪造执行状态。
多个条件并存时，安全阻断/待对账先展示，历史部分结果仍可按权限查看；交互待办与任务终止同时发生时，待办失效而非继续可批准。

### 14.2 长操作的通用约束

有副作用或需要对账的跨进程管理写操作先持久记录 operation，包含 actor、product/environment/目标、请求摘要、预期 revision、幂等标识与原因，再异步执行；只读发现/查询不强制创建异步 operation。
操作阶段与结果确定性分开：目标超时/响应丢失保持该阶段并标记 outcome_unknown，进入对账；只有确认未成功或已失败时才确认 failed。
重启查询同一目标/operation/revision，不能用新 operation 盲重发；重试时重新鉴权，安全撤销可以阻断余下步骤。
取消管理 operation 是停止后续编排的请求，不代表撤销已创建资源或已激活 Release；清理由独立补偿/回退操作承担。
每步记录期望、实际、证据、可重试性与安全下一步；查询/恢复/终止权限按资源检查，不能只因知道 operation_id 就获权。

## 15. 对外接口合同与请求一致性

以下是必须具备的语义操作清单，属于待实现公开合同；具体路径在各切片 OpenAPI 中定义，不声明当前已有统一 Management API。
继续复用当前公开用例和幂等/CAS 模式，现有 v1 路由保持原合同；新 v2 Bundle、hold/激活和委托字段不直接塞入严格 v1 schema。

| 接口域/调用方向 | 必需语义 | 关键校验与返回 |
|---|---|---|
| Jorice 后台→Jorice | 产品/环境/模板 CRUD；草稿校验、差异、解析、构建 | 管理会话/CSRF、资源权限、revision；最终值来源和结构化错误 |
| Jorice→目标 Runtime | descriptor/schema、prepare/validate、激活、hold/drain、状态/对账 | 目标 audience/管理 scope、版本/digest、operation、预期 revision；真实目标身份/观察结果 |
| Jorice→包/连接管理 | 发布/信任、安装、配置、认证、启停、升级/撤销/卸载 | 产品/环境/发布者权限、包摘要、安装 CAS、连接属主；期望与目标实际分列 |
| 业务浏览器→BFF | 打开/继续 conversation、发消息、任务列表、交互回答、产物读取 | 当前业务会话、绑定、资源 ACL、CSRF/Origin；受控句柄和获准投影 |
| BFF→Runtime | Task/输入、Client Session/绑定/Receipt、审批/澄清、取消/恢复、流/查询 | Host/Client/Run 合同、主体/工作区、消息幂等、fence；事件游标/受权结果 |
| BFF→Runtime 任务交接 | prepare-held、查询、activate/abandon、原任务安全暂停确认 | 交接 revision/前驱、唯一选择证明、当前授权；持久 hold 和实际激活状态 |
| Runtime→Host | 业务查询/写入、收据查询、必要补偿 | workload + 受限用户委托、对象版本、稳定 Effect ID；实际业务状态/收据 |
| 调度/恢复→Runtime | 受权 occurrence、新任务准入、对账/重试 | 无秘密的授权模板、当前主体状态、精确版本、幂等与预算；无登录会话旁路 |

### 15.1 写请求与错误语义

写请求的幂等域固定为受信 actor/委托链、产品/环境、操作类型和目标资源，再绑定请求摘要；同键同摘要返回原操作引用，同键异摘要冲突拒绝。
查找幂等结果之前也鉴权；不能向第二个用户返回第一个用户的结果。跨系统转发保留业务关联 ID，但各边界分别生成/验证自身安全身份。
更新使用 expected_revision/If-Match；当前 Plugin API 的创建 Idempotency-Key、更新 If-Match 可作为复用模式，不要求无差别改写所有旧端点。
长操作返回已持久接受的 operation 引用，而非立即成功；保留期覆盖声明的重试窗口，关键业务动作到期后仍保留必要去重/收据墓碑，不当作新动作再次执行。

错误语义至少区分：未认证、无权、资源不可见、缺少前置 revision、CAS 冲突、输入/合同不兼容、依赖/凭据未就绪、限流/预算、暂时不可用和 outcome_unknown。
HTTP 层可使用 401/403/404/428/409/422/429/503 等合适状态；v1 保持兼容，新合同提供稳定 error_code、retryable、correlation_id 和获权可见的 operation 引用。
错误不能泄露其他 scope 的对象、账号或 Secret；限流/依赖失败也不能返回伪造成功。可重试只表示允许按同一幂等标识恢复，不自动授权另一次业务动作。

### 15.2 查询、流和下载

查询采用稳定排序/分页游标，绑定查询范围和必要过滤 revision；游标不是授权，重用仍查当前身份与资源可见性。
事件去重使用目标身份、Task/Run 和单调序列；浏览器重连从服务端已确认游标继续，重复投递不触发重复命令/Receipt。
同一已验证范围内游标失效/历史被保留策略裁剪时，返回显式需重建投影，由查询快照及其边界游标恢复；不能从任意最新事件假装没有缺口。
产物使用受鉴权代理或有限范围/期限的下载授权；要求即时撤权的来源必须走每次读取复核的代理，不能同时承诺离线长效下载 URL 和即时失效。
任务/产物列表、全文搜索、聚合计数与导出都应用相同可见性规则，不能只保护详情页面。

## 16. 分阶段交付范围与上线条件

每阶段交付可运行切片和支持矩阵，不先开发全部后台页面；阶段编号是 Jorice 提案内的交付视图，不改动既有 Phase/任务登记。

| 阶段 | 可交付能力 | 必须具备的证据 | 不得宣称已交付 |
|---|---|---|---|
| S0 合同与等价基线 | 配置覆盖盘点、公开 descriptor/Bundle/脚本合同、认证/环境边界、当前行为到基线定义映射 | 字段归属/来源/生效时机、规范摘要稳定、未知字段/版本拒绝；v1 行为兼容 | 任意配置都已动态装配、平台生产可用 |
| S1 单产品纵向试点 | 真实 BFF 登录、页面上下文、一个 tool/context/verifier 原生包、审批/待办、独立部署与运行证据 | 授权读写、真实收据、刷新/断线/接管、部分结果、无 mock；业务 owner 确认用例 | 全 Runtime 配置完成、通用 OAuth/所有 Plugin、生产 fleet |
| S2 首个生产产品 | 所用配置域、生产身份/凭据、Plugin 生命周期、版本/环境发布、配额/告警、备份恢复、停用退出 | B01–B14 中适用项；发布/回退/故障/撤销/数据保留实证，未启用项明确禁用 | 未实现的持久索引、Webhook、灰度或多引擎 |
| S3 平台完整目标 | 两个不同产品独立版本/资源，配置矩阵全部域有有效实现/替换路径，模板与包真实复用 | 逐项配置覆盖、产品 A/B 隔离、不同 Runtime 组合与独立升级，全部目标配置域验收 | 未验收的具体第三方引擎、语言或存储适配器 |

生产产品的运行定义必须是完整 Bundle，所有域都有精确值/实现；阶段内未开放编辑的域允许显式固定默认组件，不允许悄悄回读进程 Settings。
S1 是有条件试点：没有完成生产门禁时只在授权测试环境运行，原型接口不能承担未验收的生产写入。
S2 的产品限定交付不等于平台全量目标完成；S3 允许组件/镜像式配置，不要求所有行为都能通过表单或普通业务脚本改写。
多个第三方 Provider/协议每个有自己的支持记录；“支持 OAuth”只对应已验收的 Provider/合同，不能推断所有第三方服务互通。

### 16.1 上线阻断条件

- 身份无法落到稳定主体/工作区、权限上限不可核验，或产品/环境映射歧义。
- 必需原生能力、包/镜像摘要、模型必需能力、客户端合同、Secret 或目标执行版本不匹配。
- 业务写无法满足幂等/对账和审批要求，测试仍会意外访问生产资源，或必要安全状态过期。
- 使用的内容来源不能落实 ACL/保留/删除合同，或产物发布无法提供所需完成证据。
- 使用的运维功能没有恢复/退出路径，或新旧数据库/Worker 版本不兼容却计划直接切换。

不通过的项显示负责人、影响范围和可执行下一步；例外只能在不破坏强制安全/事实合同的试点范围内收紧能力，不能点击“忽略”进入生产。
successor/定时/持久索引等未启用能力可标为不适用，但必须有目标拒绝证据；产品 A/B 隔离、核心授权、恢复及真实业务收据不能以不适用跳过。

## 17. 端到端示例：业务 UI 中审阅并更新一条业务记录

以下使用虚构产品和对象说明，不代表当前已实现或已对真实数据执行；输入合同/角色/接口名称在该产品接入时固定。

1. 产品管理员从“业务记录助手”模板派生独立 Runtime，绑定测试 Host、模型、Frontend Profile 和受限数据范围。
2. 开发者发布查询/更新 Tool、页面摘要 Context、结果回读 Verifier 三类组件；包可以复用，业务 endpoint/凭据不写进包。
3. Jorice 构建环境 Bundle；目标验证包/权限/连接/SDK 后激活精确 AgentRelease。UI 显示已生效版本及验证范围。
4. 用户在业务记录详情页登录；BFF 核验当前成员与该记录权限，打开 conversation；Readable 提供当前对象 ID、版本和获准摘要。
5. 用户请求“将负责人调整为某成员”；Agent 先经 Host 查询当前值和候选成员，输出变更预览并等待确认。
6. 用户确认时 BFF/Runtime 校验当前身份、提案摘要、对象版本和期限；Host 再验证委托与业务规则，以稳定 Effect ID 写入并返回收据。
7. Verifier 按声明范围回读版本/字段，Artifact 记录来源；UI 显示真实结果。回读失败只显示已提交/待验证，不能假称已确认完成。
8. 操作中浏览器断开，业务 Effect 不重复；用户回来按同一绑定看到已完成结果或待处理事项，其他用户无法借同一链接读取。
9. 用户想新增第三方 Plugin：完成独立连接授权并选包；支持 successor 时走 held/CAS/激活交接，否则明确结束旧 Task 后新建。
10. 产品升级/停用时，旧任务版本、计划 pin、授权新鲜度与共享资源按既定流程处理；不以模板更新直接覆盖线上。

如果对象在确认前变化，旧提案冲突失效；如果写入响应丢失，先用 Effect/业务收据查询；如果用户失去权限，停止后续读取/写入及受限产物交付。
该切片同时验证 native package、全定义冻结、业务同用户认证、前端协作、审批、业务收据和恢复，不需要先建第二个引擎或通用低代码编辑器。

## 18. 交付包、需求追踪与配置覆盖验收

每个产品环境交付一个可审计的接入记录和引用清单；下表是逻辑交付项，复用已有对象/存储，不要求新建一套表或微服务。

| 交付项 | 必须固定或记录的内容 |
|---|---|
| 接入说明与支持矩阵 | §13 信息、责任人、上线范围、不支持能力、依赖、接入步骤和业务验收样例 |
| 配置与组件锁定 | 模板/Runtime/Agent/Bundle、组件/镜像/依赖摘要、公开合同版本及覆盖盘点 |
| 环境与信任绑定 | product/environment/deployment、真实 scope、BFF/Host/Client Profile、Trust revision、Secret 槽引用；不含明文秘密 |
| 验证与发布证据 | 构建/评测/授权负例/真实业务/浏览器/故障测试记录，目标就绪与 Release 确认、适用范围和失效条件 |
| 运行与处置说明 | 结果/待办入口、告警责任、unknown 对账、授权续期、排空/回退/恢复及停用退出步骤 |
| 导出与交接清单 | 不可变包引用、配置来源/授权、允许导出的元数据与内容、保留/删除/共享引用结果 |

导出默认排除 Secret、Token、业务登录会话和执行授权；导入另一环境/产品重新登记信任并逐项重新绑定连接、scope 和数据范围，不自动恢复生产端点可用状态。
只导入声明和包不复制 Task 活动租约、Controller、待审批授权或已提交写入；执行库迁移需走单独的停写/校验/恢复流程。

### 18.1 配置覆盖记录的最小字段

每个配置项至少记录稳定 ID/schema 路径、含义/类型、默认来源、归属、支持引擎/组件、允许覆写层、权限上限、Secret 敏感度、生效边界、对应验证和 UI/结构化编辑入口。
状态必须区分：已盘点但未实现、固定可运行默认、可配置参数、可替换组件/镜像、不适用或不支持；后两者不能作为“全量目标已完成”的通用豁免。
新增/改变 Settings 或行为选择点时，配置覆盖记录与公开 schema 同步更新；不将旧完整性声明永久沿用。
全量验收除字段检查外还需行为证明：换组件/参数实际影响运行、Task 快照固定、恢复不读最新配置、权限不扩大、旧版本保持可恢复。

### 18.2 需求→实现→证据的追踪关系

| 需求 | 对应工作包/合同 | 最低验收范围 |
|---|---|---|
| Runtime 全量配置 | A/B 与全部配置域、目标 schema/Bundle/claim | 配置覆盖 + 实际组合/替换 + 恢复/版本拒绝 |
| 脚本式业务原生能力 | C、Native Package/SDK/runner | tool/context/verifier 首片，再逐类启用 step/hook 等 |
| 附加能力与 Plugin | D/P、H3/H4、P1–P3 | 安装/认证/精确选择/升级/禁用/撤销/卸载/引用 |
| 同用户业务嵌入 | H2E/J1、Host/Client/BFF 合同 | B01–B03、B05–B07 的真实业务权限与交互 |
| 独立部署与低耦合 | E/J5、版本化管理/观测协议 | B09–B10、B12–B14，停 Jorice 不改变有效执行事实 |
| 持续使用与运营 | J2–J6、固定版本/对账/治理 | B04–B08、B11–B14；启用项全部证明，未启用项拒绝 |

具体代码任务在对应合同与阶段范围批准后再登记 Ready/Owner/Owned paths；本轮没有认领源码任务、创建实现分支或提交代码。

原 B1 的真实问题是：首批宽查询没有命中正确版本事件公告，随后存在产品页绕路、
相近查询与公告＋文档的前瞻重叠补证。证据充足后的停止本身正常；当前没有发现
能通过一次 SQL 去重、缓存或连接复用改动消除这些语义选择的生产缺陷。

剩余最值得解决的是**首轮事件来源召回与模型的证据缺口选择**；不能把尚未验证
的新来源能力或模型路由包装成一个已完成的通用小修。继续在既有输入上改提示词、
增加事实账本或硬拦 URL，当前没有收益依据。不建议以重构方式继续扩大实现范围。

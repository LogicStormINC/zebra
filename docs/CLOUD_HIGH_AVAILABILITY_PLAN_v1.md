## 1. 决策与范围

值得做系统性 HA 加固，复用现有持久事件、fencing、原收据、排空和恢复机制。
保持 Python Runtime、DDD 分层和业务无关边界；不为 HA 重写 Go Runtime、拆微服务、
引入第二套执行队列或新建通用“高可用领域”。先单区域多故障域，再按实际需求评估跨区域。

HA 的目标是故障期间安全接收、有限降级、可证明接管和恢复；不承诺外部模型/业务系统永不失败。
高并发、低延迟、依赖可用性和执行正确性分别度量，不能互相替代。

## 3. 可复用能力及需要补齐的边界

| 能力 | 复用位置/现状（S，另注 H） | 补齐与验收方向 |
| --- | --- | --- |
| 执行事实与回放 | agent-core 事件/快照；agent-storage 持久事件与任务投影 | 丢连接、跨副本读取仍回到同一 Task/Run；不把回放变为重新执行 |
| 原操作与 CAS | 已有原意图、幂等收据、当前授权/CAS | 断在提交前后时只读原操作；404/超时不推断未提交 |
| 租约 fencing | postgres/leases.py：数据库时间、epoch/token/owner 校验 | 杀 Worker、旧 Worker 复活与网络分区的联合证据；识别不能被本地 fence 撤回的外部请求 |
| 数据库预算 | postgres/connection_pool.py：池1–8、等待上限32、超时2s；task_io.py 独立预算 | 核对各组合根/子进程是否覆盖，计算全副本总连接，连接切换后安全恢复 |
| Worker 并发与退出 | command_process.py 有界执行/维护及真实 drain；旧循环仍在 | 固定 cutover/开关；查 blocked candidate、异常与恢复扫描是否空转或饥饿 |
| 强停与精确清理 | 候选97463d00a的CLOUD_FORCE_STOP_20261030.md；H：99通过/2条件跳过；尚未合入本次主线 | 纳入实际部署组合与跨副本演练；未证明退出时保持 requires_reconciliation |
| 发布与门禁 | Runtime Gate、P5 原意图/排空/回退及固定镜像合同 | 接入实际就绪/退出；升级与回退不能令旧任务快照或旧协议漂移 |
| 部署 | deploy/helm/zebra-agent：API/Worker各2副本、PDB、资源限制 | 跨节点/故障域、Worker探针、排空预算；不能只靠副本数/PDB判定 HA |
| API 健康 | api_status_mixin.py health() 固定200/ok；Helm三种探针共用/health | 分离存活、启动与就绪；关键依赖不可用时撤流，避免依赖故障触发重启风暴 |
| 定时调度 | apps/scheduler：持久触发/领取与信号退出 | 复用幂等领取；核对多实例接管/租约，补实际部署与故障验收，不新造调度器 |
| 流式/前端恢复 | 持久事件与已有 SDK/BFF 原GET/映射恢复合同 | SSE断线、换API副本、游标缺口；恢复观测不得新建Run或重领Controller |
| 外部依赖 | PostgreSQL、Redis、对象存储、Broker/身份/密钥服务 | 当前生产冗余未知；按路径声明关键/可降级依赖，验证失效与恢复 |
| 资源治理 | 配额/执行器/清理基础；近期临时环境曾并行遗留 | 单一重型验收环境、租户技术限额、owner清单、失败/中断回收与泄漏告警 |

旧 Worker 循环仅在无 ready candidates 时休眠的路径是静态风险线索，尚未证明当前 Cloud
启用路径存在同一故障；必须核实 scan_ready_sessions/cutover，不直接按旧路径改新循环。
Helm 的 worker-id 当前按 release 名传入：核查与实际 owner_instance_id 的关系，不据此
直接断言 fencing 失效。原样已有能力不得被“重新实现”覆盖。

## 4. DDD 归属与不变量

| 归属 | 负责 | 不允许 |
| --- | --- | --- |
| agent-core 现有执行/任务模型与 Ports | 明确准入、租约失效、执行/终止事实及恢复用例的不变量 | 导入 Kubernetes、Docker、连接池或业务产品逻辑 |
| agent-storage | 原子持久化、fence/CAS、原收据、连接与数据库预算 | 用内存状态、Redis通知或状态文本替代权威事实 |
| agent-runtime / 工具适配器 | 受限执行器、沙箱身份、外部调用、退出与精确清理证明 | 杀共享Worker、越权清理其他任务或假报资源释放 |
| apps/api、worker、scheduler | HTTP/进程入口、依赖组合、探针、信号和有界调度 | 复制领域状态机或在HTTP层决定业务效果是否可重做 |
| agent-observability 与 deploy | 技术指标、部署拓扑、告警、容量与运维证据 | 赋予业务权限或把平台指标当作Coverage完成证据 |
| Overdoze / 业务BFF | 配置、发布编排、同源认证、原意图与公开合同消费 | 直写Runtime表、持有Worker状态、浏览器留长期凭据或替Runtime签执行收据 |

核心不变量：

1. Task/Run/段、快照、原操作ID和历史Coverage定位保持；不得通过新Run制造恢复成功。
2. Worker拥有的执行提交只允许当前有效fence；API准入/控制保留其当前授权、原事务和CAS；
   失去执行租约即停止新派发。已在途外部效果
   是否提交仍由其原收据决定，不能声称全局 exactly-once。
3. unknown 不自动重发、不自动重领Controller；只能原GET/授权发现/显式人工处置。
   未观察到原收据不是非提交证明；技术GET重连与业务POST重放必须区别。
4. 准入提交、执行结果、终止证明、资源释放和Coverage各有独立证据，不互相替代。
5. 身份/撤销/权限仍做当前检查；身份服务故障不得延长已过期授权或绕过门禁。
6. 所有兼容性变更先合同后代码；默认旧数据/旧任务/旧协议可读，启用新写入需明确门禁。

## 5. 目标拓扑与关键策略

目标：负载均衡 → 跨节点API副本；独立Worker副本与受限执行器；可多实例的现有Scheduler。
PostgreSQL为执行权威，配置受管理主备、故障切换和独立备份；对象存储覆盖实际故障域。
Redis角色逐路径确认：若仅用于唤醒/流提示，可由持久事实补读降级；若路径确有强依赖，
必须明确拒绝/排队边界，不能笼统宣称Redis故障不影响执行。Broker/密钥服务同样单列。

- readiness：检查服务该路径所需的配置/版本/关键依赖及容量，以有界缓存和短超时探测；
  不每次探针加载全历史、运行模型或创建沙箱。资源耗尽时拒绝新准入而非静默丢任务。
- liveness：证明进程控制路径可响应，不把共享数据库/外部服务短暂失败当进程死亡。
- Worker就绪/存活与调度能力分别观测；Pod健康不等于某个Task能合法恢复。
- 排空：先停止新领取/准入，撤流，完成有界在途工作/持久交接；到预算后以明确中断或
  unknown 交接，不用Future取消充当进程退出证明，不对整个共享Worker粗暴强停。
- 资源：按副本/执行器数计算总连接和内存；给恢复扫描独立预算，控制查询/通知放大。
  被阻塞候选需退避/抖动；任何自动弹性都不得扩大技术权限或突破存储总预算。
- 存储：主备切换后重建失效连接、重新确认数据库时间/epoch/fence；不盲重试未知提交。
  对象内容/索引/证据一致性、工作区可恢复性与节点本地临时文件分别验收。
- 备份不是故障切换：须独立恢复演练；恢复后隔离写入、核对epoch与收据，防止旧执行者
  对新权威继续写入。跨系统灾难恢复不承诺自动重放未知外部效果。

## 6. 候选 SLO 与测量合同

下表是首版设计目标，不是现有实测或对外SLA。HA-01须固定故障模型、流量包络、采样点、
统计脚本与依赖预算，评审后才能成为后续门禁；不能靠删除失败样本达到目标。

| 指标 | 候选目标与边界 |
| --- | --- |
| 控制面可用性 | 滚动30日≥99.9%；覆盖合法准入和原收据查询；不等于模型回答成功率 |
| 故障模型 | 首轮覆盖单API/Worker进程、单计算节点丢失、短时依赖故障；整AZ目标须存储/Broker等配套后单独验 |
| API故障恢复 | 在固定负载包络下单副本/单节点故障后≤60s恢复可服务，不放宽授权 |
| Worker可接管 | 故障注入后≤120s内合法任务获得新有效执行权或进入有理由的阻塞/对账状态；不是任务完成时限 |
| 依赖故障 | 在预算内返回明确不可用/已接收/unknown；不得无限阻塞或丢弃已提交任务 |
| 效果正确性 | 故障样本无未经原操作确认的重复业务派发；不以“未发现日志”作为无重复证明 |
| 数据持久性 | 承诺范围内已确认准入/收据RPO=0须先验证同步持久策略及故障切换，异步主备不得冒用该承诺 |
| 灾难恢复 | 单独确定备份RPO/RTO并以恢复实测验收；首轮不虚设跨区域零丢失承诺 |
| 性能与资源 | 固定并发Task/流连接、事件大小、数据库容量和副本数；记录p95/p99、池等待、队列年龄、CPU/内存与资源泄漏 |

HTTP可用性样本包含服务错误、超时及服务端过载拒绝；调用者非法输入/无权限单独统计。
在途请求的unknown不是业务成功。可接管统计须把执行恢复与因凭据过期等安全阻塞分开，
单列等待人工/原收据的积压及年龄；不得把所有阻塞样本记为接管成功。
外部模型延迟/拒绝、Host业务错误独立记录，平台对这些错误的处置仍计入正确性验收。

## 7. 分阶段交付与统一验收

顺序为基线/合同 → 稳定性 → 接管与依赖容错 → 发布/容量/联合证明。
详见任务清单；每项必须先追踪所有调用者及现有 helper，采用最小可复用修复。

每次交付都必须：

- 固定commit、镜像digest、合同/配置/迁移版本、开关、拓扑及故障域，证据不含密钥。
- 保留历史Task/Run、旧快照、原收据和Coverage；记录迁移前后计数/摘要与兼容读取证明。
- 收集故障前/注入时/恢复后原操作状态、lease/fence、事件顺序、外部效果账和资源清单。
- 涉及数据库/多进程时以真实隔离环境验收；单测、mock、SQL推导或/health不能替代联合证据。
- make test / make check 需按候选完整执行；遗留违规须定位基线并登记阻塞，不能绕过后宣称全绿。
  当前基线文档记载ERP目录尺寸门禁遗留失败；本轮未重跑，也不宣称完整门禁通过。
- 回退采用兼容读、关闭新写入/准入、排空和固定旧镜像；不回删历史数据/收据或降级抹除新事实。

## 8. 运维、资源与实施边界

验收环境必须有唯一owner/run清单，包含容器/卷/网络/子进程/镜像挂载。
同时至多一套重型本地验收；跨仓库全量验证串行执行，不自动重复中断测试。
正常、失败、SIGTERM及会话中断均先停生产者/监督进程，再回收可重建且无使用者的资源。
证据保留不等于保持Worker/数据库轮询；需保留数据的环境应停机并登记保留理由与处置计划。
禁止全局prune、删除unknown依据或业务卷。清理完成应复查无遗留运行进程和资源。

观测至少覆盖：准入错误/延迟、原GET失败、队列年龄、租约失效/接管、旧fence拒绝、
恢复积压、unknown年龄、排空耗时、执行器退出/清理积压、池等待、存储故障和节点资源。
日志保留关联ID和技术坐标，禁止令牌/身份私密信息及无限业务载荷。

生产部署/迁移/故障注入需另行授权；本方案没有恢复此前暂停的重型任务。
平台设计通过、隔离联合验收通过、生产演练通过和持续SLO达标必须分别报告。

| 用户路径 | 必须补齐的验收目标（参考环境内） | 对应任务 |
| --- | --- | --- |
| 首响应 | 本地提交反馈p99≤200ms但只称“正在提交”；核对原收据后的确认p99≤3s，服务端准入仍≤2s | 07/09，UX-01 |

| 首内容与流式 | 短依赖场景T4至首内容p99≤2s；已有持久事件至实际呈现p99≤500ms；模型TTFT另列；合法断流补齐≤5s | 07/09，UX-03、UX-07 |
| 卡死识别 | 无实质进展60s后≤5s形成疑似停滞观测；不以keepalive/重复token当进展，不对合法长任务统一强杀 | 03/07/09，UX-04 |
| 多用户隔离 | 固定总负载1/16/32个scope分桶，低负载用户仍守排队目标；挂起任务不得阻塞其他scope/查询/停止 | 03/04/09，UX-05 |
| 停止回收 | 控制准入p99≤2s；依赖可用且隔离授权已具备时退出≤10s、完整回收≤30s；未知不假报成功 | 04/09，UX-06 |
| 容量保障 | 所有连接/线程/队列/执行器/SSE缓冲有硬上限；包络外有界拒绝、未知原GET；不靠无限排队 | 03/08/09，UX-08 |
| 长历史/持续使用 | 固定页/显示窗口≤100；原GET p99≤1s、界面交互p99≤200ms；24h资源曲线与中断退出清单验收 | 07/09/10，UX-09、UX-10 |

具体计时点、分母、错误样本、E1-C混合scope、E1-O分档、依赖fixture和证据要求以合同7节为准。
E1-A短任务、E1-R恢复、多用户E1-C及超载E1-O分别验收，不拼接成未经证明的更大容量。
并发在线、SSE、排队任务与执行槽不是同一指标。扩容结合队列年龄、可用槽和存储/供应商
预算，增加Pod不能绕过上游限额或解除单任务死锁。模型/工具替身不替代真实业务正确性。

已存在的公平领取、有界lane、读取预算和safety net优先复用；必须核对实际cutover与
影子模式，不能把“有代码/有日志”当防卡死已生效。请求超时不等于后台线程/进程停止，
下层I/O、控制预算、执行器隔离及退出证明分别落实。强停未合入仍是04独立依赖。
凭据留BFF；旧数据/原收据/unknown/Coverage保持，任何性能优化不得以删历史/缩减证明换取。
真实SDK/BFF/Host UI需先独立登记消费者合同/路径，当前不修改前端mock或任一业务代码。

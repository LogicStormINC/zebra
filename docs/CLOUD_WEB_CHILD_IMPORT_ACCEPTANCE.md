## 根因与最小改动

每次原生search/fetch均exec一个新的Python子进程。仅导入Web transport时，
agent_runtime、agent_core、agent_core.domain、agent_core.ports四个包入口
却提前加载公共聚合导出，连带Harness、应用服务和存储适配器。旧进程加载1241模块，
导入约0.9秒；这不是Worker启动后只付一次的成本。

只改四个包的入口：原导出实现逐字移至各包_public_exports.py，入口保留原__all__，
TYPE_CHECKING静态导出，并以标准模块__getattr__在首次访问公开名称时加载原聚合。
__dir__仍列出公开名称；未知名称抛AttributeError，使from包导入子模块继续使用
Python原有规则。读取公开名称后缓存该对象，身份与原定义模块保持一致。

47+244+143+71，共505个既有公开导出均保留。没有变动领域模型、Port、工具/网络
执行逻辑、数据库、依赖或进程生命周期。不增加持久子进程、全局连接池、授权缓存。
仍每次新进程、新鲜DNS/TLS/权限与50ms取消检查；原总截止/kill/reap、SSRF/证书、
gzip双cap、两路并行、v2/high及按需沙箱行为不变。

有意简化：访问任一包级公开名称仍加载原来的整个聚合，不逐符号制作大型映射。
需要单个功能的热路径继续使用显式子模块导入；聚合入口消费者首访问成本仍在。
公开名称列表在入口与原导出模块一致，由新回归检查，未来扩展时须同步更新。
原导出代码四文件均与基线逐字一致，新增入口均低于200行，最大原导出模块401行。

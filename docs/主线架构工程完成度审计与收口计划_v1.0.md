## 5. 已完成且必须保持的基础

1. Event Store 和投影是持久事实源，前端状态不是权威。
2. Harness/Worker 不依赖不可恢复的进程内状态。
3. `agent-core` 保持基础设施无关，其他包通过 Ports 组合。
4. 模型输出不能绕过 Typed Tool、Policy、HITL、Runtime 和审计。
5. Runtime 生产模式必须 fail closed，而不是退回 trusted-local。
6. Context Capsule 和 Session Handoff 不传递私有 reasoning、凭证或原始大输出。
7. API、CLI、Worker 和 Desktop 复用持久状态及稳定契约。
8. `make test`、`make check` 和 CI 门禁不得为合并方便而弱化。

## 6. 当前主要缺口

### P1：发布与产品验收

- 缺少覆盖真实浏览器的新任务、续问、停止、恢复、审批、长流式和 Handoff E2E。
- CI 构建 Web 资产，但没有完整的 Tauri 打包发布门禁。
- 缺少升级迁移、备份恢复、容量、长时间运行和故障注入证据。

### P1：DeepSeek thinking tool loop 边界

Issue `#148` 仍为 Open。当前稳定 Profile 通过工具轮显式 non-thinking
规避协议问题；在启用 thinking tool loop 前，必须实现并测试 provider-private
`reasoning_content` 的最小必要回传，或正式关闭该能力。

### P2：Desktop 性能与体验

- 主 chunk 已约 `1.47 MB`，需先产出可重复 bundle 报告，再按重依赖边界拆分。
- 确定性检查不能替代真实浏览器、键盘、无障碍、缩放和低性能设备验收。

### P2：单机生产运维

- Workspace 磁盘硬配额依赖生产存储层，不能由普通 bind mount 伪造。
- Snapshot 恢复是新 Sandbox 重建，不是进程内存 checkpoint。
- 仍需明确日志、Artifact、SQLite、容器和 Snapshot 的保留、备份与清理策略。

### P3：私有云与多租户

以下能力尚未进入当前实现目标：

- PostgreSQL Event Store 和对象存储；
- 多 Worker 分布式调度与跨节点恢复；
- Credential/Egress Broker 和 Vault/KMS；
- Tenant Isolation、RBAC、组织 Policy、配额和成本；
- Kubernetes、Kata/Firecracker、Warm Pool 和灾难恢复；
- ACP、代码智能和生态市场。

## 1. 产品摘要

Jorice 是面向多产品的 Agent Runtime 配置、开发、接入、发布与治理平台。
开发者在后台组合运行组件和业务原生脚本，为产品交付独立版本、独立资源和独立生命周期的 Agent；终端用户在业务 UI 内沿用原登录和权限使用 Agent。
cloud-agent 是首个受管执行引擎；Jorice 独立部署，不进入每次模型、工具或 UI 动作的同步执行路径。

核心用户要求：**“runtime 的所有内容都应该是可配置的。”**
“配置”包括参数、版本化业务脚本、可信组件选择和完整引擎镜像选择；产品安全上限、执行事实和调用者权限不可由普通脚本扩大。

## 2. 背景、问题与产品边界

### 2.1 要解决的问题

- 新产品接入涉及模型、上下文、业务能力、权限、前端、凭据和部署，缺少一条可追踪的交付流程。
- 仅配置提示词/模型无法定义产品 Agent；业务能力需要脚本与组件，产品还需要独立升级和回退。
- Agent 嵌入业务 UI 后必须识别当前用户、工作区、页面和对象，准确调用已注册 Hook，不能另建用户体系或共享万能前端密钥。
- 已有能力、已安装 Plugin、认证就绪、任务可调用和真实执行成功容易混淆，失败后的恢复与退出也需要明确入口。

### 2.2 各系统负责什么

| 系统 | 产品责任 |
|---|---|
| 业务系统 | 用户/组织/成员关系、业务权限与数据、业务 API、原有登录、前端页面、业务订阅和计费 |
| Jorice | 技术产品/环境目录、模板/组件/脚本意图、接入配置、构建评测、部署编排、授权管理与受权观测 |
| 产品 Runtime | 目标生效版本、任务、事件、业务/UI Effect、租约、产物、执行授权和恢复事实 |

Jorice 删除目录不直接删产品数据；目录中显示的线上版本必须来自目标确认，不新建第二个执行生效权威。
本 PRD 延续当前四份 Jorice 设计；历史 Zebra 中台 PRD 仅作页面参考，不沿用其旧名称、旧实施比例或已过时的实现判断。

## 3. 目标与成功标准

### 3.1 产品目标

1. 一个产品从登记、能力开发、认证、前端接入到发布和退出有完整流程，任何阻断都能找到负责人和下一步。
2. Runtime 每个运行域都能被明确声明和版本化；恢复不读取草稿或 latest，模板升级不直接覆盖产品。
3. 业务原生能力和附加能力可复用，产品版本、数据、身份、资源与升级互不混用。
4. 业务用户登录一次，Agent 在同一权限下读取/操作业务，并能在页面中完成澄清、审批、UI 动作和长任务恢复。

### 3.2 验收指标与度量

以下是目标和测量口径，不是当前成绩；S1 建立效率/性能基线，再决定服务级别数值，不凭文档承诺接入天数或时延。

| 指标 | 目标/阶段 | 测量方式 |
|---|---|---|
| 首产品闭环 | S1：至少 1 个获授权真实测试产品完成配置→发布→业务操作→恢复 | 同一接入记录关联构建、目标版本、浏览器、业务收据及故障证据 |
| 配置覆盖 | S3：本 PRD 全部运行域可配置/可替换并有行为验证 | 已验证配置项/已盘点配置项；固定默认单列，不能计作最终可配置完成 |
| 执行可追溯 | 经 Jorice 交付的新发布/新任务均关联精确版本、组件和授权来源 | 版本/Bundle/Task/Effect/审计对账；不得存在无法解释的隐式版本 |
| 隔离与安全 | 所有规定负例均拒绝越权；不得产生额外业务写入 | 跨用户/产品/环境、旧 fence、重复消息、过期确认等固定用例 |
| 可复用独立交付 | S3：至少 2 个产品复用一项模板或能力，独立组合/升级/停用 | 共享资产引用、独立部署与 A/B 故障/权限验收 |
| 接入及处置效率 | 从 S1 起持续记录，不伪设改善比例 | 登记到首个有效运行耗时、人工步骤、首次失败原因、恢复耗时与工单分类 |

## 4. 用户分群、价值与角色

### 4.1 用户分群与工作目标

| 分群（Who） | 要完成的工作/困难（Why） | 当前可用方式（Before） | Jorice 提供（How） | 目标结果（After） | 可选替代方式 |
|---|---|---|---|---|---|
| 业务集成开发者 | 将 Agent 接入已有产品，适配业务与 UI | 组合现有接口/配置、维护产品专用集成代码 | 模板、脚本包、认证 adapter、npm/Hook/Key 向导、接入测试 | 接入步骤和能力边界可重复、可验证 | 继续手动集成或复制产品实现 |
| 产品/平台交付与运维人员 | 管理不同产品的版本、权限和运行异常 | 分别管理部署、凭据、日志和发布记录 | 环境配置、门禁、独立部署、Plugin、运行/审计与退出操作 | 知道什么已生效、哪里失败、怎样安全恢复 | 现有运维脚本与各产品控制台 |
| 业务终端用户 | 在当前页面完成查询/处理，必要时确认并稍后继续 | 手工操作产品功能，或使用独立聊天入口 | 同登录 Agent、页面上下文、受控 UI 操作、审批/待办/结果入口 | 不离开业务权限边界即可完成受支持的工作 | 继续手工完成业务操作 |

价值主张：Jorice 让集成团队复用受控能力和交付流程，让运营团队确认真实状态，让业务用户在原产品中安全地使用 Agent。
平台提供可复用的接入方式；业务目标、业务 API 与权限事实仍由产品团队定义，不宣称零业务开发。

### 4.2 角色与默认权限

| 角色 | 默认允许 | 默认不包含 |
|---|---|---|
| 平台安全管理员 | IdP/信任、发布者策略、密钥/撤销、应急停用 | 自动读取全部业务内容/Secret |
| 产品管理员 | 获授权产品/环境、接入、角色、允许能力和资源上限 | 其他产品管理权或超自身权限授予 |
| 集成开发者 | 开发环境 Runtime/脚本/Profile、受控测试 | 生产发布、全局可信源管理 |
| 发布者 | 指定产品环境的精确版本发布 | 修改测试结果、跳过授权/完整性门禁 |
| 运维人员 | 授权目标的观测、排空、部署/回退/恢复 | 凭据明文、任意业务写入 |
| 审计/观察者 | 授权范围内脱敏记录 | 默认读取业务正文或执行操作 |
| 业务用户 | 业务权限内使用 Agent、处理自己的任务/待办/连接 | Jorice 管理权、其他用户/工作区数据 |

一个人可有多个获准角色；按钮可见性与服务端权限都要检查，服务账号沿用资源/动作范围。业务审批角色可以另行配置，但批准不扩大任务或业务用户权限。

## 5. 功能范围与分期

### 5.1 交付阶段

| 阶段 | 交付重点 | 阶段出口 |
|---|---|---|
| S0 合同与等价基线 | 配置盘点、公开合同、认证/权限边界、当前行为映射 | 配置/对象/版本可解释，旧合同兼容，不宣称后台已可用 |
| S1 单产品纵向试点 | 一个真实测试产品、原生 tool/context/verifier、登录、前端 Hook、审批、部署和恢复 | 一个业务任务真实走通；完整 Bundle，其他域可显式固定默认；仅测试范围 |
| S2 首个生产产品 | 所用配置、生产凭据/身份、Plugin 生命周期、发布/回退、预算/告警、备份及退出 | 所用能力全部达到生产门禁；未启用能力目标明确拒绝 |
| S3 平台完整目标 | 全运行域配置/替换、两产品独立组合/生命周期、资产复用 | 配置行为覆盖与多产品隔离通过，不把固定默认当作最终完成 |

后续具体引擎/语言/Provider/存储按适配器逐项验收。首个实现选择 cloud-agent、Python、Compose、内部受信开发者和 Catalog，React 为首个前端 SDK。
定时、会话中能力切换、持久知识索引按产品启用；启用前满足各自验收，关闭时有明确拒绝，不能用不适用跳过核心身份/隔离/事实/恢复门禁。

### 5.2 不在首版范围

公共 Marketplace、商业套餐/计费/发票、完整 CRM/电商/工单系统、通用低代码编排、任意 DOM/JS 控制、移动管理后台、多地区多活、多主 Agent 自动路由、跨引擎透明迁移。
不为每个业务复制 Runtime 源码，也不要求业务改用 Jorice 的用户中心；S1/S2 不等于全 Runtime 配置目标完成。

## 6. 信息架构与产品界面

### 6.1 管理后台导航

```text
全局：产品目录｜业务模板｜能力资产/可信 Catalog｜身份与信任｜平台审计
产品工作区（固定显示产品 + 环境）：
  总览/接入检查清单
  Runtime：定义编辑｜原生能力｜模型/内容/策略配置
  接入：业务认证/Host｜前端应用/Key/Hook｜连接与凭据
  附加能力：Catalog｜安装与配置｜版本/撤销
  交付：构建/评测｜发布记录｜部署实例/回退
  运行：任务｜客户端/待办｜可选计划｜用量/告警｜审计
  设置：角色/上限｜备份/恢复｜停用/交接/退出
```

全局资产复用不代表共享执行权限；跨产品复制明确显示将保留什么和必须重新绑定什么。
任务详情默认展示业务进度/结果与处置；版本摘要、协议、fence 等技术字段放诊断层，不迫使普通用户填写。
产品/环境切换关闭旧流并清理缓存；未保存草稿提供保存/放弃/取消切换，服务端仍检查原请求 scope。

### 6.2 业务内 Agent 界面

侧边栏或业务方布局嵌入：会话列表/新建、消息与进度、输入/附件、可用能力、当前页面关联、澄清/审批卡、任务/待办、结果/产物。
显示“控制此页面/观察模式/等待页面连接”，并提供获权可用的接管、重连和返回任务入口。
业务会话可包含多个历史 Task；UI 解释能力切换和新任务交接，不让用户处理内部 Task/Run ID。
基础组件复用现有 SDK；Jorice 管理后台与业务终端界面是两种用户入口，共同纳入本需求。

## 7. 功能需求

### 7.1 功能清单

各需求启用时必须完整交付，不以页面存在替代真实服务。阶段列表示首个要求阶段，后续继续完善。

| ID | 需求/主要操作 | 必须体现的业务规则 | 阶段/交互 |
|---|---|---|---|
| FR-01 | 管理登录、退出、产品/环境权限绑定与撤销 | 外部 IdP；无权拒绝，生产/信任等敏感操作执行 Policy，管理身份不自动取得业务数据权 | S1／UX-01 |
| FR-02 | 产品/环境创建、模板创建/版本发布/派生、接入清单 | 技术产品与真实 Host/scope 映射；模板固定版本，环境秘密不复制；查看完成项/阻断/负责人 | S1／UX-02 |
| FR-03 | 全量 Runtime 编辑/校验/差异 | 最终值、来源、上限、生效时机；表单与结构化编辑一致，未知/不支持项拒绝发布 | S1→S3／UX-03 |
| FR-04 | 原生能力脚本编辑、Git/包导入、构建/调试 | 版本化 package，Tool/Context/Verifier 首片；Step/Planner/Hook 等逐类解锁，隔离执行，依赖锁定 | S1→S3／UX-04 |
| FR-05 | 模型/Provider/角色与可信运行组件选择 | 能力/区域/数据策略、参数、连接引用；只有已配置且兼容的 fallback 可用，不静默换模型 | S1→S3／UX-03 |
| FR-06 | 业务认证/Host/BFF 接入与信任管理 | 服务身份 + 同业务用户委托；登录一次，工作区/ACL/退出可验证；目标登记/轮换/撤销 | S1／UX-02、05 |
| FR-07 | 前端应用、公开 Key、npm/Hook 向导 | Key 定位应用/环境，不独立赋权；Profile/schema、同源 bootstrap、Tab/Task/Controller 精确绑定 | S1／UX-05 |
| FR-08 | Plugin 浏览/安装/配置/启停/升级/回退/卸载 | 安装默认 disabled；信任、认证就绪、选择、调用授权分层；共享来源和引用受保护 | S2／UX-06 |
| FR-09 | 连接/API key/OAuth 授权、刷新、重认证/撤销 | 指定账号/endpoint/scope/环境，Secret 不回显；OAuth 逐 Provider 验收，不用聊天传 Token | S2，S1支持所用连接／UX-06 |
| FR-10 | 校验、构建、评测、环境晋级与版本发布 | 证据绑定最终环境版本包；发布目标确认才生效，旧任务不换版本；结果未知先对账 | S1→S2／UX-07 |
| FR-11 | 独立部署、排空、实例/漂移、回退 | 独立 deployment/数据权限/资源；同部署副本共享权威，Worker 版本匹配；回退不是数据库自动回滚 | S1→S2／UX-07 |
| FR-12 | 业务会话/消息/附件/结果管理 | 当前会话鉴权、消息去重、输入排队或明确拒绝；上传/完成/绑定/下载分别授权 | S1／UX-08 |
| FR-13 | Readable 上下文与 Client Action | 已发布合同且实际挂载；仅当前 Controller，UI 版本/期限校验；正式业务写入走后端 Tool | S1／UX-05、08 |
| FR-14 | 澄清、审批、待办恢复 | 展示对象/参数/影响/期限；修改后重新确认，重复确认幂等，拒绝不执行 | S1／UX-09 |
| FR-15 | 能力/权限变化后的任务交接 | 前驱暂停/写入对账，候选 held，唯一会话 CAS 后激活；原结果不重做，旧绑定失效 | 启用会话切换前／UX-09 |
| FR-16 | 知识/文件/项目上下文/Memory 治理 | 来源/版本/派生/ACL/保留/删除；无治理合同不开持久索引，个人 Memory 不默认共享 | S1受控读取，S2所用治理／UX-10 |
| FR-17 | 长任务、用户任务中心与可选定时 | 显式后台委托、结果/待办入口；定时权限/版本 pin/时区/重叠/漏跑/去重，不支持的 Webhook 明示 | S1长任务，调度按需／UX-11 |
| FR-18 | 用量、预算、队列、故障与运营处置 | 任务及所用跨任务上限、真实部分结果、unknown 对账、受限重试；usage 不等于商业收费 | S1限制，S2运营／UX-12 |
| FR-19 | 运行/管理审计、证据与安全导出 | actor/委托、产品/环境、版本/操作关联；列表/搜索/计数/下载/导出同样鉴权和脱敏 | S1→S2／UX-12 |
| FR-20 | 备份恢复、暂停、解除管理、归档/销毁 | 资源所有者授权，停入口/计划、在途处理、撤销和保留分步确认；产品 A 不影响 B | S2／UX-13 |

### 7.2 Runtime 全量配置的产品范围

编辑器左侧按域导航，域内提供基础字段、组件选择和高级结构化编辑。组件 schema 决定字段，不为每个组件强制开发专用页面。

| 配置域 | 必须可声明/选择的内容 |
|---|---|
| 引擎/协议 | 类型、镜像、公开合同版本、命令/事件和恢复兼容性 |
| 执行循环 | 规划、停止、重试、委派、子 Agent、并发/调度与可信策略 |
| 模型 | Provider/角色路由、参数、窗口、能力、超时、重试与允许 fallback |
| 指令/输出 | 系统/业务指令、语言、模板、结果 schema、输出/发布门禁 |
| 上下文 | 来源、授权、排序/预算、历史、压缩、Capsule、子任务继承 |
| Memory/知识 | 适配器、个人/工作区、检索/写入确认、期限和外部来源 |
| 内容与派生治理 | 格式/大小、解析、来源/版本、ACL 新鲜度、派生、引用、更新/删除/保留 |
| 原生能力 | 必需包、脚本、组件入口、依赖、风险/权限与失败策略 |
| 附加能力 | 允许范围、安装/启停、精确选择、依赖/冲突和撤销 |
| 工具 | 名称、输入/输出、Host/Client/Sandbox 位置、资源绑定、幂等与风险 |
| 生命周期扩展 | 入站、context、plan、pre/post tool、verify、output、stop 的受限执行点 |
| Policy/认证 | 外部身份、业务委托/工作区/资源、审批、信任、凭据引用与上限 |
| Sandbox | 类别、镜像、CPU/内存/PID/磁盘、网络、挂载、超时与生命周期 |
| 存储/恢复 | Event/Effect/Projection/Artifact、检查点、租约、恢复和后端适配 |
| 通信/交付 | HTTP/AG-UI/SSE、命令、重放、结果/产物交付和错误合同 |
| 前端协同 | 应用/环境 Key、Profile/SDK、Readable/Action、挂载、Controller、HITL |
| 触发/后台 | 交互/API、所启用定时、授权模板、去重、漏跑/重叠与后台期限 |
| 技术预算 | token/调用/时长/并发/速率、资源、内容/产物限制与用量证据 |
| 验证/评测 | 样例、完成标准、验证器、质量/发布门槛、证据范围 |
| 观测/部署 | 日志/指标/Trace/脱敏/保留、目标、队列、实例、网络/Secret、备份/升级 |

四种配置方式均须标明：结构化参数、受限业务脚本、可信组件选择、引擎/镜像替换。
每项有类型/默认来源/支持版本/敏感度/允许覆写层/生效时机。配置顺序：固定模板→产品→环境→已解析版本包→任务进一步收紧。
保存草稿、校验、构建、部署、激活分别显示；业务变更形成新版本供新任务，撤销/限制可阻断旧任务后续操作。
S1/S2 完整 Bundle 中未开放编辑的域须显式固定默认实现，禁止恢复时读取 mutable latest 或猜测进程设置；S3 才验收所有域可配置/替换。

## 8. 关键用户旅程与交互约束

### 8.1 总流程

```mermaid
flowchart LR
  A[创建产品/环境] --> B[业务身份与目标登记]
  B --> C[模板/Runtime/原生能力]
  C --> D[连接与附加能力]
  D --> E[前端应用/Key/npm/Hook 配置]
  E --> F[校验/构建]
  F --> G[测试部署/业务与 UI 验收]
  G --> P[生产预检/受限激活验证]
  P --> Q[开放普通业务准入]
  Q --> H[业务 UI 使用/审批/结果]
  H --> I[观测/升级/恢复/退出]
```

后台支持分工并行填写配置，但上线依赖不能跳过；页面显示未完成项，不要求所有用户按固定顺序反复重填。
开发接入测试使用已受控激活的开发验收版本；生产在前置门禁通过后受限验证最终环境版本，再正式开放普通业务准入。目标激活与业务开通分开显示，完整流程见附件 UX-07。

### 8.3 统一交互规则

- 主按钮明确动作：“保存草稿”“校验”“构建版本”“部署并激活”“暂停新任务”；不把全部动作叫“保存/完成”。
- 长操作返回已接受状态与操作详情，可离开后找回；双击/重试幂等。超时显示“结果待确认”，先查原操作。
- 表单保留可恢复输入，字段错误就地显示，跨页错误汇总可定位；Secret 只写不回显，不回填浏览器持久存储。
- 不可用能力解释缺少的合同/连接/授权和下一步；对无权资源遵守防枚举，不泄露其他产品/用户信息。
- 显示空数据、未配置、无权、加载中、离线/陈旧、版本不支持和执行失败；真实连接不可自动回退 mock。
- 生产发布/信任/销毁按 Policy 展示范围与风险确认；不能用前端勾选“已测试”替代可信证据。
- 会话归档、取消任务、删除数据分开；取消不代表外部业务回滚，部分成功不能显示全部完成。

## 9. 核心对象与状态

### 9.1 产品对象

产品/环境、业务类别模板、Runtime 定义/版本包、原生组件包、Agent 版本/Release、目标/部署操作、前端应用/Profile/公开 Key、连接/凭据引用、Plugin 安装、业务会话/任务、交互待办、内容/Memory/Artifact、计划、审计/验证证据。
它们是产品概念，不要求新建相同数量的数据库表/服务；复用现有对象，各系统通过公开合同交互。

### 9.2 状态必须分开

| 状态域 | 展示与约束 |
|---|---|
| 配置草稿/构建 | 未保存、已保存、校验阻断、构建/评测中、通过/失败；通过证据绑定精确输入 |
| 部署/发布 | 准备、验证、部署、就绪、激活、已生效；确定失败或结果未知分开，多 scope 逐项显示 |
| 产品管理 | 可接入、暂停、归档、解除管理、待销毁；暂停须目标本地限制确认，不能只改目录 |
| Plugin/连接 | 包信任、安装/enabled、认证/目录就绪、Task 精确选择分别展示；ready 不等于永久调用权 |
| 客户端 | 未接入、登录/连接中、已挂载、Controller/Observer、失联、需重绑定/不兼容 |
| 任务 | 排队/运行/等待输入或审批/等待认证或页面/暂停/取消处理中/成功/部分成功/失败/取消/待对账 |

任务状态是目标事实的投影；Session.completed 不单独证明业务全成功。所有显示带观察时间，失联不能继续展示为当前确认。
历史 v1/legacy 任务按原合同展示及恢复；缺少 Bundle 等证据时说明历史边界，不补造摘要、不自动迁移成 v2 或扩大授权。
公开 Key 绑定前端应用/环境；Client Session 绑定具体页面实例；Run Binding/控制租约绑定任务动作权，不能共用一把长期前端 Secret。

## 10. 非功能要求

| 类别 | 必需要求 |
|---|---|
| 安全 | 默认拒绝、逐接口身份/权限、产品/环境/用户/工作区/资源隔离；秘密不进入包/前端构建/URL/日志/模型 |
| 可恢复 | 消息/管理写幂等、revision/CAS、lease/fence、持久等待；已提交决策/收据重放，未知写入先对账 |
| 可用性 | 有效已部署合同不依赖 Jorice 逐次在线；安全新鲜度过期照常阻断，依赖故障不换空库或他人凭据 |
| 配额/性能 | 长操作异步/可查询，列表分页、编辑无静默丢失；上限由目标跨 Worker 执行，S1 实测后制定容量/时延目标 |
| 兼容 | SDK/管理协议/引擎/组件/恢复合同矩阵；已固定旧任务和 v1 兼容路径，不静默塞新字段 |
| 无障碍 | 键盘完成表单/确认/审批，焦点与错误可读；状态不只依赖颜色，表格/流程有文字说明 |
| 内容治理 | ACL/派生/删除覆盖检索、上下文、缓存、Memory、产物、必要执行记录/备份；不承诺收回已外部交付副本 |
| 可诊断 | 脱敏关联 ID、真实状态/证据、可执行处置入口；支持人员不因运维角色自动获业务写权限 |

不得把 HTTP 200、健康检查、容器启动或 mock 页面称为业务闭环；只读、模拟、真实写入和生产验收分别标注。

## 11. 发布依赖、风险与决策

实现依赖先满足认证/合同，再完成单产品纵向切片，逐项打开配置域/Plugin/部署治理；页面、后端、BFF/SDK 和业务 API 联合交付。

| 依赖/风险 | 产品处理与负责方 |
|---|---|
| 业务 API/ACL/委托不完整 | 业务集成团队在 S0 接入清单确认；无法受限核验则不开放对应动作 |
| Host 出站仅有服务兼容凭据 | 部署/安全团队落实生产发行/轮换/撤销和用户委托；已有 HMAC Port 不能通过该门禁 |
| npm/Hook 仅有底座 | SDK/BFF 团队完成新接入封装与专项验收；`@jorice/react` 为拟定名称，未声明已实现/公开发布 |
| SPA/刷新/多 Tab | 同 Session 只收窄；新增挂载重建 Client 绑定，刷新新 document 独立 Session；不跨页面重发 Secret |
| 外部写入无法确认 | 业务方提供幂等/查询收据；无法确认时阻断自动重试，保留部分/unknown |
| 存储/内容源不支持所需删除 | 限制持久化或阻止该来源上线；不能以页面隐藏替代清理证据 |
| 工期受实际复用影响 | S1 用真实切片测量后估剩余；旧 20–36 人周不是本 PRD 完整范围承诺 |

S0 需登记首个试点产品/验收对象、实际 IdP/部署目标、所用 Provider、真实写入范围及容量目标；这些是环境选择，不改变本 PRD 已定义的流程/安全边界。
上述选择由相应产品/部署负责人确认并进入接入记录；本轮不虚构已指定的人名、上线日期或生产资源。

## 12. 验收标准与需求追踪

每项证据记录版本、环境、身份/数据范围、预期与实际、证据引用和观察时间；启用项必须通过，未启用项有目标拒绝证据。

| 编号 | 验收场景 | 对应需求/流程 |
|---|---|---|
| AC-01 | 管理主体只能管理获授权产品/环境；配置/发布/读取业务数据权限分开 | FR-01、19／UX-01 |
| AC-02 | 创建产品/模板/环境，缺项可找回；环境复制不复制生产秘密，映射歧义拒绝 | FR-02、06／UX-02 |
| AC-03 | 配置源/上限/最终值可查看，未知字段拒绝；各域实际改变行为且旧任务恢复不读 latest | FR-03、05／UX-03 |
| AC-04 | tool/context/verifier 真正执行，包/依赖精确；脚本取消/超时/无效输出有确定结果 | FR-04／UX-04 |
| AC-05 | 业务登录一次；服务身份和受限用户委托共同核验，伪用户/工作区/对象不能越权 | FR-06、12／UX-05、08 |
| AC-06 | 公开 Key 复制/伪 Origin/任意目标 URL 不授予权限；npm 初始化与 Profile/SDK 不兼容可定位 | FR-07／UX-05 |
| AC-07 | Hook/Readable 真正进入受限上下文及 Effect 链；只执行指定 Controller 页面，Receipt/恢复可查询 | FR-13／UX-05、08 |
| AC-08 | 首批 Hook、路由新增、卸载重挂、复制 Tab、刷新/接管/退出均不串身份或复用旧 fence | FR-07、13／UX-05 |
| AC-09 | 安装未启用/缺认证/未选择不能调用，升级/撤销/卸载不破坏共享来源/引用 | FR-08／UX-06 |
| AC-10 | API key/OAuth 账号/scope/环境正确，回调重放/并发 refresh/失效有确定结果，无秘密泄漏 | FR-09／UX-06 |
| AC-11 | 环境证据匹配最终版本，部署/激活真实确认；受限期普通账号/非验收资源拒绝，验收失败不开通，开通响应丢失查原操作；多 scope 部分失败不显示全产品成功 | FR-10、11／UX-07 |
| AC-12 | A/B 独立资源/版本/权限，副本恢复同一事实；回退保留历史、不复活撤销版本 | FR-11／UX-07 |
| AC-13 | 消息重复/断线不重复执行；附件完成/绑定/下载受权，终态/部分结果真实 | FR-12、18／UX-08 |
| AC-14 | 澄清/审批刷新后找回；参数变化/过期/错误主体拒绝，重复确认无重复写入 | FR-14／UX-09 |
| AC-15 | successor 候选 held，旧写入对账，唯一 CAS 后激活；崩溃恢复不双执行 | FR-15／UX-09 |
| AC-16 | 来源撤权/删除影响检索、缓存、Memory、产物及保留副本，失败可追踪 | FR-16／UX-10 |
| AC-17 | 显式后台委托与重新登录任务/待办可用；启用计划时去重、时区/漏跑/重叠、版本漂移可复现 | FR-17／UX-11 |
| AC-18 | 模型/授权/预算/依赖失败真实显示，unknown 先对账，取消不假称业务回滚 | FR-05、18／UX-12 |
| AC-19 | 列表/搜索/计数/流/下载/导出同样过滤，审计可关联但无秘密或越权业务内容 | FR-19／UX-12 |
| AC-20 | 停用/退出无新入口，旧任务有处置，解除管理不误删库，共享引用/备份恢复保护，A 不影响 B | FR-20／UX-13 |

AC-12 的双产品验收是 S3 完整平台条件；其他产品限定项目按阶段范围验收，但生产不能跳过核心权限、真实收据、恢复与自身资源隔离。
严格全量业务数据处理另按授权快照、确定枚举、集合/版本对账和所有输出门禁验收；脚本与知识源接通不自动保证完整覆盖或答案语义正确。

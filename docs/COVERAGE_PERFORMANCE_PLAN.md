# Coverage 执行链路深度性能优化方案

实施发现的重要修正：移除历史物理重读并完全保留提交时拒绝语义，需要当前
存储尚未提供的不可变保留证明。不能直接用索引替代，见
[增量证明前置条件](ADR-COVERAGE-INCREMENTAL-PROOF.md)。下述 C/D 目标不因
同调用去重组件通过就视为完成。用户已批准新准入采用增量提交、最终认证把关；
必须显式绑定版本模式，旧任务拒绝时机不变。实现及验收仍在进行中。

日期：2026-10-10。状态：实施中；有界工作片、RR 查询复用、超时合并和只读
binding 读取已落地；恢复首次对象读取的嵌套权限校验从四次合并为前后各一次。
活跃 lease 的恢复扫描先按原锁顺序做拒绝式预检查，避免先生成完整证明再延后；
未命中释放预检查锁后仍做完整恢复，正常 fenced continuation 尚未走快速协议。
正常续跑／增量验收协议及性能目标尚未完成；证据见
[工作片验收记录](COVERAGE_WORK_SLICE_EVIDENCE.md)。本文目标不等于已有结果。

补充：binding 使用原生 psycopg BEGIN 参数代替独立 SET TRANSACTION，短批次页
不再追加空查询。真实 PG 已验证 deadline/borrow 包装下 RR/read-only 及归还重置。
当前九条负载使用固定 binding loader，因此不能用它证明该原生路径的收益。
本轮默认81.35s/85643SQL、诊断49.19s/54282SQL；未观察到耗时改善。仍需直接
处理正常续跑完整恢复和权限链扇出，不能把这些小项当作整体性能完成。

## 1. 问题与证据

当前 9 条测试输入是 native part 0 至 native part 8，每条 13 字节，共 117 字节。
每条有 part 和 record_merge 两个检查单元，模型 HTTP 返回预设 clear。
Worker 和 PostgreSQL 实际执行，Host、模型和 S3 为受控 transport。
这组数据只能测执行基础设施成本，不代表真实文章处理或真实模型准确率。

早期受控 1/6/9 条完成耗时为 17.69/140.89/261.70 秒；1 条启用 profile，
不能直接与未 profile 的大组比较。9 条对应 224,929 次 SQL execute，
3,521 次对象 GET，517 次物理连接，18 次执行交接。
SQL execute 包含超时配置和连接重置，不能直接称为业务查询数量。
计时从 fixture admission 完成后的第一次交接到认证完成，不含 fixture 初始化。

最新受控样例（单次观测，不是 p50/p95）：

| 配置 | 完成时间 | SQL execute | 对象 GET | 执行回调 |
| --- | ---: | ---: | ---: | ---: |
| 默认 2 秒工作片 | 144.69 秒 | 152,882 | 2,534 | 11 |
| 诊断 60 秒工作片 | 99.53 秒 | 98,296 | 1,062 | 1 |

原始证据：`evals/coverage_acceptance/active-lease-load-20261010.xml`。
诊断组恢复 prepare 仅两次、合计约 0.021 秒，仍然整体很慢。
`_record` 累计包含子调用耗时约 83.06 秒；commit 约 22.04 秒。
两者重叠，不能相加，也不能当作互斥耗时占比。
诊断组业务 SQL 56,155 次、连接 reset 33,564 次、clock 8,578 次。
因此主要问题不是 9 条内容复杂，而是检查调用树和提交历史回放放大。
更早的同 SQL 数诊断组只需约 69.96 秒，说明还存在环境波动；不能把单次
时间变化全部归因于代码优化。验收需要同机重复采样与结构计数同时改善。

源码确认的放大环节及当前状态：

- 原固定 execute_batch(limit=1) 已改为有界工作片，不再列作待修复项。
- 正常 continuation 调用恢复证明；反复装配、回放和独立验证已有数据。
- coverage.py 的 commit 通过 verify_model_results 新建验证器，读取已有模型账本。
- CloudCoverageArtifacts._record 调用完整 check_authority；前后读取再次调用。
- dispatch 的 check 同时进行 ownership、事件追赶、Task binding、lease、active
  segment 和 Host snapshot descriptor 查询；细粒度 Artifact 读取放大这些调用。
- 两次 set_config 已合并；RR 同快照有界查询复用已实施。
- 每个对象 getter 仍可能进入任务级权限链；每次 commit 仍新建历史验证器。
- 独立短事务非常多，连接重置进一步放大这些调用的成本。

这些是已确认的调用结构，耗时占比仍需分阶段 profile，不用调用次数猜百分比。

## 2. 目标与边界

目标是让正常执行的基础设施成本随输入和产物近似线性增长。
保留快照身份、精确集合、模型收据、预算、幂等、lease fence、STOP 和正式发布门禁。
正常执行、故障恢复、最终认证采用不同的工作范围，避免每一步都重做完整恢复。
新调度不减少持久化检查点，不依赖进程内状态保证正确性。
新查询组织不缓存撤权、到期、取消或当前 lease 的决定。

## 3. 修改执行粒度

复用 CoverageExecutor.execute_batch 的多单元能力，移除生产路径 limit=1 常量。
采用可配置工作片：最多 32 个单元、8 MiB 输入、约 2 秒本地执行时间，
任意一个阈值达到就在安全检查点让出。初值由固定基准校准。
慢模型调用有独立超时与 lease heartbeat；2 秒是协作让出阈值，不中断在途调用。
每单元仍持久提交，运行中的进度持续发送；发送 UI 事件不要求退出 Worker。
进程崩溃后从已提交单元恢复；模型结果已持久化时复用收据，不重复计费。
单 part 的 record_merge 保持独立合法结果，但在同一工作片立即处理。
多 part 只有所有匹配 part 已提交才允许 merge；missing-unit 查询必须重新取就绪依赖。
强制每单元换 Worker 的原测试保留为故障/交接压力测试，不再代表正常吞吐。

## 4. 正常继续与故障恢复分开

当前 fence 下的 Worker 正常让出时，在同一短事务内校验当前命令代次、Task、
binding、STOP、lease、run 和本次提交序列，原子写 continuation 和 outbox。
下个 Worker 仍验证当前权限与绑定，再从持久记录取缺失单元。
只有 lease 丢失、进程退出、交接异常、版本冲突或执行状态不确定才进入完整恢复。
不能把一条进度通知、计数或调用方提交的 digest 当作恢复凭据。
复用原子 outbox/命令交接实现；新增路径必须覆盖重复投递、旧 fence 和提交后崩溃。

## 5. 增量提交与最终独立认证

每次提交验证当前输入、模型原始响应与收据、派生结果，以及本记录所需的 part。
事务中校验预期 run revision，原子追加原始事件、单元结果索引、预算和进度。
依赖已有接受事实必须有不可混淆的 native Event/receipt 关联，普通投影不成为信任根。
同一单元只接受一次；同键不同内容拒绝，重试同内容返回原收据。
最终认证独立枚举精确 expected/accepted 身份集合，检查缺失、重复、额外结果、
版本、原始模型证据和保留期限，并读取所需物理对象。每个唯一对象在该阶段读一次。
数据库索引、增量计数和哈希可加速定位，但不能代替最终集合与原对象证明。

首先实现无需新增持久信任根的工作片复用、依赖定向查询和批量加载。
如仍需跨 Worker 的“已验证前缀”检查点，另列 ADR、可信存储约束和迁移后实施；
不能只新增 verified=true 或自报哈希便跳过历史证明。
频繁故障下可能仍需要 O(N × 恢复次数) 工作，不宣称任意故障下均为线性。

## 6. 权限与 Artifact 查询合并

查询按步骤、依赖和消费需求执行，而不是为一个工作片预取完整历史。
先验证拒绝条件，已发现无效准入则不读取 stream/history/binding；当前单元
只取必要依赖。已固定上界的分页达到上界即结束，不再发空页探测 SQL。
没有完整上界或允许等 sequence 多行的扫描不能套用该结束条件。
分步查询不能自行宣布全量完成；最终认证仍独立枚举并验证完整集合。

把纯身份/摘要/长度检查与需要当前数据库/Host 状态的检查分开。
为一个受限读取/提交批次读取统一的权限上下文，联合查询 lease、epoch、Task、
binding revision、状态和到期时间；每个外部调用前后与提交时检查当前有效性。
远端 Host 的立即撤权语义须由可验证的版本/撤权协议支持；没有该能力时保留必要
远端检查。不能凭固定 TTL 缓存改变撤权行为，也不能仅比较快照 descriptor 代替权限。
批量获取相关 Artifact 完整记录，保留 session/namespace/version/lifecycle/receipt
及 retention；回包后再批量比较。时间到期判断使用当前时间。
同一阶段按确切 Artifact ID 与 object version 复用字节，保持原有内存上限。
独立认证重新读取，跨阶段缓存不能充当对象仍存在、未损坏的证据。

## 7. SQL、连接与锁

采集按阶段和 SQL 指纹的次数/耗时：admit、bootstrap、execute、commit、
handoff、recover、certify；同时区分业务 SQL、set_config、reset、连接和 Host 请求。
复用已有 psycopg；先合并一个事务内的查询，不新引入缓存服务或数据库框架。
合并两项 set_config 或使用已安装客户端支持的 pipeline，保留共享剩余 deadline，
服务端取消和锁超时；不得以每条重置总预算延长任务。
真正相同的 RR 只读查询可以在同一快照重用有界结果，final 仍执行原生重新验证。
真实表上检查 EXPLAIN (ANALYZE, BUFFERS)，只为已证实的扫描/排序补组合索引。
检查 run/session/event type/sequence、缺失单元及 Artifact identity 查询。
网络/模型读取尽量在事务外准备；短事务用完整 revision/fence 比较提交。
最终物理证明若缺少可保证不变与保留的存储协议，仍保留同步最终读。
记录该成本；不承诺通过单纯移出锁就能保持同一证明语义。

## 8. 模型与批量大小

先优化基础设施，再测模型受限并发。初值最多 4 个独立 part 在途，同记录 merge
依赖全部 part 接受；每次派发先原子预留预算，响应乱序但提交身份确定。
117 字节测试不需要模型并发来解释基础设施性能。
真实批量按输入 token、配置的输出上限、字节和供应商限制选取；每记录结果有独立
身份与可校验引用。一个坏结果不能导致整批再次付费。
原 full-context 9 条模型预算门禁保留；扩到 100/1000 条必须使用另一个合法且
明确标注的测试 profile，不修改生产上限来让基准通过。

## 9. 用户可见进度

durable 接受后立即反馈排队/执行状态；记录进度来自已提交检查单元。
part 和 merge 在 UI 以记录进度组织，避免用户把 18 单元误解为 18 篇文章。
执行输出持续发布 commentary；正式答案等待证书。最终校验阶段单独显示。
不使用虚假百分比、重复 heartbeat 文案或提前 completed 掩盖后端停滞。
断线恢复从序列游标补读，不重复显示内容；terminal 后撤销 Working。

## 11. 实施顺序与交付

1. 分阶段计量和两种基准：正常执行与强制恢复，先冻结目标。
2. 批量新鲜权限与 Artifact 查询，消除 getter 的任务级检查扇出。
3. 定向依赖验证与增量提交，保留最终独立完整证明。
4. 依赖上述持久接受事实实现正常 continuation，不复用故障恢复全量路径。
5. SQL 往返、索引、连接和锁优化，再引入受限模型并发。
6. 同机对比、故障矩阵、真实联调和 UI 渐进反馈验收。

这是同一优化目标的内部依赖顺序，可连续实施。每轮报告实际输入、模型真假、
计时起止、p50/p95、工作量、失败样例与尚未满足的门槛。
代码主要涉及 agent-core executor/Ports、agent-storage coverage/authority/query、
Worker dispatch/recovery，以及必要的 Trench 进度映射；不把规则搬进前端。
在现有 task registry 扩展准确 Owned paths 后实施。迁移与协议改变先写 ADR。
已有运行保留协议版本；新旧 Worker 不能混用未识别的 continuation/proof 版本。
发布先单任务验收，再并发；回滚路由到兼容 Worker，保留原始事件和任务进度。

## 12. 可实施的读写契约

以下是待实现设计，不代表当前已有快速协议。复用现有 Ports、Event Store、
Artifact facade、outbox 和预算账本；不新建通用缓存平台或引入依赖。

### 12.1 区分不变数据与当前授权

| 数据 | 允许复用的范围 | 必须重新检查的边界 |
| --- | --- | --- |
| 精确对象版本的字节、长度、digest | 单次有界验证阶段 | 最终认证重新物理读取 |
| manifest、已接受事件的不可变内容 | 当前阶段、精确身份 | 原始事件定位及完整性验证 |
| lease/epoch、STOP、binding、到期与撤权 | 不做跨操作 TTL 授权缓存 | 外部操作前后、提交、交接、发布 |
| 投影计数、缺失单元索引 | 查询加速 | 以原始接受事件/收据验证 |
| Host snapshot descriptor | 绑定输入快照 | 不能代替当前访问授权 |

批量接口必须显式限定 namespace/session/run、对象身份集合和数量/字节预算。
返回缺失、重复、跨 scope、过期或版本不符时拒绝，禁止静默漏项。
权限上下文是一次操作的校验材料，不是可传给后续任意操作的永久通行证。

### 12.2 消除嵌套 getter 检查

由最外层业务操作负责批量 pre-check，传递内部专用、操作范围受限的读取上下文；
facade 内层不再为同一读取重复启动任务级验证。物理读取后做批量 post-check，
使用当前时钟核对生命周期，并比较精确元数据/版本。普通独立 getter 仍保留原检查。
禁止公开 `skip_authority` 布尔参数，禁止把调用方自报的上下文当作可信凭证。
单个外部请求的前后检查不能因为“同一批”而被跳过；只有具有明确前后边界的
批量外部操作才能共享检查。没有 Host 原子批量/撤权协议时保留必要远端往返。
缓存继续受现有 32 MiB 上限约束，超出退回流式读取，而不是全历史驻内存。

### 12.3 增量接受的事务边界

事务外：定向获取本单元输入、原始模型响应 checkpoint、reservation/settlement、
本记录的依赖接受事实；验证结果与快照/派生版本绑定。不得读取全部历史 batches。

短事务内：锁定精确 run/预算行，检查 expected revision、fence、当前状态、STOP、
授权版本与保留约束，原子追加接受事件、单元索引、预算结算与进度/outbox。
版本冲突重新读取受影响依赖，不无条件重新调用模型。相同幂等键与同内容返回
原收据；同键不同内容必须拒绝。单元身份由数据库唯一约束保护。

接受事实至少绑定：协议版本、scope/run、snapshot/manifest digest、unit key、
输入与响应 checkpoint 的精确版本、派生规则版本、依赖收据、预算收据、
commit key、原始事件序号及接受时 fence。字段应复用现有模型，缺项才补。
收据由服务端验证并与原始事件在同一事务生成；自报 hash 或 `verified=true`
都不足以证明接受。新增持久证明语义必须先补 ADR、迁移与篡改回归。

对象必须先完成不可变持久化再接受；事务失败的孤立对象交现有保留/GC 处理。
将网络 I/O 移出锁之前，必须确认版本不变与 retention/deletion fencing 契约。
没有这些保证的最终证明继续保留必要同步读取，不人为扩大 TOCTOU 窗口。

### 12.4 预算与模型账本

按 request/reservation ID 定向读取，不为每个新单元重放全部账本。
预算预留、settlement 与原始事件原子维护；可重建投影负责定位，不独立授权。
正常提交只核验本次 reservation 与依赖；最终认证重新对账全部原始收据。
调用已发送但响应不确定时标记 unknown 并进入协调流程，不能直接重试付费请求。

## 13. 正常交接与异常恢复协议

正常链路：工作片提交 → 短事务记录 continuation/outbox → 下一 Worker 验证
当前授权与精确持久检查点 → 查询就绪缺失单元 → 继续执行。

continuation 绑定 run revision、命令代次、最后接受事件/收据、预算状态、
输入快照与协议版本。接管方仍获得新 lease/fence，旧 fence 不能继续写。
正常交接不能仅依赖进程内缓存、UI progress 或未认证计数。
验证范围为确定的检查点和新增后缀；没有可信接受契约前，不开启该快路径。

| 故障窗口 | 处理方式 |
| --- | --- |
| 请求尚未发出 | 幂等接管并正常执行 |
| 请求已发出、结果不确定 | 协调供应商/请求状态，无法确认则 unknown，禁止盲重试 |
| 响应 checkpoint 已持久化、尚未接受 | 验证原响应后重试接受，不再调用模型 |
| 接受已提交、消息投递失败 | 原子 outbox 重投，幂等消费 |
| 旧命令/旧 fence/重复消息 | 拒绝写入或返回已有结果，不重复执行 |
| 当前 Worker 仍持有效 lease | 保留现有延后逻辑，不制造并发接管 |
| 检查点冲突、证据缺失、异常退出 | 独立完整恢复；无法证明则拒绝正式发布 |
| 证书已提交、客户端没收到 | 从持久事件补读，不重新认证/生成整份答案 |

完整恢复保留为异常路径，不删除原恢复实现。记录恢复原因和触发次数，防止
实现表面有快路径、实际因兼容条件每次仍回落到全量恢复。

## 14. 最终认证与大规模读取

最终认证依然独立完成 expected/accepted 精确集合比较、依赖完整性、原始
响应/证据验证、预算与 unknown 对账、当前权限与发布 fence 校验。
同一次最终认证中按对象精确版本去重物理读取；前序阶段的字节缓存不作证明。
manifest、事件及结果使用稳定游标分页；集合比较优先有序归并，内存受限。
只在确实需要无序集合外排时使用现有临时存储，并明确磁盘配额与清理边界。
正常无故障验证工作量目标 O(单元数 + 依赖边数 + 证据字节数)，不承诺任意
故障次数下仍线性，也不拿计数相等替代集合相等。

发布事务核对认证所依据的 revision、当前权限、保留约束和唯一证书；发生
相关改变则重验受影响范围或拒绝。不能先显示正式成功再异步补认证。

## 15. 连接、并发与用户体验收尾

查询先合并再调索引：为实际高频指纹采集调用者、rows、耗时与 EXPLAIN。
优先检查 scope/run/unit、accepted event sequence、reservation、Artifact identity。
一个业务操作尽量复用连接及事务边界，减少几万次独立事务/reset。
不直接删除 `DISCARD ALL`；若改变 reset 策略，必须证明角色、GUC、search_path、
临时对象、事务隔离及 prepared statement 不跨请求泄漏，reset 失败丢弃连接。

基础设施达标后再开启有界模型并发，复用现有调度器；任务、租户、全局均有限额。
限制等待队列与连接峰值，STOP 取消未派发工作，在途调用按既有取消/unknown
契约处理；不能用提高并发掩盖单任务几万次 SQL。

前端阶段映射：排队 → 处理中（已完成记录/总记录）→ 正在校验 → 完成/失败/
需处理。记录仅在必要 part 与 merge 均接受后计完成；工具步骤不是文章数。
首个持久状态不等待完整证明；进度可短窗口合并发送，但不得丢失持久事件。
commentary 属于进度，最终正文属于已认证交付；开始正式结果时默认折叠过程。
终态到达立刻结束 Working，重连按序号补齐；断流显示连接状态而非假装继续工作。
不改变输入框定位/滚动容器；本次性能改动需加现有布局与用户上滚回归。

## 16. 验收方法、迁移与回滚

### 16.1 测量口径

拆开 queue wait、bootstrap、authority、object read、model wait、commit、handoff、
recovery、certify、发布及 UI 可见时间。并发跨度使用 wall time 和独占/包含耗时
分别报告，禁止累加嵌套 span 算整体时间。
同时报告 SQL 指纹/分类、事务与 reset 数、唯一/重复 GET、Host 检查数、
扫描行数、锁等待、对象字节、峰值 RSS、临时磁盘、每条输入模型调用数。
使用持续运行 Worker 作为正常基准；每次回调新建 consumer 的 fixture 单列，
不能把它的恢复次数直接当作生产系统的每次交接次数。

至少 20 次探索样本定位；发布前关键 9 条受控测试至少 100 次，报告分布、
失败率与环境，profile 运行另列。5 秒目标只针对预热受控模型/Host/S3基础设施，
不是对真实大模型与远端网站的端到端承诺。
9 条 SQL ≤1,000 是工程验收预算，不能通过不计 reset 或跳过安全检查“达标”。
真实链路逐段测量并单列供应商耗时；未达到的门槛仍标 OPEN。

### 16.2 必须通过的回归

- tenant/scope 隔离、撤权、到期、STOP、epoch/fence 竞争和旧消息重投。
- 对象在 pre/post/提交/认证各边界被删除、替换、损坏；原始事件和收据不匹配。
- 同键同内容重试、同键异内容拒绝、并发预算不足、unknown 调用不重复收费。
- 提交前后及 outbox/证书各故障窗口杀进程；无丢单、无重复接受、无提前发布。
- 1/6/9 受控样例，合法预算的 100/1000 条真实尺寸，1/4/16 并发任务。
- 冷/热、新/旧协议、持续 Worker/强制接管分别测试，峰值内存不随全历史驻留。
- 真实 RabbitMQ、对象存储、Host、模型、Trench 与浏览器端到端独立验收。

没有人工标注业务集时，仅交付控制样例正确性和真实链路性能，不宣称真实语义
准确率达标。快照处理完整性也不等于上游抓取完整或零漏判。

### 16.3 兼容发布

迁移采用新增字段/索引与协议版本，不破坏原始事件；回填必须通过原证据验证。
旧 run 默认继续旧协议；只有独立认证过的检查点才允许显式升级，不能批量置真。
新命令仅路由到支持新协议的 Worker；旧 Worker 不认识版本时拒绝接管。
先只读对照验证，不重复模型调用，再对新 run 小范围开启；以延迟、证明失败率、
恢复回落率、预算异常与重复调用数决定是否扩大。影子验证也必须限流。
回滚先停止新版本 admission，保留能处理在途新协议的 Worker 排空或安全恢复；
不能简单把旧二进制替换回去并让它消费新命令。原始证据、收据与进度均保留。

### 17.3 恢复阶段有界查询合并（2026-10-10）

历史事件与执行单元各自的全量数量/字节统计和有界行读取，合并到同一原生

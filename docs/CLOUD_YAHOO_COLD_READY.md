# Yahoo 冷启动与暂停反馈最小修复

任务 YAHOO-COLD-READY-01；2026-10-17；基线 218951a6。

## 结论与实施边界

安装镜像的原生 EngineCache 已有 SQLite 持久化和到期清理，但默认使用
`tempfile.gettempdir()`。实际数据库落在 `/tmp/sxng_cache_ENGINES_CACHE.db`，
已有 `/var/cache/searxng` 命名卷为空；容器重建后 Yahoo YBV 初始化状态丢失。
Compose 仅增加 `TMPDIR=/var/cache/searxng`，复用现有卷、原生缓存和 86400 秒到期规则。
没有增加缓存服务、依赖、预热任务、搜索答案缓存或授权缓存。

真正空卷、缓存过期或 Yahoo 拒绝已有 cookie 时仍需初始化，不能保证直达 200 或 5 秒成功。
保持 Yahoo 5 秒、搜索 6 秒、Zebra 10 秒预算和上一轮原生状态 0 有限重试配置。

安装版 SearXNG 的暂停分支不向 Yahoo 发请求，实际 JSON 是
`[["yahoo", "Suspended: timeout"]]`。旧诊断把它当成本次已执行的超时，
标记可重试并附加 5 秒倒计时；非瞬时搜索失败又落入通用“修正参数”的提示。
共享归一化现在先识别已核对版本的 `Suspended:` 前缀，标记不可立即重试、不虚构倒计时；
仅当全部 1–8 个诊断均暂停、结果确为空且没有顶层错误时标记 `not_executed`。
混合、部分结果、超过诊断上限、未知文案仍保守处理；不接受部分候选为完整证据。
只读 upstream_search 失败提示引导 Agent 使用已有证据、独立可用引擎或报告缺口；
真实瞬时超时仍保留原有限恢复，写操作结果未知保护不变。
没有自动切换引擎、强制工具、绕过限制或降低质量门。

## 原生无模型验证

固定 SearXNG 镜像 `245b675ff61b`，独立实例，只记录状态和缓存是否存在，不记录 cookie。

| --- | ---: | --- | --- |
| A1 临时目录首次 | 2415.7 ms | 否 | 307 / 307 / 200 |
| A2 临时目录重建 | 1456.7 ms | 否 | 307 / 307 / 200 |
| B1 命名卷首次 | 1699.7 ms | 否 | 307 / 307 / 200 |

四次均返回 7 个候选，包含目标官方公告；耗时受网络波动影响，不作为稳定百分比。
安装版真实 processor 的隔离暂停控制返回 10.56 ms、零结果、上述暂停 JSON，
且没有 Yahoo HTTP span。相同响应经过修复前后纯函数链，模型可见状态从
executed/true/5 秒变为 not_executed/false/无倒计时，提示不再建议改写同引擎查询。
这证明反馈契约，不能证明真实模型一定不再尝试其它检索。

## 页面协议

固定最多四个新 Run，顺序 A1/B1/B2/A2；同一账户、Flash、高思考、探索、transient_v2，
相同问题：联网核对 PostgreSQL 18、Redis 8 正式发布日期与两项特性，仅官方来源。
工具由 Agent 决定。每样本先执行同一个中性 SearXNG documentation 请求，
随后重建搜索服务，再从页面点击发送计时。中性请求不查询测试答案，成本单列。
这是“已有使用后搜索容器重建”场景，不能替代空卷首次启动或稳态暖请求验收。

B1 准备阶段、调用模型前遇到 Docker max depth exceeded：原 Worker 124 层，
诊断 A 126 层、B 128 层。通过未启动容器导出原文件系统并导入，恢复 image Config，
压至 2 层；语义启动配置相同，69 个既有 Worker 源文件指纹相同。
剩余 A/B 使用同一压平基镜像。A1 保留作前期样本；正式比较只用 B2/A2，
不混算压平前后的均值，也没有增加第五个 Run。

首正文为最终正文前 16 个归一化字符首次出现在页面的时间，包含明确临时草稿；
进度文字不计首正文。Host 完成从点击到业务 completed；DOM 末次变化另列。
SQL 统计限本轮 Worker attempt 和点击至完成后 1 秒内 API observer 请求，
是 DriverSQL execute 次数，不能当成整机 PostgreSQL 总查询数。

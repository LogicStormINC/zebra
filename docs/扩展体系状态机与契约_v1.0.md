# 扩展体系状态机与契约 v1.0

> 状态：Phase A 契约基线
> 日期：2026-07-20
> 上游 ADR：`ADR-014_扩展体系架构.md`
> 任务：`EXT-0`

本文把 ADR-014 的五层扩展状态机展开为可实施的契约：每层的输入、输出、失败模式、
持久化载体，以及与既有 durable Session/Event/Workspace projection 的对账规则。本
文是 `EXT-SKILL-*` 与 `EXT-MCP-*` 实现卡的目标契约。

## 1. 五层状态机

```
Available → Installed → Enabled → Granted → Approved
```

前一状态**不自动推导**后一状态。每层都有独立的输入、判定与 durable 落点。

### 1.1 Available

- 输入：本地 catalog root（`ZEBRA_SKILL_ROOTS`、`ZEBRA_MCP_SERVERS`、未来的 plugin
  install dir）或 Registry 查询结果。
- 判定：组件 metadata 通过结构校验（name / description / version / digest 形态）。
- 输出：catalog 条目，仅暴露 name / description / scope / digest 等不可信 metadata。
- 失败模式：metadata 畸形、digest 不匹配、root 不可达 → 条目不进 catalog。
- Phase A 落点：`LocalSkillCatalog._discover`、MCP discovery。

### 1.2 Installed

- 输入：一个 Available 组件 + 固定版本 + 内容 digest。
- 判定：digest 与落盘内容一致；版本在兼容范围内。
- 输出：不可变安装记录（version + digest + source + 安装时间）。
- 失败模式：digest 漂移、版本冲突、磁盘不足 → 安装失败，保留上一版本。
- Phase A 落点：Skill digest（`EXT-SKILL-02`，sha256 of manifest ‖ body）；MCP server
  descriptor 校验。Plugin 完整安装记录属 Phase B（`EXT-PLUGIN-01`）。

### 1.3 Enabled

- 输入：一个 Installed 组件 + user / repo / namespace 选择。
- 判定：组件未被 admin 禁用；namespace 无未解决冲突。
- 输出：enablement 状态记录。
- 失败模式：admin 禁用、namespace 冲突、scope 非法 → 不启用。
- Phase A 落点：Skill enable/disable 持久化（`EXT-SKILL-04`，`skills_state` 表）。

### 1.4 Granted

- 输入：一个 Enabled 组件 + Task 启动。
- 判定：Task authority 投影包含该组件的精确 identity。
- 输出：`TaskPreparedPayload` 中的精确 component identity 快照。
- 失败模式：组件未 Enabled、authority 不允许、digest 与 Installed 不符 → Task 不获
  得该组件。
- Phase A 落点：`TaskPreparedPayload.skill_components`（`EXT-SKILL-03`）、既有
  `mcp_allowlist`。
- 不变量：运行中 Task 不静默换版本；撤销的组件对旧 Task 按撤销策略暂停或仅允许读取
  已捕获内容。

### 1.5 Approved

- 输入：一个 Granted 组件 + 一次有副作用调用。
- 判定：既有 Policy / Approval / HITL 流程放行。
- 输出：Approval 事件（既有 `APPROVAL_REQUESTED/GRANTED/REJECTED`）。
- 失败模式：Policy deny、Approval 拒绝、超时、取消 → 调用不执行。
- Phase A 落点：既有 Policy engine、`mcp_proxy_policy`、Elicitation→Clarification
  （`EXT-MCP-06`）。

## 2. 状态对账规则

| 转换 | 谁触发 | durable 落点 | 可否回退 |
|---|---|---|---|
| Available→Installed | operator 安装 | 安装记录 + digest | 是（卸载） |
| Installed→Enabled | user/admin 启用 | enablement 状态 | 是（禁用，只影响新 Task） |
| Enabled→Granted | Task 启动 | `TaskPreparedPayload` 快照 | 否（Task 期间固定） |
| Granted→Approved | 单次副作用调用 | Approval 事件 | 否（单次有效） |

对账不变量：

- Enabled 的变更**只影响新 Task**；已 Granted 的 Task 保持其快照 identity 直至终态。
- Granted 快照必须能在 Task resume / inspect / diff 时无歧义重建（无需重放 catalog
  状态）。
- Approved 是一次性的：每次有副作用调用独立走 Approval，不因 Granted 而隐式通过。

## 4. 与既有 durable 契约的对账

- **Event Store**：Phase A 不新增 EventType 成员。Skill 选择快照走既有
  `TASK_PREPARED`（`skill_components` 可选字段）；Elicitation 走既有
  `CLARIFICATION_REQUESTED/RESPONDED`。
- **Task authority**：`TaskPreparedPayload` 是 Task-time 授权快照的权威源；
  `workspace_projection` 镜像同步（既有 ALTER TABLE 渐进加列模式）。
- **HITL**：`ClarificationContext` + `WAITING_INPUT` + pause-resume loop 是 Elicitation
  的复用原语；仅扩展 typed `response_schema`。
- **执行链**：`McpProxyTransport` 协议、`normalize_mcp_allowlist`、
  `AuthorizedMcpToolCatalog` 披露桥、`mcp_proxy_policy` 路由分类均为传输/扩展无关，
  新传输与新扩展种类直接复用。

## 5. 失败与恢复语义

- 组件撤销：新 Task 不可用；旧 Task 按撤销策略——默认暂停并要求 operator 决策，
  或仅允许读取已捕获的不可信内容，不执行新副作用。
- digest 漂移：fail closed；Task 不获得该组件，并向模型返回结构化失败证据。
- 安装/升级失败：保留旧版本，可原子回滚；不留半安装状态。
- 连接失败（MCP）：区分配置、传输、协议、认证、上游、Policy 故障；有界退避重连，
  不无限后台重试；quarantined 后新调用 fail closed。

## 6. Phase B 演进位

下列在 Phase A 不实现，但本契约为其预留位置：

- `TASK_EXTENSIONS_GRANTED` 事件 + `task_extensions` projection 表：当 Task 中途需要
  可变授权（enable/disable 组件）时，从 `TaskPreparedPayload` 快照升级为可变授权流。
- Plugin manifest 完整生命周期与不可变安装记录（`EXT-PLUGIN-01`）。
- 声明式 Hook 与 content-hash 信任（`EXT-HOOK-01`）。
- Marketplace 分发、签名、SBOM、撤销、kill switch（`EXT-MARKETPLACE-01`）。

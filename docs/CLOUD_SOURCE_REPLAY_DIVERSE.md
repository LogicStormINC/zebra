## 预先冻结的评分与晋级门槛

生成前冻结 rubric.safe.json，不按结果调整来源或再抽取有利样本。

“确定可避免”包括重复成功的相同请求，以及所有所需事实已经获得后、没有新缺口的
额外请求。“预期重叠”单独记录：例如同批抓取发布页和内容相近的特性文档，不能
在还没读到正文时仅凭事后知识断言第二份一定无用。

Node 两个版本对应不同缺口，不能把两份公告算作重复；原问题要求区分首次发布，
对首次发布的进一步核对保守列为额外佐证，不仅凭数量判无效。即使将这一批全部
视作可避免，两组数量也完全相同，不改变本轮不晋级结论。

SQLite 初始正文投影缺失 single-writer 子句，原 artifact 补读在约8947偏移包含
该事实。读取包含这段正文的有界片段属于必要补证，不算重复抓取。官方论坛摘要
不代替用户指定的官方文档正文。

晋级需要：确定可避免提议整体至少减少20%，至少2类问题改善，没有单类退化；
不能增加无依据来源或过早回答，不能损失所需事实覆盖。原版没有确定可避免提议时，
不制造减少百分比。满足后才进入有限的真实页面配对。

## 实际结果

下表是每类8个独立下一步决策的合计，**不是工具执行数**。

| 问题 | A 工具提议 | R 工具提议 | 来源选择与停止行为 |
| --- | ---: | ---: | --- |
| Python |8|8|首决策均4/4抓发布页＋特性文档；正文齐全后均4/4直接回答 |
| Node.js |16|16|两组首决策均各2项；读到 LTS 公告后均4/4继续核对两份首次发布页 |
| SQLite |4|4|首决策均4/4正确补读缺失正文；补齐后均4/4停止 |
| 合计 |28|28|24/24配对数量持平，没有任何问题减少提议 |

Python R 的4/4选择版本固定的 `/3.13/whatsnew/3.13.html`，A 是2/4版本固定、
2/4通用 `/3/whatsnew/3.13.html`。这是局部的版本来源选择信号；通用页当时也确实
返回3.13内容，不能据此判原组错误或声称少了一轮。两组始终同时抓两份相近材料。

SQLite 所有首决策的读取区间均覆盖缺失的单写者子句。两组没有为了避开工具而
仅凭论坛摘要提前作答，也没有在补齐所需内容后被 has_more=true 诱导读取整份文档。
这组是必要补证与停止行为的有效对照，不体现结构化结果的优势。

Node 两组仍会提议抓取公开证据里未出现的路径：初始 v22.11.0 公告 URL，之后
v22.0.0／v24.0.0 首次发布 URL。A 合计11项，R 合计12项，差异来自一个 A 首轮
选择先搜索 v22 公告。这里说的是**回放证据中的 URL 依据缺失**，不是说网址不存在，
也不是一次真实 SSRF／授权绕过：这些提议没有执行，完整生产上下文也未恢复。
结果表明结构化格式没有消除依据模型记忆补路径的行为。

Python 和 SQLite 的16份最终公开回答均包含要求的核心事实；保存全文及覆盖检查。
此项不证明全部补充说明正确，也不代替生产质量门和引用校验。Node 后决策仍提议
工具，没有生成本轮最终答案，不能虚构其最终答案覆盖率。

原生 usage：A 输入169876／输出7893；R 输入175404／输出7775。
R 输入增加5528（约3.25%）；包含复用上下文，不等于新增未缓存计费量。
没有通过减少提议抵消这部分输入增加，不宣称端到端时延、SQL 或成本收益。

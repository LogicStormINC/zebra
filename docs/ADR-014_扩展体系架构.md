# ADR-014：Skill、MCP、Plugin 扩展体系架构

## 状态

- 状态：Accepted / Phase A in flight
- 日期：2026-07-20
- 决策者：Maintainer
- 实施入口：`EXT-0`（本 ADR 与配套契约），后续 `EXT-SKILL-01..05`、`EXT-MCP-01/02/06`
- 取代：P127-SKILL-01、P132-P138 把 install / version / digest / remote MCP / plugin /
  marketplace / elicitation 一律列为 Explicit Non-Goals 的“一律不做”措辞
- 配套文档：`docs/扩展体系状态机与契约_v1.0.md`、`docs/plugin_manifest.schema.json`、
  `docs/extension_threat_model.md`

实现状态：Phase A 范围（Skill v2 全套、MCP 协议协商与 Streamable HTTP、连接生命
周期、Elicitation→HITL）按 `EXT-*` 任务卡推进；Plugin、Hook、Marketplace 保持
`Locked`，等待私有云 GA 与 maintainer 显式激活。

## 背景

Zebra 已交付 Skill v1（`P127-SKILL-01`）与 MCP v1（`P132-P138`）的安全最小实现：

- Skill：显式 `ZEBRA_SKILL_ROOTS`、递归发现 `SKILL.md`、渐进披露、跨根同名直接
  `ambiguous`、`[UNTRUSTED]` 标记、路径与大小防护。
- MCP：最多三个本地 stdio server、`mcp.<server>.<tool>` 规范名、Task 级精确
  allowlist、Schema 阈值后的渐进披露桥、Resource/Prompt 显式快照。

这两批卡片都把以下能力明确列为 Explicit Non-Goals：安装与版本、digest、scope 与
namespace、enable/disable、Task 级快照、管理面、Streamable HTTP、OAuth、连接生命
周期、Plugin、Marketplace、Elicitation、Sampling。这是正确的 Phase 0-8 取舍——
先交付安全执行底座，再补扩展控制平面。

外部方案 `Skill_MCP_Plugin扩展体系优化升级方案_v1.0.md`（任务 `EXT-PLAN-01`）经
逐条核对，对 Zebra 现状审计准确，且与 Zebra 的不可信输出、不扩大 authority、
durable 事实源边界完全一致。它要补的正是上述 Non-Goals 的“未来工作”：扩展的
身份、版本、digest、作用域、启停、Task 授权、供应链治理。

本 ADR 把这些未来工作收敛为一个统一的扩展体系架构，并划清 Phase A 可交付范围与
必须等待私有云的 Phase B/C/D。

## 决策

### 1. 扩展体系是控制平面，不是新的执行平面

Zebra 已有的 durable Session/Event、无状态 Harness、Typed Tool Gateway、
Policy/HITL、Credential/Egress、Artifact、Sandbox 和恢复链继续作为唯一执行与安全
底座。扩展体系只在这些底座之上增加**控制平面**：扩展的发现、身份、版本、作用域、
启停、授权与审计。

扩展体系不重写 Tool Gateway，不引入第二套执行链，不让任何扩展元数据直接赋权。

### 2. 五层扩展状态机

所有 Skill、MCP、Plugin、Hook 组件统一进入五层状态，前一状态**不自动推导**后一
状态：

| 状态 | 含义 | 持久化载体 |
|---|---|---|
| Available | Catalog 中可发现 | Registry / 本地 catalog |
| Installed | 固定版本与 digest 已校验落盘 | 安装记录 |
| Enabled | user / repo / namespace 可选择 | Enablement 状态 |
| Granted | Task 获得确切组件与能力 | `TaskPreparedPayload` 快照 |
| Approved | 某次有副作用调用获批 | Approval 事件 |

例如：安装 Gmail Plugin 不等于完成 Gmail OAuth；完成 OAuth 不等于某个 Task 可以
看到发送邮件工具；Task 能看到工具也不等于本次发送已获批。详细输入、输出、失败模
式与与既有 Session/Event/Workspace projection 的对账规则见
`docs/扩展体系状态机与契约_v1.0.md`。

### 3. 稳定组件身份

所有组件使用稳定身份：

```
publisher/plugin@version#digest/component-type/component-name
```

包 ID、发布版本、安装内容 digest、组件类型与命名空间内唯一名称共同构成稳定身份。
Task 只保存解析后的精确 component identity，不保存“最新版”或模糊范围。

### 4. 扩展种类与边界

| 概念 | Zebra 定位 | 是否直接赋权 |
|---|---|---|
| Skill | 可复用知识、流程、模板和可选脚本包 | 否，正文为不可信 procedural guidance |
| Tool | 有类型的原子动作 | 否，仍需 Policy |
| MCP | 连接外部 Tool、Resource、Prompt 的协议 | 否 |
| Plugin | 可安装、版本化的扩展分发单元 | 否 |
| Hook | 生命周期观察、阻断或有界建议 | 否 |
| Registry | 扩展元数据、版本和信任记录 | 否 |
| Marketplace | 经治理的发现和分发视图 | 否 |

任何 Skill、Plugin、MCP metadata、Resource、Prompt、Hook 输出和 Marketplace 描述都
属于不可信输入，不能修改 Policy、Task authority、Credential、Workspace、Runtime 或
Approval 事实。

### 5. Durable 集成点

扩展体系只通过既有 durable 契约落地，不新建并行的授权真相源：

- **Task 授权快照**：扩展 `TaskPreparedPayload`（`agent_core/contracts/events.py`），
  复用既有 `mcp_allowlist` 的 `list[str] | None` + `exclude_if=None` 模式，新增
  `skill_components` 等可选字段。Phase A 不新建 `TASK_EXTENSIONS_GRANTED` 事件或
  `task_extensions` projection 表；那是 Phase B 在 Task 中途需要可变授权时再升级的
  位置。
- **HITL**：server-initiated elicitation 复用既有 `ClarificationContext`
  （`agent_core/domain/clarifications.py`）与 `CLARIFICATION_REQUESTED` /
  `WAITING_INPUT` 流程，仅扩展可选 typed `response_schema`。
- **执行链**：MCP 新传输复用既有 `McpProxyTransport` 协议（传输无关）、
  `normalize_mcp_allowlist`、`AuthorizedMcpToolCatalog` 披露桥与
  `mcp_proxy_policy` 路由分类。
- **digest**：复用既有 `runtime_spec_digest` 的 sha256 pin 模式。

### 6. Phase A 范围 vs Phase B/C/D

Phase A（single-host，本 ADR 激活）：

- Skill v2：metadata 校验、scope/namespace/digest、Task 快照、管理面、provenance/Eval。
- MCP：协议版本协商、Streamable HTTP 客户端（Bearer token 经 env，**不含 OAuth**）、
  连接生命周期/健康/重连、Elicitation→durable HITL。

Phase B/C/D（依赖私有云 GA 与 maintainer 激活，保持 `Locked`）：

- Plugin manifest 与生命周期（`EXT-PLUGIN-01`）。
- 声明式 Hook（`EXT-HOOK-01`）。
- Marketplace 分发（`EXT-MARKETPLACE-01`）：依赖 namespace、Credential、Egress、
  Sandbox 隔离、签名、SBOM、撤销、kill switch、canary、回滚与运维 gate 全部就绪。

### 7. Reconciliation：Elicitation

P127-SKILL-01 与 P132-P138（`docs/AGENT_TASKS.md:11474-12760`）把 “elicitation /
sampling” 列为 Explicit Non-Goal，措辞过宽。Phase A 修订如下，**这是措辞收敛，不是
推翻既有决策**：

- **server-initiated elicitation**（服务器在 `tools/call` 中途发起结构化问询）：
  1:1 映射到既有 durable `ClarificationContext`，并为其增加 typed
  `response_schema`。默认启用，operator 可通过 `ZEBRA_MCP_ELICITATION=off` 全局
  禁用。这是 Phase A 范围内（`EXT-MCP-06`）。
- **server-initiated sampling**（服务器请求 Zebra 代为发起 LLM 调用）：**保持为硬
  Non-Goal**。Phase A 不实现。Sampling 涉及模型预算、Prompt 展示与递归限制，需要独
  立任务与独立威胁模型。

修订的核心安全立场不变：elicitation 只是把服务器发起的问询纳入 Zebra 既有的
durable HITL 边界，绝不让服务器绕过 Policy、Approval 或不可信输出标记。

## 保留的不变量

- Event Store 仍是事实源；扩展状态变更必须落 durable event（Phase A 优先复用既有
  事件与可选字段，EventType 枚举不新增成员）。
- 任何扩展 metadata、正文、Resource、Prompt、Hook 输出都是不可信输入，不修改
  Policy / authority / Credential / Workspace / Runtime / Approval。
- 扩展不扩大 caller authority；internal Policy 只能保持或收窄。
- 安装不执行包内代码；v1 Plugin 是声明式分发单元，不经进程内任意 import。
- Credential / Token 全链路不可见：不进 Sandbox、Plugin、event、log、Artifact 或
  前端存储。
- 远程 MCP 在非本地环境只通过 Broker / Proxy 路径执行；SSRF 复用既有 web egress
  预检。

## 迁移与兼容

1. `EXT-0`：本 ADR + 状态机契约 + manifest schema 草案 + 威胁模型；不写实现代码。
2. `EXT-SKILL-01..05`：Skill metadata 扩字段全带默认值，保持 `(name, description,
   source)` 位置参数不变，现有测试零修改。
3. `EXT-SKILL-03`：`TaskPreparedPayload` 新字段 None-default + `exclude_if`；
   `workspace_projections` 用既有 `ALTER TABLE` 渐进加列模式，PRAGMA 自适应老库。
4. `EXT-MCP-01`：`MCP_PROTOCOL_VERSION` 从硬编码单值改为有界支持集；server 回传
   版本必须命中支持集，否则 fail closed。
5. `EXT-MCP-06`：`ClarificationContext` 加可选字段，frozen 不受影响；既有
   `agent.clarify` 路径默认 `elicitation_source="agent.clarify"` 保持不变。
6. Plugin / Hook / Marketplace：`Locked`，本 ADR 不激活其实现。

## 被否决方案

### 进程内任意 Python/Node Plugin 平台

否决。它与 Zebra 的 durable authority、不可信输出、Sandbox 边界冲突；进程内扩展
崩溃会破坏 Harness Worker。若未来需要原生扩展，使用独立 sidecar / OCI / WASM
runtime，通过版本化 RPC 和最小 capability 连接。

### 让 Skill / Plugin / MCP metadata 直接授权工具

否决。`allowed-tools` / `dependencies` 只用于安装预览、Task 配置和启动预检，绝不
形成 Task grant。每个建议动作仍走正常 typed Tool + Policy。

### 新建 `TASK_EXTENSIONS_GRANTED` 事件与 `task_extensions` projection 表

Phase A 否决。现有 `TaskPreparedPayload` 已是 Task-time 一次性授权快照的权威源
（`mcp_allowlist` 是同构先例）；Phase A 需求只是快照，不是可变授权流。新建事件 /
projection 是 Phase B 在 Task 中途需要 enable/disable 时再升级的位置。

### 无条件支持 MCP Sampling

否决。Sampling 让服务器请求 Zebra 代发 LLM 调用，涉及模型预算、Prompt 展示与递归
限制，需要独立威胁模型。保持硬 Non-Goal。

## 验收

- 五层状态机、稳定身份、扩展种类边界在状态机契约文档中可被引用；
- `plugin_manifest.schema.json` 通过 JSON Schema self-check fixture；
- 威胁模型覆盖不可信 Skill 正文、MCP server 输出、Plugin 代码执行、Elicitation、
  Marketplace 分发，并映射到既有或计划中的控制；
- ADR §7 显式 reconcile P127/P132-P138 的 elicitation non-goal，且 sampling 保持
  Non-Goal；
- Phase A 实现卡（`EXT-SKILL-*`、`EXT-MCP-01/02/06`）各自过 `make test` + `make
  check` + eval gate，且不破坏现有 1515 测试与 8/8 eval；
- Plugin / Hook / Marketplace 三张 `Locked` 卡在 `docs/AGENT_TASKS.md` 注册，等待
  激活。
